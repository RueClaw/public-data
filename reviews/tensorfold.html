Key points

What changed since the September review, and what matters now.

1

A native rewrite, not a routine release

The v0.3 Python/MLX and PyTorch/Triton server became a 132K-line Zig runtime: checkpoint loading, tokenization, chat templates, kernels and HTTP APIs run in one native process. The license moved from MIT to Apache-2.0.

2

Evidence has first-class states

Cache measurements are cold, reused or unverified. Missing counts never become zero, absent token hashes never prove equality, and incomplete streams never enter throughput figures. This discipline is worth copying.

3

Living Weights is research, not memory infrastructure

Facts are trained into Nemotron's output projection and survive restart or a Metal↔CUDA move. But the documented five-fact test recalled only 5/11 questions, contaminated 1/16 neighbors, and offers no per-fact undo.

4

Security posture improved materially

API-key digests use timing-safe comparison. Reloadable key files use NOFOLLOW, strict permissions and fail-closed refresh. Auth remains optional, so a non-loopback listener still requires deliberate hardening and TLS termination.

  • Repository-pinned Zig 0.17.0 archive matched its documented SHA-256.
  • 17/17 Python 3.12 model-free benchmark-evidence tests passed.
  • zig build test reached Metal compilation but stopped because Xcode's optional Metal Toolchain is not installed on this host. The Zig suite is not claimed as passing.
  • No model checkpoint or vendor throughput result was independently tested.

Why the receipt format matters

Reports preserve server token counts, cache state, complete/incomplete state, token IDs when available and chunk-independent hashes for content plus reasoning. Unknown evidence remains unknown.

How Living Weights works

text → extract facts → create held-out questions
→ train output-projection delta → recall/regression checks
→ commit whole lesson or roll it all back → write safetensors

The checkpoint directory is mutated and accepted facts cannot be individually removed. The server rejects linked/shared files to reduce the risk of modifying a Hugging Face cache, but operators still need a disposable copy and immutable original.

  • SHA-256 key digests and timing-safe equality.
  • Bearer or x-api-key; CLI, environment or reloadable file sources.
  • NOFOLLOW, regular-file and mode checks, 1 MiB cap.
  • Unsafe reload closes authenticated routes instead of retaining questionable state.
  • Authentication is optional; use explicit keys, network policy and TLS off loopback.

TensorFold's advantage is specialized kernels plus unusually auditable exactness and cache claims. Its cost is a narrow matrix and a young, large low-level codebase.

Verdict

The deployment call.

⚠️ Interesting

Pilot it on a qualified machine and harvest its benchmark-receipt, qualification-matrix and fail-closed secret-loading patterns. Do not make it a general fleet standard yet: the native line is days old, hardware support is narrow, and Living Weights is too weak and irreversible for production facts.

Key points

What matters most, in order.

1

Authority vs. task data, kept straight

Model output, OpenAPI descriptions, and user briefs are task data; the compiler's control requirements (scope, approvals, budgets, evidence) are authority and can't be drafted away. "Do not claim a model can remove those through a draft field." Most skill generators get this wrong.

2

Secrets sealed by construction

API keys live in a keystore outside the app and never inside a skill — so a generated package is safe to commit, diff, and share. The studio authors skills and explicitly never executes the business tasks inside them.

3

Honest offline mode

Without a model, deterministic template mode works fully offline — and later chat messages are appended as explicit constraints "rather than pretending a model rewrote the procedure." The loopback server binds exact 127.0.0.1 with a literal host check.

4

Verified, and one day old

Local run: 120/120 tests pass; the CLI preview/create pipeline works as documented. But the repo was created 2026-10-06, has 2 stars and one author — and the README itself admits the real safety of a skill depends on the host harness enforcing scope, approvals, and budgets.

OpenAPI → skill

Import an OpenAPI 3.0/3.1 spec, select operation IDs explicitly (none selected by default), and the compiler produces the API contract alongside SKILL.md. Descriptions and schemas are treated as untrusted task data.

Revision-bound export

Export reviews the exact revision, verifies the ZIP round trip before reporting success, and never overwrites existing output folders. Success is scoped honestly: the artifact is valid — not proof any business API ran.

CLI surface

python scripts/bsc.py import-api spec.json
python scripts/bsc.py preview --plan plan.json
python scripts/bsc.py create --plan plan.json --out <parent>        --openapi spec.json --operations listInventory
python scripts/bsc.py validate <exported-folder>

bsc/ splits cleanly: core.py (compiler), openapi.py (spec import), keystore.py (sealed secrets), security.py, server.py (loopback studio), cli.py/harness.py/control.py (agent surfaces), providers.py (model endpoints), workspace.py (drafts), web/ (studio assets).

Both interfaces funnel into the same compile function — no browser-only export format or agent-only fork. Writes happen only through explicit create with an approved parent directory.

Clone, run install.sh / install.ps1 (drops a desktop icon) or python3 -m bsc serve. Studio opens at http://127.0.0.1:8717 — use the literal address; the host check is exact.

Single-user local release: do not expose the loopback server through a public tunnel.

What matters most, in order.

Small, integrated Linux workflow

Font browsing, link previews, comparison, and editable outlines share one local app. Python uses standard-library networking while Chromium and Fontconfig do substantial work.

2

Local does not mean authenticated or risk-free

Loopback, Host/Origin checks, font allowlists, and archive limits are real safeguards. Local callers need no token; URL validation does not pin DNS results, and aggregate job quotas are missing.

Deep dive

Into the repo itself.

Typecase targets Omarchy and other Linux desktop users who want to browse installed fonts, compare two to four families, acquire fonts from public links, and compose a simple page without switching tools. Fontconfig supplies installed family/style metadata. The UI exposes favorites, filters, glyph details, variable axes, and supported OpenType features.

The canvas supports text, path, and path-group layers; transforms, direct point editing, and outlines derived from HarfBuzz shaping. It is a small desktop workflow, not a multiuser font service, cloud design suite, or full font editor. The README's screenshots and feature descriptions are supported by implementation paths, but visual fidelity was not independently exercised.

Preview before installation

GitHub repository/folder/file links, Google Fonts family names/links, and direct TTF/OTF/TTC/ZIP links become temporary staging collections. Files must pass a font magic check and fc-query before preview; family-name collisions are surfaced. Selected files are copied into a new user-font collection. Duplicate detection is by family name, not content hash or license equivalence. Google Fonts requests resolve through the public google/fonts GitHub repository, not an authenticated Google integration. Backend evidence

Typography plus editable outlines

The frontend probes font features and axes, supports shared comparison text, and maintains up to 200 in-memory canvas snapshots. Outlining uses local HarfBuzz WASM, browser line measurements, and a custom direction-run heuristic. This is a useful bridge from text composition to editable glyph paths, but not evidence of complete Unicode bidirectional-layout equivalence across every script. Canvas, outlines

Portable exports have different tradeoffs

JSON saves the document model, not a bundled font package; reopening on another machine can substitute an available family. PNG is rasterized at 2× artboard dimensions. SVG embeds complete used font/face bytes as base64 rather than subsetting or checking embedding restrictions. This improves portability but can disclose or redistribute commercially licensed font programs. Outlining removes the live-text font dependency but is not a blanket exemption from the font license. Exported artwork and JSON contain the user's text. Export implementation

Architecture

The launcher selects a local port, starts the Python process, opens Chromium in app mode with a dedicated profile, and attempts to stop its child when the window/browser exits. Python serves the static frontend, allowlisted font bytes, and JSON APIs. Fetch jobs run on daemon threads; jobs and previews live in process-global dictionaries. State updates use a lock and temporary-file replacement. No database, account backend, API key, AI service, telemetry client, or arbitrary shell-command API was found in the reviewed application paths.

External processes are invoked with argument lists rather than interpolated shell commands in the Python backend. The small codebase is easy to trace, though the frontend shares global state and packs substantial parsing, geometry, persistence, and UI logic into two large files. Launcher, backend

Security and boundaries

  • Local, not authenticated: The server binds 127.0.0.1, checks Host, checks Origin and Sec-Fetch-Site on API/font routes, requires JSON POSTs, and caps request bodies at 10 MiB. These are meaningful browser cross-site defenses. Requests without Origin/Fetch metadata are accepted; there is no token or OS-user authentication. Other local processes able to reach the port can read state and invoke operations. Do not expose it through a proxy or broaden its bind address. HTTP boundary
  • Restricted file access: Font endpoints require exact normalized allowlisted paths discovered through Fontconfig/staging. Uninstall resolves the collection directory, verifies files remain within it, refuses symlink files, and removes recorded files rather than indiscriminately deleting a collection. Useful protections, not a sandbox for the whole app. Allowlist, uninstall
  • Outbound downloads are explicit: Public-IP DNS validation applies before downloads and redirects, with a 400 MiB download ceiling and ZIP limits of 60 MiB/file and 500 MiB unpacked. However validation and urllib connection perform separate resolution; addresses are not pinned, leaving a DNS-rebinding/TOCTOU gap in the intended public-only boundary. HTTP is permitted, and no artifact signature or checksum verification is performed. This is static analysis, not a demonstrated live exploit. Download checks, ZIP handling
  • Preview already parses untrusted fonts: fc-query handles downloaded bytes before the final install click, followed by browser and WASM font parsing. Magic checks are not malware validation. Keep Chromium and Fontconfig current; use trusted font sources.
  • Resource limits are incomplete: Each fetch creates a thread/job without a global concurrency, job-retention, or cumulative-stage quota. Direct-file downloads use the 400 MiB ceiling, not the ZIP per-file limit. Multiple requests can exhaust memory/disk despite individual caps. Imported JSON is parsed before sanitization; large artboards and many layers can be expensive.
  • Credentials/privacy: No accounts or credential store are required. Source URLs are retained verbatim in installation records; avoid token-bearing URLs. Download servers see the request/IP and Typecase user agent. The README's “nothing is loaded from the internet at run time” accurately describes bundled UI/shaping assets, not the font-download workflow. It is not a network-free application in installer use.

Data and recovery

State and installation records default to the user's local Typecase data directory; fonts live in the user's Typecase font collection directory; staged downloads default to the source checkout's .cache/staging. Chromium maintains a separate persistent profile. Files are ordinary local data, with permissions inherited from the user's environment rather than application encryption or a documented retention policy.

Successful installs and explicit cancels remove staged directories; startup clears the staging root. Failed/abandoned fetches can leave files until a later startup. Completed jobs remain in memory until exit. Install records retain source URLs, dates, families, and absolute font paths. Corrupt JSON is renamed with a .bad timestamp, preserving a recovery copy; writes use os.replace but no fsync or versioned backup. These damaged copies have no automatic retention limit. State, staging lifecycle, startup

Installation copies fonts and runs fc-cache before recording ownership. A copy/cache exception or crash can leave partially installed fonts without an install record; there is no rollback transaction. Uninstall removes files before persisting the revised ledger. Back up both data JSON files and font collections, not just the canvas. Autosave is debounced and ignores request failures, so manual JSON exports remain advisable; browser closure is not proof that the last save persisted. In-memory undo is not crash recovery. Install ordering, autosave

Font acquisition also drops non-font archive files, including license/readme notices; the Google Fonts fetcher selects only font files. Preserve source licensing material separately before distributing fonts or font-bearing SVGs.

Adoption gate

Before relying on it: obtain a clear application license; test fonts/export fidelity on the intended platform; preserve font license notices; harden install rollback and autosave error reporting; pin validated download addresses and add global resource limits; and establish repeatable CI/release provenance. For now, study or evaluate with disposable documents and trusted, appropriately licensed fonts—not irreplaceable production work.

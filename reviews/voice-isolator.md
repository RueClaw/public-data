## Verdict

⚠️ **Interesting — credible implementation, not independently established best-in-class quality or live-call readiness.** The checkpoint integrity checks, explicit stream state, careful overlap handling and candid evaluation disclosures are stronger than a typical model demo. Pilot it for recording cleanup or a measured streaming pipeline; do not treat the private VIBE leaderboard or “20 ms look-ahead” as proof of quality, consumer-device speed or end-to-end latency.

## What It Is

This is neither transcription nor text-to-speech, and it is not an identity-conditioned speaker selector. The release aims to retain the foreground voice, its timbre, level and nonverbal sounds while removing noise, music and competing talkers. The model card says similar-level speakers are usually both retained and a quieter competing speaker can disappear. That is an important risk for meetings, dialogue and accessibility applications, not a universally desirable enhancement policy.

Version 1 is explicitly denoising, not restoration of missing bandwidth. Natural-language prompting, broader on-device support and restoration are roadmap items. Subtracting the voice from the aligned mono input gives a mathematical residual, not a guaranteed clean instrumental stem: leaked speech can remain. These behavioral descriptions are vendor claims, not listening results from this review. [README](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/README.md), [model card](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/MODEL_CARD.md).

## Stack and architecture

| Layer | Implementation |
|---|---|
| Public API | VoiceIsolator, isolate/isolate_many, stateful stream sessions |
| Signal processing | STFT/iSTFT, 48 kHz, 2048-point FFT, 480-sample / 10 ms hop |
| Network | Band-split dual-path attention and Mamba; complex mask plus bounded residual |
| Storage and delivery | Revision-pinned Hub safetensors; local audio files; no required hosted inference |
| UI / evaluation | Optional Gradio browser demo; independent benchmark wrappers and scoring scripts |

The model card describes 46 frequency bands, width 512 and seven alternating blocks: four time/band attention blocks and three time/band Mamba blocks (state size 16). It reports 64.0M offline and 58.2M realtime parameters. The implementation contains these network building blocks, rotary attention, bounded corrections and a plain-PyTorch selective-scan fallback; actual architecture is loaded from checkpoint metadata, not assumed from constructor defaults. No checkpoint was acquired, so parameter totals and released embedded configuration were not independently counted. In particular, the generic config's 12-second chunk default is not proof against the released model's documented 8-second setting. [model.py](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/src/inworld/voice_isolation/model.py), [scan.py](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/src/inworld/voice_isolation/scan.py), [isolator.py](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/src/inworld/voice_isolation/isolator.py).

### Audio contract and offline processing

- File decoding uses SoundFile/libsndfile-supported formats; this is not a promise to decode arbitrary video or every codec. Files are averaged to mono. Array input accepts mono or small channel/time matrices, scales integer PCM and rejects ambiguous shapes/int64; ordinary isolate rejects empty and nonfinite input.
- The pipeline resamples to the model rate using torchaudio's high-quality Kaiser sinc settings. Python isolate returns the input sample rate unless overridden; the CLI defaults to 48 kHz. Resampling to 48 kHz does not reconstruct missing frequency content or preserve a stereo image.
- The documented released offline model processes 8-second windows with 2-second overlap. The code linearly crossfades and shifts the final full window back to the clip end rather than rendering a poorly contextualized tiny tail. Whole input/output arrays still reside in memory: chunked network computation is not bounded-memory file decoding.
- CLI offline voice/background outputs are FLOAT WAVs, preserving levels for reconstruction. The general save_audio helper defaults to PCM_16 and scales an over-full-scale waveform down before integer encoding; that can change gain, so do not assume the Python default preserves levels identically. Outputs use a same-directory staging file then rename. Permissions are 0666 filtered by umask, not forced private 0600. Keep originals and choose private output directories.

Sources: [audio.py](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/src/inworld/voice_isolation/audio.py), [CLI](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/src/inworld/voice_isolation/cli.py), [enhance](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/src/inworld/voice_isolation/model.py#L748).

### Streaming: real state, qualified latency

The public stream API accepts arbitrary-size mono floating-point pieces at the model rate; it does not resample or normalize integer PCM for the caller. push emits finalized CPU samples, and flush drains the tail and closes the session. Attention caches, Mamba recurrent/convolution states, STFT buffers and overlap-add state persist between pushes. The high-level API defaults to 600-frame (6-second) attention windows and 200-frame (2-second) crossfades. A second lane starts with cloned Mamba state and empty attention, blending raw decoder outputs before bounded spectral correction; this is not simply restarting the entire model every six seconds. Plain streams or undersized caches can make output depend slightly on push partitioning after cache trimming, explicitly documented in the source.

The advertised 20 ms is **look-ahead**, not total delay. The code defines algorithmic delay as n_fft + hop × lookahead: at 48 kHz and two frames, 3008 samples = **62.67 ms**; zero and four frames imply 42.67 and 82.67 ms. Constructor look-ahead defaults to zero; examples explicitly request two. Device computation, capture/playback blocks, resampling, transfers, queueing and network delay are additional. block_frames is a throughput cap: partial available blocks execute without waiting to fill it. The file-streaming CLI nevertheless writes only after processing the file; it is not a live sound-device utility.

Unlike ordinary isolate, Stream._accept validates shape/dtype but has no finite-sample check. A caller should reject NaN/Inf before feeding a long-lived session and bound push sizes/backpressure. Streaming state should be separately owned per audio session. [streaming.py](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/src/inworld/voice_isolation/streaming.py#L398), [latency/API](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/src/inworld/voice_isolation/isolator.py).

## Quality evidence and benchmark reproducibility

VIBE is unusually explicit about its limitations. Inworld owns both the benchmark and a competing model, selected its checkpoints with these scores in view, and did not tune other upstream releases the same way. **Neither the evaluation audio nor score files are distributed**, so publishing scorers and charts does not make the rankings independently recomputable. The claimed set has 5,502 items / 77 conditions: 4,898 paired items in 13 languages, 96 noise-only beds and 508 real recordings in 128 languages. Recording-level training screening is stated, but 36 items have speakers with known or possible training overlap. Training itself is reported as approximately 10,000 hours, with no complete public training corpus or reproduction recipe. [benchmark README](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/bench/README.md), [model card](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/MODEL_CARD.md).

**What is strong:** fixed anchors rather than competitor-relative normalization; explicit keep/remove/restore task contracts; build IDs; complete-cohort requirements; pinned external wrapper revisions and environment receipts; audio/scorer/protocol digests; separate raw diagnostics, multilingual core, downstream recognition and long-stream probes. These are inspectable methodology mechanisms, not proof the undistributed inputs or reported scores are correct. The registry explicitly binds historical v0 benchmark names to the same file hashes currently shipped as v1, rather than silently aliasing future v1 updates. [protocol](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/bench/PROTOCOL.md), [wrapper contract](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/bench/WRAPPER_CONTRACT.md), [registry](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/src/inworld/voice_isolation/registry.py).

**What limits interpretation:** the denoising composite averages remove/keep/sound parts, while restoration is a separate room axis. A policy threshold of more than 10 dB added out-of-band energy decides which board ranks a system; added energy does not prove restored speech. Fixed normalization constants express scoring policy, not audibility thresholds. Composite gaps below 0.03 and timbre gaps below 0.05 are reporting ties, not confidence intervals. NISQA predicts perceived quality; it is not a blinded human listening panel. Waveform-coherence metrics can penalize natural-sounding resynthesis. Speech suppression is not automatically improved word intelligibility.

The docs describe 2,000 seeded anchor-policy draws and axis-weight sensitivity analyses, but their output cannot be independently inspected/recomputed without score files. ASR checks use Whisper large-v3/small and optional hosted Inworld STT; transcripts include corpus/Gemini/recognizer agreement and human-checked tiers, with some reference-transcription fallbacks. Those provenance distinctions matter: not every target is an independently human-transcribed gold label. The streaming badge checks future dependence and long-input drift (≤100 ms look-ahead, specified drift/no-drop criteria), not live throughput or playback delivery. [metrics and diagnostics](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/bench/METRICS.md).

### Hardware and performance

README lists tested A100, H100, B200, B300 and CPU, and explicitly says smaller GPUs are not yet tested. Runtime chooses CUDA, then qualified MPS on PyTorch ≥2.6 with an FFT round-trip check, then CPU. Default CUDA network arithmetic is bf16 autocast; elsewhere fp32, with STFT/iSTFT/scan remaining fp32. A CPU fallback is availability, not a real-time guarantee; MPS selection is not a measured Mac latency result.

speedtest.py has useful cold-first-call versus warm p50/p95/max, repeated clips, finite/length failures, CUDA synchronization and peak-allocation reporting. But “cold” begins **after loading**, not download/process startup; clips are loaded/resampled before timing; its realtime_p50 is audio-seconds / elapsed-seconds (speed multiple, inverse of the common elapsed/audio RTF). It measures whole processing calls, not streaming inter-chunk deadlines. Memory is CUDA allocated peak, not total system/VRAM residency, and non-CUDA reporting is CPU-oriented. The inspected public text does not supply a reproducible cross-hardware timing report or minimum consumer VRAM requirement. No speed or memory result was measured here. [speedtest.py](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/bench/scripts/speedtest.py).

## Trust, privacy and operating boundaries

**Checkpoint supply chain:** named releases pin Hub revision 9b0285b3fe8403aa8e2f1dbb2165a80a4294c970 and verify SHA-256 before use. The default format is safetensors. Legacy .pt loading explicitly uses torch.load(weights_only=True) without unsafe fallback; missing or unexpected learned parameters are rejected. These are meaningful defenses, not a complete security guarantee for arbitrary architecture metadata or old framework versions. Arbitrary hf:// locations have no registry checksum, revision is optional, and local files bypass registry integrity checks. Pin trusted files and current patched dependencies; do not accept user-supplied model paths in a public service. [loader](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/src/inworld/voice_isolation/isolator.py), [registry](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/src/inworld/voice_isolation/registry.py).

**Core privacy:** inspected inference code does not upload audio to Inworld or require an API key. Hub download/cache traffic and package installation are network activity, separate from local inference. No core audio telemetry was found; this is a static finding, not packet-capture certification. CLI reads inputs and persists voice/background files until the operator removes them; model caches also persist. A residual can contain private words, so treat it as sensitive audio too.

**Demo changes the boundary:** browser uploads and microphone chunks go to the Gradio server; only a server on the same machine is local to that user. Default bind is 127.0.0.1, analytics_enabled=False, and share is opt-in. Authentication is optional and not forced when choosing a public bind/share. The demo has 300 MB uploads, 10-minute offline and 60-second live limits, a two-minute live-state TTL and cache sweeps every 600 seconds for entries older than 3600 seconds. That is retention cleanup, not secure erasure or a guarantee after crashes/backups; examples are deliberately retained. Protect remote use with authentication/TLS, isolation and explicit retention controls. Microphone capture needs browser permission; it is unnecessary for file/API use. [demo app](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/demo/app.py), [live state](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/demo/live.py), [browser transport](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/demo/assets/online.js).

**Optional evaluation egress/cost:** selecting Inworld STT sends base64 audio to https://api.inworld.ai/stt/v1/transcribe using INWORLD_API_KEY. That path may incur provider charges and provider retention terms; neither is a core-inference requirement. Other evaluator models/dependencies require their own downloads. Do not casually run the entire benchmark on sensitive audio or assume its optional hosted path is free. Local GPU/CPU time, memory and power remain real costs. [scoreasr.py](https://github.com/inworld-ai/voice-isolator/blob/c73b3fab81a870410cbac50d2f05f25edc4d10aa/bench/scripts/scoreasr.py).

## Comparison and practical fit

| Option | Better reason to evaluate it | Main distinction |
|---|---|---|
| Voice Isolator | Local full-band foreground cleanup, explicit stateful API | New release; private vendor comparison; speaker-removal policy |
| [DeepFilterNet](https://github.com/Rikorose/DeepFilterNet) | Real-time full-band noise suppression / deployment-focused baseline | Different model and speech-preservation policy; compare on target hardware |
| [RNNoise](https://github.com/xiph/rnnoise) | Lightweight established real-time noise suppression | Much smaller integration footprint; not the same quality/foreground-isolation target |
| [Demucs](https://github.com/facebookresearch/demucs) | Music source/stem separation | Different task; VIBE appropriately treats vocals as a reference, not an equivalent ranked denoiser |

These are task-fit alternatives, not an independently measured ranking. Start with the least complex baseline that meets the actual requirement. For a later authorized pilot, use consented representative recordings with unprocessed controls, quiet/overlapping speakers, laughter, music and long sessions; assess intelligibility and voice loss blind, alongside downstream WER and speech-preservation measures. Measure startup, p95 per-push time, memory and total capture-to-playback delay on the intended hardware. Keep originals, pin code/checkpoints/dependencies, and validate privacy separately for local CLI versus hosted demo.

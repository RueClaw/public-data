Key points

What matters most, in order.

1

One engine, real editable output

The desktop, CLI and headless MCP backend share document commands. Layout, components, variables and prototypes are substantive modules, not just an AI image-generation wrapper.

2

Conversion is not preservation

Actual .fig import and experimental export coexist with offline Penpot 2.x conversion and Sketch import. Warnings, missing fonts and dropped semantics matter; internal round trips do not prove external compatibility.

3

Local-first is not network-free

Desktop startup update checks contradict the absolute no-contact-until-sharing claim. Online sharing is not end-to-end encrypted; bearer links and locally stored owner tokens carry authority.

Deep dive

Into the repo itself.

Extensions / networkMetered wasmi; WebSocket collaboration server

Design with frames, auto layout, reusable components, variable modes and prototype interactions. Generate handoff code and export assets; generated code was not validated as a production application.

Penpot conversion retains bounded source metadata and fingerprints for unchanged properties, but not embedded font binaries. .fig export omits or approximates comments, history and selected prototype/text features. Preserve originals and inspect warnings.

Persistent scene graphs and snapshots underpin shared engine commands. Plugins have no WASI, explicit fuel/memory caps and a restricted host-command policy. The opt-in loopback control interface has no inspected token authentication; automation roots constrain relevant engine file/network access, not the whole process.

Atomic saves and external-change checks improve preservation, but explicit-path writes differ and size/mtime checks are not a transaction. WASM panic aborts remain possible despite the README’s “Never crashes” headline.

Static review only; no source execution or interoperability tests. Reviewed SHA: bd920fc7dec63ee8d433884a175f2f581cc9eb87. Upstream CI reported success, SonarCloud failure and FreeBSD in progress. The core CI workflow follows a mutable shared main branch.

Full evidence, pinned source links and limitations

PenpotBrowser-first collaboration versus FigCraft’s native local-file emphasis
FigmaEstablished native ecosystem versus experimental .fig compatibility
InkscapeMature SVG authoring versus interface-specific layout/prototype workflows

Local design needs no server or model provider. Collaboration defaults to a loopback, closed-publishing server; use TLS, restricted reachability, quotas and tested backups. Online operators can read stored designs; stopping access does not itself delete the stored file.

Owner tokens live in local preferences. Native desktop/browser platform behavior, external dependency security, font fidelity and recovery were not dynamically tested. Code is dual-licensed; distributed modified forks must remove restricted ArtCraft marks and retain applicable notices.

Verdict

The call, and why.

⚠️ Interesting

Pilot on disposable designs, not a production Figma replacement. Substantial editable-document and automation implementation, but experimental interchange and alpha collaboration require independent backups and workflow-specific qualification.

Key points

What matters most, in order.

1

Actual Linux GPU backend

Pinned MLX plus real Vulkan kernels, allocator and stream machinery—not a remote macOS proxy. Omarchy integration includes launchers, theme adaptation and a login service; kernel and driver prerequisites remain separate.

2

Evidence is specific, not universal

M1, M1 Max and M2 Max have reported measurements. M4 is experimental with 34 of 800 battery cases failing. Numerical gates, token divergence, ANE contention and a released batch-2 slowdown qualify speed claims.

3

Separate the security and release boundaries

Chat has loopback, session, Host/Origin and CSRF defenses. The underlying serving API can bind remotely without authentication. The maintainer confirms v0.7.35 ANE install assets remain broken despite a source fix.

Local inference with concrete admission controls

The planner budgets full weights, KV context and workspace with locked reservations. The mlx-lm shim caps tokenized prompt plus output. Catalog revisions and approve-first downloads improve provenance; these estimates are not an OS memory sandbox.

Hardware and speed claims

The author reports M1 Max Qwen3.5-9B at 37.1 versus 59.4 macOS decode tokens/s and 299.4 versus 339.0 prefill tokens/s. Driver provenance, differing repeat counts, changed outputs and older tables limit comparisons. None was reproduced here.

ANE is separately qualified

Supported Parakeet paths verify and seal assets; the low-level worker also has unpinned branches. Encoder fixture parity does not prove arbitrary Core ML support, full speech accuracy or a production soak test. GPU qualification is not ANE qualification.

Pinned upstream archive → additive overlay and patches → MLX graph → Vulkan backend → Honeykrisp GPU. Chat and serving stay local; external acquisition uses GitHub, package repositories and Hugging Face.

Security and privacy

The browser assistant forces loopback and checks Host, Origin, session and CSRF. The inference API only warns on unauthenticated non-loopback binding. Opt-in history is local JSON and normally survives uninstall. Diagnostic submission is explicit; derived host aliases also travel in a request header, even when omitted from public records.

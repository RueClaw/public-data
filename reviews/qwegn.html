Native execution with explicit state ownership

The package separates Foundation, Operators, Subsystems, Runtime and Apps. QWEngineDriver holds the HAL, arena, weights, attention/GDN operators and pipeline states. QWEngineSession owns position, token history, KV handles, recurrent/ring state and speculation, with snapshot/rollback and an idempotent-finish witness. This is meaningful structure. Numerous unchecked Sendable classes and manual synchronization mean compiler concurrency checks alone cannot prove correctness. Driver, session.

Repository memory is cached computation plus retrieval

Indexing discovers bounded UTF-8 files, orders them by structural depth and temporal stability, prefills a resident envelope and writes a .qwcache plus manifest. Default Cortex budget: 32,768 tokens. Default additional Vault recall budget: 8,192 tokens per turn. Recall and live deltas still depend on source files. This is not weight training or portable learned memory independent of model and repository.

The “semantic” index is narrower than the name suggests: 128-dimensional signed FNV-hashed term projections, splitting/stemming, hand-authored concept expansions, weighting and clustered retrieval—not an embedding-provider call. Git and .qwgignore rules, regular-file checks, binary checks and a 256 KiB per-file cap reduce unwanted ingestion, but are not secret detection. Tests are excluded by default. “Whole-codebase visibility” does not mean every byte is resident or every relevant file recalled. Builder, Vault, index, ignore matcher.

One control plane is not tenant isolation

Inference, model loading, settings, logs, telemetry and memory inspection/indexing/mounting share one service. Structured tool output is a protocol capability; callers still own execution policy, approvals and sandboxing. A coding agent does not become safe merely because inference is local.

The README advertises large MoE packs on a 128 GB M5 Max, million-token contexts, zero steady-state heap/Metal-buffer allocations and major cache TTFT gains. Relevant code and harnesses exist, but none of those measurements was reproduced here.

Useful defaults: loopback binding; refusal of unauthenticated non-loopback binding unless explicitly overridden; bearer/x-api-key authentication with constant-time-style byte comparison; bounded HTTP framing and malformed-request rejection. Server images default to bounded data URLs, with local paths and remote URLs disabled. Optional remote fetching blocks private address classes, redirects and excess source bytes. Server, helpers, parser, image policy.

Limits: loopback may be keyless and is not user authentication. CORS controls emitted response headers; inspected dispatch does not reject all unapproved Origins as an authorization gate. The listener uses plain TCP, not built-in TLS. One key grants broad authority rather than separate inference/admin/workspace roles. Use authenticated encrypted transport and route restrictions beyond one trusted local client; avoid the unsafe public-bind override.

Memory APIs accept filesystem paths. Root resolution normalizes a path and checks directory existence, but does not enforce an authorized-repository allowlist. Indexing writes within that repository and updates Git exclude state. Workspace metadata, a model-name @repo suffix or system/developer-message paths can trigger auto-mounting. If no new root is found, an existing active pack can remain available. This is daemon-wide state, not per-user isolation. Use separate processes/accounts for separate trust domains. These are static authority findings, not demonstrated exploits. Index/root resolution, mounting.

The optional image policy checks DNS before URLSession connects; address pinning was not established. DNS-rebinding resistance is unproven, not a confirmed exploit. Keeping remote images disabled avoids this extra egress surface.

Settings use private directories and 0600 files, but serialize the configured API key in JSON rather than a dedicated credential vault; settings responses mask it. Hugging Face uses HF_TOKEN, and HF_ENDPOINT changes its destination. Only configure trusted endpoints. No paid model API is necessary for native inference, but model acquisition, package setup and optional images still use the network. Local inference is not a zero-network guarantee. Settings, pull/bootstrap.

Repository text becomes model context, including memory envelopes rendered as system content. Filtering and delimiters are not a prompt-injection boundary. Review sensitive inclusion and enforce effect policy in the consuming agent. Optional fan-control UI documents root or an SMC helper socket for direct writes—a separate privilege boundary unnecessary for basic inference. Envelope, fan settings.

  • Settings/profiles: local JSON with atomic settings writes and restrictive permissions. One atomic file is not a transaction across application state.
  • Prefix caches: default 4 GiB warm RAM, 10 GiB SSD, 32 entries and eight session slots. Stored token IDs and model state/logits are sensitive recoverable context, not anonymous telemetry. LRU and startup stale-cache cleanup are not secure erasure or a complete retention policy. The inspected store writes through direct I/O to its destination, not a universal atomic multi-file transaction. Config, store.
  • Repository packs: manifests record source digests and model/cache identities and save atomically. Cache and manifest are separate writes. Unmounting is not deletion. Preserve source and matching model/config assets; rebuild derived caches after incompatible or interrupted writes. Manifest.
  • Browser chats: conversations, presets and UI state use localStorage. JSON/Markdown export, turn/session deletion and double-action Clear All exist. Browser deletion does not purge caches, packs, exports or backups. Chat.
  • Logs/uninstall: disk logs can append persistently; the memory ring holds 2,000 lines. Uninstall deliberately preserves models/settings/profiles/caches. No end-to-end encrypted backup/restore or verified total-erasure workflow was established. Plan retention and restore testing yourself. Logger, uninstaller.

Documented platform: macOS 26+, Apple Silicon, Xcode 26+, Swift 6.2/Metal; M5 recommended for cooperative tensors. This is not a Linux/Windows runtime, and M5 Max results should not be generalized to every M-series Mac.

SwiftPM commits exact resolutions for ArgumentParser, swift-jinja and swift-collections, while manifest ranges permit updates. Python direct versions are pinned, not a hash-locked full graph. Lazy bootstrap upgrades pip and falls back to unpinned numpy/safetensors/torch if requirements installation fails, then stamps success. Initialization success is not proof of a reproduced environment. Resolution, requirements, bootstrap.

The downloader uses mutable Hugging Face main, skips existing files by size and does not establish revision-consistent content addressing in the inspected flow. Ranged downloads accept any 2xx response and validate lengths rather than an explicit 206/Content-Range contract. Downloadable hash sidecars are not enforcement. Independently pin and verify artifacts; resumed acquisition should not mix revisions. These are static provenance/correctness concerns, not tested corruption incidents. Downloader.

The installer places CLI/app/support files in system locations and can terminate an existing menu app. Packaging supports Developer ID/notarization but defaults to ad-hoc app signing and permits unsigned installers without identities. Release metadata lists package/archive/checksum assets; their contents/signatures were not downloaded or verified. Preserve a known-good version/config; no transactional app rollback was demonstrated. Packaging.

Root Apache-2.0 permits modification/commercial redistribution subject to conditions, notices and patent terms. It does not grant rights to third-party models, evaluation data or brands. No code or visual assets were extracted. Retain component/model notices when redistributing packs. License.

Public metadata checked November 17 reports creation November 9, last push November 16, one star, zero forks and zero open issues. Latest listed release: v0.23.0, November 16. These are activity signals, not quality scores. Public CI at the exact reviewed SHA reported success.

The macOS workflow builds and runs host/CLI/server/quant/token/UI suites. GitHub Actions deliberately skips bare-metal GPU/golden suites, paired-performance tests and kernel-benchmark execution. Tests cover framing, auth/CORS, settings permissions, cancellation and memory mounting/indexing. GPU parity suites and golden generators exist, but existence is not a local pass result. Checkout uses a version tag rather than a full action SHA. Workflow, CI script, tests, security policy.

Limits: selective static review, not a complete audit or numerical-correctness proof. No tests were run; model catalogs/weights, pack recovery, installer signatures, isolation and throughput were not experimentally verified. Only public sources/metadata were used. Review-page markup validation is separate from executing Qwegn or visually testing its UI.

Start pinned, local-only and single-owner on supported hardware with non-sensitive source. Select workspaces explicitly; disable automatic memory use where inappropriate. Authenticate even loopback if local clients are not trusted. Do not share a daemon across mutually untrusted users or run it as root merely for fan control.

Budget for unified memory, model storage, conversion/indexing, SSD traffic, electricity and maintenance, not cloud per-token fees. Repeated stable repositories best amortize prefill. Prefer an existing engine for portability or ordinary small-context chat.

Adoption gate: verify hashes/install signatures; reproduce exact and relaxed quality/performance separately; test stale-file recall, workspace switching, API compatibility, interrupted indexing, disk-full recovery and complete deletion. Until then: interesting single-owner pilot, not a production multi-tenant service.

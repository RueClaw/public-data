Key points

What matters most, in order.

1

Windows on Linux — not Microsoft WSL

A real Windows guest provides OS compatibility. remotewin presents separate application windows; accel-virt forwards graphics commands to Linux host drivers without whole-GPU passthrough.

2

Shared GPU does not mean universal compatibility

API coverage and author GPU tests are promising, not certification. A Lightroom issue reports redraw and acceleration failures. Some performance notes describe uncommitted work, and fallback pixels can be much slower.

3

Convenience crosses security boundaries

Loopback RPC and MCP have no inspected authentication gate; guest credentials persist in INI and unattended media. Silent administrator elevation, test signing, writable shares and persistent USB permissions demand an explicit trust decision.

Desktop integration

Per-application windows, popups, file opening, USB attachment and shared folders are implemented. Managed mirroring distinguishes listener readiness from the first actual frame.

Compatibility evidence

The root README offers D3D9/11/12, Vulkan, OpenGL and OpenCL, including 32-bit processes. Native D3D9 exports exist despite stale component documentation. Real-app compatibility remains unverified here.

Evidence limits

The GPU harness describes multiple GPUs, image comparisons and reset detection. Large traces and run outputs are outside Git; no complete independent benchmark replay was obtained. Current CI targets main while the default branch is master and references missing codegen paths.

Manager → framed JSON RPC → guest service/session helpers. remotewin carries windows; accel-virt carries GPU commands through a patched QEMU device. GPU-backed frames use exported dma-bufs; fallback uses TCP pixels.

LSW runs the executor inside QEMU, not the optional separate renderer described by accel-virt. Host forwards bind loopback, but the guest listener binds all guest interfaces. The manager also starts a powerful unauthenticated loopback MCP endpoint.

Credential storage is plaintext QSettings INI plus unattended media. Framing has no visible maximum payload cap. This is not a hostile-guest containment recommendation.

Target: x86-64 KVM, KDE/KWin Wayland, host Vulkan drivers, Windows 11 24H2+ and unenrolled Secure Boot keys for the test-signed driver. Arch-built packages currently require Qt ≥6.12; other distributions may not match the ABI. Defaults include 8 GiB guest RAM and a 60 GiB disk.

Recovery before experimentation

Back up disk, NVRAM, domain XML and settings before upgrades. Package removal is not a complete cleanup: inspect user state, desktop integration and generated USB udev rules. reset-vm.sh deletes the entire data directory despite its ISO-preservation comment; do not use it as recovery for valuable data.

Rights and redistribution

Root LSW is Apache-2.0, but bundled QEMU, WinFsp and other components retain their terms. Neither pinned standalone first-level submodule had a tracked LICENSE/COPYING file; clarify before reuse. Windows, applications, SDK/WDK materials and media require separate rights.

Verdict

The call, and why.

⚠️ Interesting

Substantive experimental engineering, not a hardened daily driver. Evaluate on a disposable licensed guest: unauthenticated local control, plaintext guest credentials, stale CI and a destructive reset script require caution. Static review only; no applications, benchmarks or VM installation tested.

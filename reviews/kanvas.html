Key points

What matters most, in order.

1

The tool is the policy

Agents never edit the canvas JSON directly — they go through canvas-tool.py, which enforces valid state transitions and dependency checks. An agent physically cannot mark a blocked task doing, or skip review. That's the correct trust model for shared human/agent state.

2

Both sides contribute, with the right power split

Agents propose (purple) and execute; humans approve (red), draw dependencies, and verify done work (green). Not a one-way instruction sheet — a shared space where the human holds the two gates that matter.

3

Verified: blocking works, transitively

Run against the sample board: status, ready, and blocked all compute correctly — including chains (DL-03 correctly gray behind a gray DL-02), and automatic unblocking when a dependency goes green.

4

Git-native project memory

Board and code commit together; any checkout shows the plan state at that moment. No server, no account, no database — project archaeology for free. Caveats: maintenance looks stalled (last push 2026-03-27), and there's no multi-agent locking story.

Kanvas trades collaboration features for zero infrastructure and local-first operation — the right trade for a small team with an Obsidian vault already.

Clone outside your project, open the project in Obsidian once (to create .obsidian/), then:

python ~/repos/Kanvas/canvas-tool.py init ~/repos/my-project

Copies the CLI, instruction files, rules, and a blank board; installs the watcher plugin. Python 3.7+, any OS. Node only needed for the standalone watcher.

Key points

What matters most, in order.

1

A research host, not a normal app install

Physical Apple Silicon and macOS 15+ are the documented baseline; nested macOS guests are unsupported. Even the narrower setup relaxes SIP debugging restrictions and changes AMFI admission. Exact guest/host pairing matters.

2

Protect the library, not just the API

Eligible VM artifacts are deliberately changed to 0777; exposure depends on ancestor traversal permissions. HTTP tokens do not protect the local RPC/shell socket or on-disk guest data. Avoid sensitive accounts and audit permissions after lifecycle operations.

3

Recovery has a precise scope

Stopped-machine APFS snapshots keep disk, SEP storage and NVRAM together. They do not revert VM configuration, firmware inputs or live memory; exports omit snapshots. Schema-1 VMs require recreation for 2.x.

Real firmware, bounded compatibility

Not an Xcode Simulator substitute: modified Apple guests, device-specific patch recipes and restore/signing dependencies. Release 2.19.0 adds visionOS 27.2 support according to upstream; no guest combination was booted for this review.

Powerful automation

HTTP/WebSocket is opt-in, with a per-launch random token and browser-request checks. The proxy admits connections, not per-method roles. Plain HTTP, token-bearing logs and the separate local control socket remain important boundaries.

Host-side hardening

The root helper checks caller signatures and administrator authorization, hashes copied archives, validates nested signatures and records executable cdhashes. These useful defenses do not remove the need to trust the publisher and privileged extraction path.

Pinned scope

Reviewed release 2.19.0 at 5dfd335a3a39ad7e5d1a24da80fbaa1a6c251aaa. Its annotated tag resolves to that commit. Public CI metadata reports build/release success; tests were not run locally.

Different trust objects

Notarized Launchpad is distinct from the ad hoc signed core bundle. GitHub asset digests and nested signature checks establish integrity within the release trust chain, not independent publisher authentication or reproducible builds. MIT does not grant Apple firmware, SDK or service rights.

Device and user boundaries

Normal restore resolves a VM ECID, but lower-level device selection can use an attached device. Restore is destructive. Disconnect unrelated hardware and verify identity. Guest files and local automation are not a multi-tenant isolation layer.

Dedicated workstation only

Use an explicitly documented host/firmware pair, matching Launchpad and core-bundle series, ample storage, a protected library parent and loopback-only automation. Do not put production Apple IDs or personal keychains in the guest.

Before useful data

Verify artifact provenance, audit resulting filesystem permissions, back up coherent machine state and test restore independently. No installation, firmware download, live API probe, physical-device access or virtualization was performed in this review.

Verdict

The call, and why.

📚 Study

Study the native pipeline and coherent snapshots; operate only on a dedicated research Mac. Relaxed host security, guest-root control and deliberately 0777 VM artifacts rule out an unqualified shared-workstation recommendation. Static review only; no VM or upstream tests run.

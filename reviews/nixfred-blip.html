Key points

What matters most, in order.

1

A Mac is the gateway

Not an iMessage protocol replacement. A logged-in, reachable Mac and Omarchy/Hyprland are operational dependencies; broad macOS permissions remain significant.

2

Real controls, incomplete isolation

Restricted SSH dispatch and same-UID socket checks are concrete strengths. Default-on web previews contact senders’ sites, and DNS checks do not pin the connection address.

3

Read-only is not a backup

Saved exports avoid overwrites, but the 200 MiB sent-media retention store can evict files still needed for attachment viewing. Uninstalling the Mac directory removes it too.

Blip integrates a bar badge, popout and separate Messages-style window into Omarchy. The Mac reads its Messages database and performs sends through Messages.app; Linux renders conversations and invokes bridge tools over SSH. It does not implement Apple's protocol, replace the Apple account, or work without the Mac. SMS/RCS depend on the Apple-side forwarding/account setup.

Conversation search, rich attachments, group identities, contact review/export/creation, notification allowlists and optional OTP autofill are substantive features. Edit/unsend, native threaded-reply sending and typing indicators are not supplied. Experimental tapbacks have narrower text/DM and OS-version limitations. The README's screenshots use fictional fixtures, a useful privacy-conscious documentation technique. README

Metadata-only unread reconciliation

The collector separates the seen watermark from read marks and persists an unread ledger rather than relying on a moving recent-message window. Read intentions are retained and reconciled against Mac state; newer inbound activity can invalidate an old retry. This is a meaningful correctness design, not just a cosmetic badge. Groups are addressed by their actual chat GUID instead of the most recent speaker. collector.ts, read-sync.ts, thread.ts

Restricted transport, not a restricted account

The Mac forced-command dispatcher shlex-splits requests and execs only named tools, without an arbitrary shell. The dedicated key uses its own ControlMaster socket and disables agent identity substitution. The optional accelerator has owner/mode checks, same-UID peer credentials, bounded queues and deadlines; its Mac serve channel allowlists read-only commands and failures fall back to one-shot SSH. These are concrete, inspectable controls. dispatcher, shim, daemon, reader

Deliberate exports and action verification

Attachment saving pins destination directory descriptors, uses exclusive staging and hard-link publication, and numbers collisions rather than overwriting files. Contact creation is distinct from contact review; source documentation describes duplicate checking and native API readback rather than direct database editing. Read/tapback actions distinguish a click from verified state. These controls reduce common data-loss and false-success problems without proving every platform interaction works. save-attachment.ts, contact-save, imsg-read

Architecture

BarWidget owns refresh/watch behavior and the shared model; BlipView and window/panel components display it. TypeScript helpers handle collection, search, send state, media fetching and display transformation. Mac helpers remain separately executable behind the forced-command entry point. The persistent bridge is an optimization, not a new cloud service: two pooled SSH channels amortize Python and database startup while binary attachments and mutations keep separate paths.

This separation supports pure logic tests and mocked transport tests. It also creates a large compatibility surface across QML, Bun, Python, shells, Apple database schemas and localized UI automation. The 2,672-line collector and 2,800-line-class Mac reader are substantial modules, not a tiny glue script. The vendored bridge records its upstream origin and Blip-specific deviations in BRIDGE-VERSION.

Security, Privacy and Execution Boundaries

  • The Mac and Linux user account are trusted. Full Disk Access is granted to sshd-keygen-wrapper, not exclusively to the Blip key. Other shell-capable keys on that account inherit broad access. The restricted key still intentionally reads messages and invokes send/contact actions. The client automation switch is not a defense against another process running as the same user. If the dedicated key is absent, the shim falls back to ordinary SSH authority; verify confinement, do not assume it. SECURITY, shim
  • No hosted Blip relay does not mean no outbound web requests. Automatic link cards default on, directly contacting linked sites from Linux when conversations are opened. The implementation accepts HTTP as well as HTTPS, sends no configured cookies, executes no page JavaScript, limits redirects/body sizes, and rejects many private addresses. However, safeUrl resolves a hostname separately from fetch(current): the validated IP is not pinned to the connection. That leaves a DNS-rebinding/validation-to-use gap in the intended SSRF defense. This is a static design finding, not a reproduced exploit. Use link_previews=off or an enforceable public-only egress boundary. linkpreview.ts
  • Message-body minimization is useful, not zero sensitive storage. Normal send bodies use stdin and state snapshots retain metadata rather than text. Attachments, preview titles/descriptions, contacts summaries and explicit exports remain sensitive; the notification daemon may retain previews. A clicked URL reaches the browser, and allowlisted toast previews can appear in process arguments. The absolute README slogan that text never touches argv/disk needs these qualifications. PRIVACY
  • Optional automation adds real powers. Read pushes can emit read receipts and select a Mac conversation; tapbacks use Accessibility; OTP autofill injects into a focused field. Origin checks and single-use/deadline logic help, but application-supplied accessibility labels are not authentication. Enable features individually and test with synthetic/non-sensitive inputs. An unlocked gateway and auto-login guidance also have physical-security costs; retaining disk encryption and accepting manual unlock is a legitimate safer tradeoff. OTP policy, desktop adapter
  • The advertised audit is project-reported. docs/SECURITY.md describes a Codex audit and later multi-lens reviews. The fixes are useful evidence, but neither token counts nor an audit label establish independent assurance of the current revision.

Data Preservation and Installation

Read-only SQLite avoids directly corrupting Messages history, and muting/filtering in the client is not deletion. Nevertheless, Blip is not a backup. Mac file sending deliberately retains staging files because Messages may leave attachment records pointing at them. keep_sent limits that store to 200 MiB and removes older directories; its failure fallback deletes staging. Consequently older sent media that depends on that retained copy can become unavailable. The README's uninstall instruction to remove the entire Mac Blip directory also removes this retained media. Export important originals and inspect dependencies before cleanup; “never writes chat.db” is not equivalent to “cannot lose attachment availability.” imsg-send, keep_sent/gc_outbox, README removal section

The setup script preserves non-owned configuration keys, appends an SSH block rather than replacing the whole file, and backs up displaced non-shim executables. It still mutates SSH authorization, installs helpers on both hosts and rewrites owned config values. Its config write is direct rather than a transactional rollback system. Review a pinned revision and back up relevant configuration first. Plugin installation follows main; updating Linux alone does not necessarily refresh the Mac helpers. No installer was run for this review. blip-setup

Tests, Claims and Maturity

The committed Ubuntu CI runs Bun tests, synthetic QML badge checks, Python syntax checks, numerous bridge regression suites, and shellcheck. Tests explicitly cover read verification, scheduling, attachment MIME, conversation clustering, socket trust, deadlines, quoting and contact creation. This is meaningful breadth. It is not a macOS integration matrix: real TCC grants, AppleScript behavior, Accessibility focus and Messages delivery still need live qualification. Bun is selected as latest and actions are version-tagged rather than immutable SHA-pinned. No tests or dependency audit were run here. CI

The Bun preload redirects XDG cache/config directories but does not replace HOME, while some helpers compute paths directly from HOME. That preload alone is not a secret-free sandbox. Future tests should run with an isolated home, no host credentials and no real SSH/desktop endpoints. test-setup.ts, collector.ts

This is a two-device personal client, not a multi-tenant web service. Documented baseline is macOS 13+ with a logged-in Messages session, SSH and one-time permissions, plus Omarchy/Hyprland and the listed Linux tools. Sleep, logout, screen lock, TCC changes and macOS upgrades affect different features differently. Do not solve every failure by weakening system protections. Restrict SSH reachability, inventory other account keys, keep the dedicated key confined, start with previews and optional automation disabled, and confirm intended recipients and delivery/read outcomes on your own test account before normal use.

Verdict

The call, and why.

⚠️ Interesting

Credible specialist client with strong transport and read-state engineering. Pilot on your exact platform; disable automatic previews for sensitive use and preserve sent-media originals. Static review only: no tests or live messages.

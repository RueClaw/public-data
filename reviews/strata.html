⚠️ Interesting — promising trial candidate with licensing and installer-verification caveats. The architecture goes well beyond a cosmetic file browser, and the preview/update defenses deserve credit. Do not treat the root MIT badge as a complete reuse answer or assume the shell installer always authenticates build provenance.

Strata targets Arch Linux and Omarchy while supporting compatible GTK4 Linux desktops. It combines columns, grid and list presentation with shared navigation/selection, recursive fuzzy filename search, local and GIO/GVfs locations, previews, file operations and device integration. Optional portal/file-manager integration can make it a system-wide chooser or folder handler.

The published binaries require glibc 2.39 or newer and GTK 4.12 or newer, with additional media/desktop libraries. This is a native desktop application, not a dependency-free static binary or a server to self-host. README, manifest.

The implementation separates UI, browser/model work and services rather than rebuilding operations for each presentation. Cancellable enumeration, bounded streaming and incremental monitoring are particularly relevant to large or changing directories. Search indexes names/paths; it should not be sold as universal full-document content search. Remote shares are not included in global filename indexing at this revision. Source tree, main, README.

Parser-backed previews run across process boundaries instead of treating every untrusted file as safe GTK input. The inspected browser worker requires fully enforced Landlock write restrictions, including truncate protection, and no-new-privileges; seccomp closes additional mutation paths. This is real defensive code, not merely a README claim. It does not establish that every parser, helper or desktop capability is fully sandboxed. Worker, process boundary.

Test hostile/truncated media and sandbox failure behavior in an isolated environment before making it the default file manager. A file browser necessarily holds broad access to the user's files; parser containment is not a replacement for backups and explicit destructive-action confirmation.

The in-app update path parses bounded manifest/signature documents, uses bundled trusted keys, checks artifact size/hash and binds a package to its source commit. Archive and command-handling code has corresponding tests. These are positive static design signals; this review did not verify a downloaded release. Manifest verification, archive handling, tests.

In contrast, the shell installer's verify_provenance function warns and returns successfully when GitHub CLI is absent or unauthenticated. Installation then proceeds after HTTPS plus a checksum downloaded alongside the archive. Checksums catch corruption but are not independent publisher authentication if both files are replaced. The README's stronger provenance language therefore needs qualification. This is a confirmed control-flow discrepancy, not evidence of an actual compromised release. Installer.

- Custom actions and external providers are executable extensions: install only scripts whose authority you understand. Their existence is intentional functionality, not by itself a vulnerability. Custom-action documentation. - SMB/SFTP use desktop authentication integrations; the README describes explicit host-key decisions. Do not silently accept new host identities or assume remote operations have local-filesystem semantics. - Optional portal, folder-handler, keybinding and encrypted-volume integrations change desktop behavior. Evaluate them separately from opening the app, and preserve a rollback path. - Automatic update checks are on by default and can be disabled. This creates routine network activity even when local browsing is the main workload. - No reviewed HTTP server/auth/CORS surface is presented here. The relevant IPC and permissions are local desktop/D-Bus and subprocess boundaries. Portal interface.

The actual root LICENSE is MIT, copyright 2026 LGSE Ltd., and Cargo.toml declares MIT. However, a tracked-file scan finds 18 files with GPL SPDX identifiers. Representative compiled source files include update manifest, archive handling and browser animation, each carrying GPL-3.0-or-later headers.

This is an unresolved scope conflict, not proof of infringement and not sufficient evidence to assign one simple license to the entire binary. Ask the maintainers to reconcile the declarations before proprietary reuse or redistribution. Do not erase restrictive headers based on the root badge.

RAR support is enabled by default in the manifest and uses UnRAR components. Bundled UnRAR terms permit handling RAR archives but prohibit using that code to develop a compatible RAR archiver/recreate the proprietary compression algorithm, and impose notice requirements for modified source. The dependency stack therefore cannot be summarized as MIT-only. No exhaustive transitive-license audit was performed.

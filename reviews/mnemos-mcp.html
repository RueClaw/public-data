Key points

What matters most, in order.

1

Lifecycle is the real advantage

Atomic capture pairs, signed-by-model labels, separate handoffs and startup delivery make memory usable. The author’s searchable plain-file control matched factual retrieval.

2

Forget does not erase

Old words, correction history and backups remain. Local SQLite is not encrypted storage; export is a lossy projection that can overwrite existing notes.

3

Keep authority narrow

Simple stdio scopes are not OS tenancy. Advanced ID-based inspection/forget lack full scope checks; autonomous hours add provider egress and host tools.

The agent chooses what to capture and writes its own content and lesson. Mnemos stores it, asks for reflection as memories age, and returns a waking packet plus query-driven recall. Standing preferences do not fade; handoffs belong to sessions; journals are not automatically converted into beliefs. This differs from automatically mining every transcript. Hooks and harness adapters provide the practical advantage over a folder of notes. Authorship resolution can inspect harness/session information; “not a transcript indexer” does not mean no integration ever reads a session file.

Neuroscience vocabulary describes software heuristics: strength, stability, accessibility, decay and graph propagation. These are inspectable mechanisms, not validated biological fidelity. The identity framing is product philosophy, not scientific evidence of consciousness. Overview, authorship.

Capture: atomic memory, not automatic summarization

Simple capture strips outer whitespace, appends supplied context, classifies kind/domain/tags with local rules and prepares an engram. Memory and continuity note land together through save_capture_pair; a standing mark shares that transaction. Embedding/bookkeeping follows the durable save and reports a secondary failure without claiming the original capture failed. That avoids an obvious retry-duplicates trap, although ordinary capture is not universally idempotent. Optional provider classification/connection discovery happens before the pair transaction. Capture, store.

Recall: hybrid, scoped and state-changing

Current retrieval uses 30 lexical and 30 semantic seeds, word/meaning weights 0.3/0.5, reciprocal rank constant 60 and a semantic floor of 0.35. Content and its authored lesson take their better lexical rank rather than duplicate votes. Resonance walks at most two hops and five strongest links per expansion; notes do not propagate activation. Scope/visibility filtering is part of candidate selection. Retriever.

At this SHA recall defaults to 16 rows, three allocated to handoffs, and allows 50 on request. Handoffs have a separate search so old drafts do not dominate memory results. Recall reinforces returned memories once per session, wakes dormant matches and can restore faded archived items when requested; deliberately forgotten/replaced items are excluded by the supported simple path. Only the first 15 returned memories are co-linked. This is not a pure read API: retrieval changes future behavior. Recall, unreleased changes.

Continuity and upkeep are distinct

Startup context records delivery/session state without running decay. Capture can request background upkeep; scheduled and capture-triggered upkeep share a transactionally claimed, token-owned lease. Reflection asks the agent what a fading experience taught or whether a fact still holds; the agent supplies the meaning/verdict. Handoffs, journals and standing preferences have different lifecycles from ordinary memories. Claims, consolidation, decay.

MCP authority

Simple tools are context, handoff, journal, note, page, capture, recall, correct, reflect, introduce, maintain and health. Bounds include 65,536 capture characters, 4,096 query characters and 50 recall rows. Type/length validation reduces malformed-input/resource hazards, not semantic authorization. Most operations are honestly annotated as mutating, but openWorldHint=false is not an offline guarantee when providers are enabled. There is no per-call human approval gate for writes: the host's tool policy owns that decision. Surface, limits.

Stdio delegates access control to whoever can launch/use the process. Simple scope is agent/person/project, configured rather than inferred from the current directory; project defaults to global. This avoids accidental fragmentation but requires explicit partitions for separation. Same-account processes can access the files. Authorship “signatures” are model/session labels, including caller-supplied model IDs, not cryptographic writer authentication. Scope.

Advanced mode is an admin boundary, not an equally restricted view. It adds setup, ingestion, inspection, functional-memory, belief and legacy shared-pool tools. In particular, mnemos_inspect(engram_id) and legacy mnemos_forget(engram_id) directly load an ID without the simple runtime's person/project check. Advanced access plus an ID can inspect/archive another partition within that database. This is a static finding, not an executed exploit; it does not imply network exposure or bypass of the simple tool. Keep advanced mode away from mutually untrusted clients. Inspect, legacy forget.

Persistent prompt injection

The implementation distinguishes agent/person/tool-authored words, labels unsigned/other-model notes and avoids promoting legacy tool-written content into identity. That is valuable provenance, but cannot determine whether an agent copied malicious instructions into its own capture. Such content can return at startup, especially when standing. There is no demonstrated semantic injection sanitizer or cryptographic writer attestation. Treat recalled text as evidence rather than authority; restrict writers and inspect corrections. Trust model.

Local storage is not local inference

- Baseline memory/FTS and maintenance need no dedicated account/key. Cached local embedding loads are forced offline; model download is a separate operation. The README estimates about 90 MB for the model and several hundred MB for libraries including PyTorch.
- Explicit provider selection sends selected memories for link/surprise judgments. A key alone does not opt in. Providers include Claude CLI, Anthropic, OpenRouter and OpenAI. Environment/config and searched .env files determine selection/credentials; default search includes the launch directory and Mnemos's own directory. A chosen OpenRouter path can also inspect an existing OpenClaw config for a key. Inspect ambient credential discovery; do not launch from an untrusted config context. Provider code.
- Explicit Gemini selection sends embedded memory/query text to Google. Its REST implementation places the key in the request URL; caught errors redact it, but URL-handling intermediaries/logging still deserve care. Embeddings.
- Optional Jev sends up to 1,000 message characters and six 200-character candidate lines to TypeSafe. The private key file is not shown back; scores choose cue lines, not memory rewrites. Jev.
- Anything a host agent reads enters its model context regardless of Mnemos's provider setting. Explicit shared captures enter a separate collective database, readable through recall by other agents and potentially their providers. Withdrawal authorization is tool-level, not OS isolation. Shared memory.

Quiet hours add autonomous work and cost

The documented setup choice is yes-by-default after disclosure; noninteractive setup does not directly schedule the hours. Claude hours use the person's plan and transmit prompt material, wake context and whatever is read/recalled to Anthropic. Own-hour defaults are 60 minutes/400,000 tokens; work-hour defaults 30 minutes/200,000 tokens. These ceilings are not dollar budgets or price quotes.

Controls include restricted Claude invocation, explicit MCP config, isolated settings, secret-read denies, sandbox enabled with no unsandboxed fallback, and previously written studio settings moved aside. But the own hour includes Bash/WebSearch/WebFetch: it is not an offline database timer. Actual isolation depends on Claude's installed runtime and OS sandbox. Hermes/OpenClaw handed-off hours use ordinary host tools, a weaker boundary acknowledged in the docs. Leave hours off until authority, quota and egress are accepted. Construction, privacy.

Companion exposure

The companion binds specifically to 127.0.0.1, uses a random URL token, validates Host, requires a matching Origin and JSON for writes, bounds request size, and sends no-store/no-referrer/nosniff headers plus a page CSP. Assets are bundled. The page can inspect neighboring local minds and change memory/settings: its URL is a local bearer capability, not a multi-user login. Do not share/reverse-proxy it as a remote authenticated service. Server.

Retention, Export, Backup and Durability

Forgetting is not erasure. Corrections archive the old pair and retain lineage/version history; forget archives rather than deletes. Normal recall suppresses deliberately forgotten content, but raw SQLite, backups and admin access retain it. No comprehensive hard-delete/retention-expiry workflow is provided by the documented interface. Uninstallation intentionally leaves memory. This is not a compliance deletion mechanism. Correction, privacy.

Storage is ordinary SQLite, not encrypted storage. POSIX helpers apply 0700 to newly created directories and 0600 to files; existing directories are not automatically tightened without force, and chmod is skipped on Windows. Use disk encryption, account ACLs and encrypted backups. “One file” is simplified: WAL/SHM sidecars, shared stores, backup files, config and hour records also exist. File security.

Backup uses SQLite's online backup API, integrity-checks the copy and publishes through a temporary file. Restore saves the old destination, restores through SQLite rather than swapping a live WAL-backed file, then compares fresh-connection row counts/digests for seven principal memory tables. Stronger than copying the main DB, but not proof of every table's semantic correctness or all power-loss conditions. DB backups do not preserve every integration setting/hour artifact; this is not an off-machine backup policy. Backup/restore.

WAL, five-second busy timeout, immediate transactions, rollback on BaseException, migration backups and code-version gates address real failures. WAL synchronous=NORMAL favors performance; it does not promise the latest acknowledged transaction survives sudden power loss. An expiring upkeep lease is not permanent exclusion if a job outlives it. Recent Hermes fixes serialize shared-connection calls and correct conversation handoffs, but MCP sidecar mode still cannot distinguish every topic sharing one server. Do not treat one runtime as a proven arbitrary-concurrency service. Transactions, Hermes fixes.

Workspace export is a projection, not a round-trip backup: it truncates selected content and writes MEMORY.md plus daily/topic/belief files. It directly overwrites rather than merging existing notes; selection is agent-level rather than the simple API's full person/project scope. Export into an empty dedicated destination; inspect for mixed-scope content and stale exports after forgetting. Exporter.

Evidence, Costs and Maturity

The README reports 35%→65% on 30 tasks, 14%→41% on 64 sealed questions and 22%→42% with ordinary tools. These are author-run, one-person workloads, not independently reproduced results. The useful control is that the same memories as searchable plain files scored 43% versus Mnemos's 42%: evidence supports capture/wake discipline more clearly than superior retrieval. Reported 22%/8% cost reductions are workload-specific API-price accounting, not guaranteed subscription/embedding/autonomous-hour savings. Claims.

The public synthetic retrieval benchmark uses 224 engrams, disjoint topic vocabularies and one seed. Its recall@k denominator is capped at k, equaling precision when topics have enough relevant items; it is not full-corpus recall. Published depth-three default results also describe an older propagation design: current code uses two hops and a fan limit. Do not transfer those numbers without rerunning. Recent unreleased handoff rules were chosen after inspecting a small question set; the changelog reports no live-agent validation for that selection yet. Benchmark, constants, changelog.

Begin with simple stdio, one trusted identity, explicit scope and an isolated store. Verify actual semantic availability, not just provider selection. Leave dedicated providers, shared memory and quiet hours disabled until accepted. Do not expose the companion remotely. Back up before upgrades and test restore using synthetic data, including corrections/forgotten rows and mixed scopes. Use empty export destinations. Expand concurrency only after demonstrating distinct handoffs and complete saves on intended host versions.

Before sensitive use require synthetic checks for out-of-scope IDs, malicious stored instructions, retried writes, interrupted transactions, backup/restore, provider egress and the exact sandbox. This review is static evidence, not a penetration test, runtime compatibility certification or longitudinal retrieval evaluation. No private memory or transcripts were used.

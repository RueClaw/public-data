Readable physical and logical topology

Port VLAN ticks distinguish tagged and untagged membership; trunk cables use a contrasting inner stroke, and link widths encode speeds. Folder-shaped physical device cards distinguish hardware from guests. These are useful design patterns, but the actual cable endpoints and several speed labels remain hardcoded: changing a YAML port target alone does not reroute the line. build.py

Dense server and storage views

Hardware lists, grouped VM/container cards, multi-app containers, disks, pools and a media-flow explainer make one image unusually information-rich. Optional fields support guest kinds, cluster-node labels and multi-VLAN SSIDs. Some overflow assertions and text measurements help detect fit problems, but they are not automatic layout or general collision detection; Python optimization can disable assertions. server and guest rendering

Two output modes, not a privacy guarantee

Default mode substitutes the configured domain in text, selects a redacted title and uses each SSID's redacted field. Unredacted mode uses separate filenames. Internal addresses, hostnames, inventory IDs, hardware/OS versions, exposed services, topology and watermark remain visible unless the user edits them. SSID replacement is specific to its rendering section, not a general text scrub. Inventory flags can disable redaction even without the unredacted CLI option. Review the entire SVG and PNG before sharing; never place credentials in inventory notes. redaction setup, SSID rendering

The build script loads inventory at module top level, builds VLAN/color lookup maps, appends SVG strings into one list, computes the final canvas height, writes SVG and invokes librsvg. It is a script, not a reusable import-safe library: importing it also performs the build. The icon helper caches base64 bytes to avoid repeatedly reading each image. Text helpers apply domain substitution and HTML escaping. The final height follows the main server panel rather than computing a bounding box over every rendered element. input/helpers, export

Discovery and outbound access

The renderer has no application-level network client. Its subprocesses are font lookup and image conversion, using argument arrays rather than shell interpolation. The separate icon downloader contacts jsDelivr, then raw GitHub on failure, using a fixed mapping of names. It has a 20-second request timeout, bounded retries, modest delays and an aggregate failure exit; it does not implement Retry-After handling. It downloads from moving upstream paths without content digests, MIME/XML validation, download-size bounds or redirect restrictions. Once icons are present, no downloader is needed for ordinary builds. Dependency installation is another optional network step, not performed for this review. fetch_icons.py

Rendering and input safety

PyYAML safe_load avoids arbitrary Python-object constructors, and text nodes go through html.escape with quotes enabled. Those are worthwhile protections, not a complete trust boundary. Inventory-derived VLAN colors are interpolated directly into SVG attributes without validation or escaping; crafted colors could break attribute boundaries or introduce markup in a directly opened SVG. Icon names are joined to the icon directory without checking containment, allowing traversal to other readable files with an SVG suffix; those bytes are embedded in the output. Base64 encoding is not SVG sanitization. Exploitability in a particular browser or librsvg version was not tested.

There are no schema, numeric-range, input-size or rendering-time limits. Wrong keys/types can fail with exceptions; oversized inventories, images or values can consume resources or break geometry. PNG conversion has check=True but no timeout. Keep inputs and icons trusted, validate colors and paths before offering any upload workflow, and isolate rendering with no host secrets. Do not expose these scripts unchanged as a public service. SVG primitives and icon loading

Persistence, export and recovery

The editable source of truth is YAML plus Python, not the exported picture. There is no round-trip SVG import, undo history, built-in backup or multi-user conflict handling. Output and downloaded logos are ignored by Git, but inventory is tracked: adding real infrastructure details to it can disclose them through repository history regardless of render redaction. Keep private inventory outside a public checkout and pass it with --inventory; also remember that outputs still go into the script's own out directory.

Builds overwrite fixed filenames. SVG is written before PNG conversion; a failed conversion can leave a new SVG beside an old, missing or partial PNG, so file existence is not a success receipt. No atomic publish pair, manifest or freshness checksum exists. Icon fetching overwrites successful files while retaining other old files on failure, allowing mixed upstream versions. Recovery is a rerun after fixing inputs/dependencies, with independently backed-up sources and verified outputs. For reproducible snapshots, archive permitted icon bytes and system dependency versions as well as the Python lockfile. export, .gitignore

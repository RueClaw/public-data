Source and package distribution

package.json exports ESM, types, shared CSS, assets and component subpaths. The library config preserves modules and externalizes React and the Three.js variants. This provides a small-import path, but does not establish a measured bundle budget: multiple Three.js versions can coexist, and authored HTML/runtime assets add costs outside the JS import graph.

Public subset validation

Boundary tests compare catalog/report counts, check variant/control parity, validate source bundle hashes, exclude paid entries and inspect runtime documents. Release tests cover semver classification; CLI tests exercise PKCE, path rejection, auth persistence, byte-preserving downloads and overwrite refusal. This is stronger packaging evidence than a screenshots-only collection, but self-consistency with a generated report is not proof of renderer correctness or private-tree completeness. See the existing public subset pattern.

Heterogeneous rendering

WovenCloth uses titled, allow-scripts-only sandboxed srcDoc iframes for companion variants. This avoids granting parent same-origin privileges. It is not an offline or no-network boundary: scene code can still fetch libraries/assets, and restrictive CSP/CORS policies may break individual scenes.

WarpFieldBackground instead owns a canvas renderer, resize/intersection observers and an animation loop, disposing resources on unmount. Its renderer caps DPR at 2, shares some geometry/materials and explicitly disposes textures and layers. Those are concrete engineering positives, not a library-wide FPS or memory guarantee.

Rendering and accessibility

  • Motion is component-specific. Search preview videos respect reduced-motion preference and use buttons with descriptive labels. The sampled Warp Field host has no reduced-motion check, and its canvas has no explicit accessible description or decorative hiding. Supply semantic alternatives or mark truly decorative visuals appropriately.
  • A lifecycle edge needs testing. Warp Field schedules its next frame only when intersecting and the document is visible. If a callback observes document.hidden, the loop stops, but the host has no visibilitychange restart listener. Returning to an unchanged viewport can therefore leave it paused until an intersection transition. This is static control-flow evidence, not a reproduced browser bug.
  • Timing is frame-dependent. The sampled renderer advances elapsed time by 1/60 and position by a fixed step each render, rather than real delta time. Refresh rate can change apparent speed. It also captures variant at construction while the React effect has no dependencies; changing the variant prop without remounting does not rebuild the chosen scene.
  • Modal semantics are incomplete evidence. SearchDialog declares dialog/aria-modal, initially focuses the input, supports Escape there and labels results. No focus trap or focus restoration is implemented in that component, and the input has placeholder text without an explicit label. No screen-reader or keyboard traversal audit was run.
  • Do not generalize visual polish into platform support. WebGL, observer APIs, GPU limits, root-relative assets, iframe origin rules and client execution matter. SSR/framework integration, context-loss recovery, touch behavior, low-end mobile thermals, contrast and memory stability remain untested.

The main flow is src/main.tsx → App.tsx → catalog/docs → selected renderer. Generated src/data/shaders.tsx, src/index.ts and src/package-components/ connect the catalog to package entry points. public/source-code.json supplies the code tab. Synchronization from a separately held upstream snapshot filters access tiers and copies public source/assets; consumers do not need that private snapshot to use the checked-in tree.

Site and library have separate Vite builds. A third surface, packages/cli, handles optional authenticated Pro downloads. Keep those trust domains separate: a login-free Community renderer does not require installing or authenticating that CLI.

Security and privacy

Community needs no model provider, API key or paid service. That does not mean zero outbound traffic: asset notices document ThreeUI-hosted previews/media and public CDN resources. A self-hosted copy still needs a per-scene request inventory and licensing/CSP decisions. The hosted service/backend was not audited.

The optional OAuth implementation uses random state and S256 PKCE, a loopback browser callback, atomic auth-file replacement and owner-only modes when creating files/directories. Refreshable bearer credentials live in a local JSON file, not an OS credential vault. Server-side entitlement enforcement is a README claim outside this public tree’s verification scope.

The installer rejects absolute/traversal paths and duplicates, and refuses changed-file overwrites unless forced. Containment is lexical, not filesystem-real: it does not resolve/reject symlink ancestors before mkdir/writeFile. A pre-existing linked directory can redirect writes outside the intended destination. This is a static risk, not a tested exploit. Use a fresh trusted destination; add real-path/no-follow safeguards before accepting hostile bundles or working trees. Writes are sequential rather than transactional, and remote bundles have no explicit size budget or independent signature check here.

The CLI entry point allows development API/metadata overrides without an HTTPS/origin allowlist. An existing valid session can be reused while the API endpoint is overridden; an untrusted command line can therefore redirect an authenticated download request. Treat those flags as credential-routing authority. Downloaded source is not automatically installed/executed by this installer, but becomes executable when incorporated into a project. The CLI can launch a system browser; none of it was run for this review.

The public audit is a useful heuristic, not a security scanner. Its text-extension allowlist omits .ts/.tsx, so sensitive-assignment scanning does not cover the primary TypeScript files. Build auditing checks selected signatures and source maps, not arbitrary secrets or hostile logic. No fresh dependency vulnerability assessment was performed; the old review’s clean audit is not today’s result.

CI and maturity

CI declares clean install, tests/typecheck/site and library builds, audits and anonymous package-install smoke checks on Linux/Node 24. npm publishing uses provenance/OIDC and an environment, but is a separate workflow; public configuration alone does not prove publishing waits for every verification job. Actions are version-tagged, not immutable SHA-pinned. The inspected tests emphasize packaging/boundary/release/CLI behavior, not automated browser accessibility or rendering benchmarks.

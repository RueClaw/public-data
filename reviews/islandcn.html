What matters most, in order.

An activity renderer, not a task service

A priority/group store drives compact, split and expanded views. Your app still owns execution, authorization, persistence and recovery.

2

Detailed motion, incomplete public proof

islandcn places a black pill at the top of a page or positioned container. Activities supply compact, minimal and expanded React content; the engine selects idle, single-activity, split and expanded presentations. Priorities select the foreground activities, while groups allow several activities from one source to take turns. Upload, timer, music, incoming-call, ETA, recording, nearby-transfer and battery presets demonstrate the UI vocabulary.

Those names describe presentation, not service integrations. The reviewed engine/presets do not implement microphone capture, telephony, transport, background upload execution, or an OS-level island. The embedding app supplies real state, media permissions and callbacks. A playground edits activities and motion, exports code, and serializes designs into shareable URLs. An optional coding-agent skill teaches installation and composition; it is not an embedded model or paid provider integration. README, recording preset

Activity state is separate from rendering

actions → in-memory store → derived scene → measured geometry/choreography → SVG and content layers

The store exposes start/update/end/expand/collapse, stable handles and subscriptions. Reusing an ID updates rather than duplicates an activity. Priority sorting is stable by start order; group handoffs have explicit timers, and delayed alert content has cancellation/flush paths. React consumers use useSyncExternalStore; useIslandActions avoids unnecessary consumer subscriptions. This is more substantial than a CSS morph demo. Store, hooks

Motion is interruptible and inspectable

Closed-form spring evaluation and per-transition choreography let shape targets change mid-flight instead of restarting an unrelated CSS animation. A controllable frame clock supports pause, step and seek for captures; the optional window devtools object is off by default. SVG pill/bubble/neck geometry and separate entering/leaving content layers produce the characteristic split and merge effects. Frame work writes DOM properties without requiring a React rerender for every frame. The main surface is nevertheless 2,296 lines, a significant maintenance and regression surface for copied source. Spring solver, choreography, surface, clock

Source ownership is useful, but updates are your work

Registry generation checks imports against site-only modules and verifies declared registry/npm dependencies. The core item ships engine files rather than requiring the Next.js site. Presets use a lifecycle hook that starts after hydration, updates from dependencies and ends on unmount. This supports ordinary React apps, including a documented Vite path, but the code is DOM-oriented—not React Native or non-React UI. Registry builder, engine item, lifecycle hook

Accessibility and Platform Compatibility

There is real accessibility work: a named region, native button hit targets, activity labels, polite live announcements, Enter/Space expansion, Escape/outside collapse, focus restoration when content disappears, visible focus outlines, and inert/aria-hidden outgoing layers. Reduced motion follows the system by default, replacing overshoot/blur/scale with gentler transitions. This is not the same as “no animation”: the documented reduced-motion shape transition still eases over 0.2 seconds. Root interactions, layers, engine guide

A concrete activation gap: the pill/bubble buttons wire pointer handlers and onKeyDown, but no onClick. Enter/Space is manually handled; an assistive technology that activates a native button by dispatching a click without those input events has no corresponding activation handler. This is a static code finding, not a reproduced VoiceOver/NVDA failure. Add and test semantic activation without double-triggering the pointer path. The detached bubble also lacks the pill's aria-expanded attribute. Test full keyboard traversal, focus after activity replacement, screen-reader activation and live-region verbosity with real application content. Surface interaction code, buttons

Browser-specific code detects Apple WebKit to adjust filter compositing and shadows. Comments report Safari improvements, not independently verified cross-browser benchmarks. The engine depends on browser DOM/SVG, ResizeObserver, animation frames and modern focus/inert behavior. Test Safari, Chromium and Firefox, touch long-press, narrow layouts, zoom, text resizing and reduced motion; phone-width clamps and clipped compact slots can hide long or localized labels. This review does not certify WCAG conformance, mobile frame rate or older-browser support. Platform workaround

Security, Privacy and Authority Boundaries

- Engine authority: ordinary same-page React code. No network client, credential store, model provider, account login or privileged OS service was found in the reviewed engine/presets. App-provided React nodes and callbacks are trusted executable code, not sandboxed content. A “Pay” or “Approve” button still needs application-side authorization and server validation; the UI is not an approval security boundary.

- Install authority: the README's npx shadcn@latest command executes a moving CLI and retrieves a mutable hosted registry that writes project files. Review/pin the CLI and source snapshot, inspect the generated files/dependencies, and commit a baseline before installing. The reviewed Git SHA is not proof that the current hosted registry bytes match it. The optional skill also writes instructions into both .agents/skills and .claude/skills; install only intentionally. Skill item

- Share-link parsing: fields are reconstructed through allowlisted kinds, icons, actions and sample-photo names, with text and numeric limits; sample-photo inputs are not arbitrary remote URLs. This is good defense against treating a URL as executable UI configuration. But the claimed 64 KiB inflated-JSON guard is checked only after Response.arrayBuffer has fully materialized the decompressed stream. Plain base64 JSON has no equivalent total-size cap. Bound encoded input and enforce a streaming decompression limit before allocation; otherwise crafted links may consume excessive browser memory/CPU. This is a static resource-exhaustion concern, not a demonstrated exploit. URL parser

- Sharing is not secrecy: the design lives in the query string, compressed/encoded, not encrypted. It can be copied, retained in history and received/logged by the hosting server when opened. Do not include credentials, private transcript text or real customer data. The component does not introduce a cloud sync account, but the URL is deliberately transferable.

- Development routes: frame/fidelity endpoints read reference/capture files and are enabled outside production, or with ISLANDCN_DEV_TOOLS=1. They validate root names, slugs and frame filenames and normally return 404 in production. They do not authenticate callers; do not expose a development/capture server. Filename checks are not a realpath/symlink confinement policy, so keep configured roots trusted. Build tracing excludes references, captures and env files as an additional packaging precaution, not an authentication substitute. Route policy, frame reader, Next configuration

No paid inference, provider OAuth or API keys are required by the component. Hosting, development and optional external coding-agent costs are separate and user-selected. No live hosting privacy behavior or dependency vulnerability audit was verified.

Persistence, Recovery and Operational Fit

The activity store is ephemeral. Reloading/remounting does not resume an upload, timer or recording from a journal. The application must reconstruct UI from authoritative job state and distinguish “hide/end this indicator” from “cancel the actual operation.” Group-hidden activities remain in the store; more activity state does not imply every task stays visible. Declarative presets clean up their own activity on unmount; imperative users own their handle lifecycle.

Store reset clears alert/press and pending-content timers. Surface observers/subscriptions have cleanup, and the frame clock stops scheduling when it has neither listeners nor timers. These are useful local lifecycle measures, not crash recovery, durable background work or guaranteed timer delivery in throttled tabs. Use wall-clock/server deadlines for consequential timing. Store, clock, provider

Source-copy updates can overwrite local edits. A regression test specifically guards a prior shadcn --overwrite import-resolution problem. Track upstream patches and review a three-way diff; rollback with project version control rather than assuming a package uninstall restores modified source. Regression test

The manifest is private version 0.1.0 with a pnpm lockfile and pnpm 11.28.7 selection. Build runs registry generation, a Blume docs build, then Next; it is not needed merely to consume already-reviewed core source. Build scripts execute local tooling and replace generated docs/registry output. Workspace policy permits esbuild/sharp build steps, uses copied package imports, and overrides two transitive dependency versions. Adoption / Self-Hosting Notes

For a pilot, take a reviewed source snapshot into a disposable React 19 project, use only required registry items, and keep the optional agent skill separate. Connect one non-sensitive task, then test cancellation versus dismissal, background-tab recovery, multiple activity priorities, pointer/keyboard/assistive activation and reduced motion. Fix bounded share decoding before accepting untrusted playground links in a sensitive environment.

You do not need to host the upstream demo to embed the component. If hosting that site, use a production build, keep dev/capture tooling disabled, do not mount private capture roots, and establish ordinary dependency updates, logging/privacy controls and security headers. No deployment was performed here.

Bottom line: technically interesting, unusually detailed motion work with useful source ownership. Adopt selectively as UI, not as a durable activity system or a substitute for tested accessibility and authorization.

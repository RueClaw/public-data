Key points

What matters most, in order.

1

RavenTrap, not the automation platform

The repository still says Huginn, but v1.0.0-rc5 is branded RavenTrap. It integrates Cowrie, OpenCanary and other sensors into attacker histories, replay and campaign views.

2

Constrained SSH is not complete isolation

The dashboard pulls through a root-side forced export command, which can also toggle IDS and logout behavior. Hardened parsing and privilege dropping help; network segmentation must still be enforced outside the honeypot.

3

Local-first does not mean offline

IP and DNS enrichment disclose observations to outside providers. ENRICH=0 does not stop keyed MalwareBazaar calls in the collector, update checks or configured notifications; secrets and captured material also persist in local storage.

Attacker investigation

Per-IP histories combine attempted credentials, commands, replay, file metadata and external lookups. Campaign shapes, bait interactions and static malware families are useful investigative leads, not validated attribution.

Controlled feeds

Tokenized text, nftables, ipset, MikroTik, CSV and C2 feeds include score/age filters, exclusions and a size cap. Manual blocks override never-block exclusions; compromised sensors can still fabricate evidence.

Pinned implementation · Upstream test result

Pull, parse, persist

Collector, enrichment and backup threads share a SQLite-backed application alongside a bounded threaded HTTP server. Capped recent sensor exports are parsed and deduplicated; long outages or heavy traffic can exceed available history.

Web and key boundaries

The UI defaults to HTTP on all interfaces. Specify allowed hosts, private ingress, TLS termination and narrow trusted proxies. Scrypt, same-origin POST checks, strict cookies, escaping, CSP and connection limits are positive controls, not proof of exploit resistance. Docker automatically trusts the first scanned SSH host key; independently verify it.

Privacy and egress

IP enrichment, DNS lists, optional hash lookups, update checks and ntfy have separate disclosure paths. UI-saved provider keys are ordinary SQLite metadata. URL feed tokens, captured credentials, recordings, environment and backups need restricted handling.

Recovery limits

SQLite backup API, integrity checks, atomic replacement and exclusive restore locks are concrete strengths. Same-disk database backups do not include every recording, setting or SSH identity. Default history retention is 180 days; flags and backups outlive deleted events.

Use a separate disposable sensor VM/VLAN and verify externally enforced LAN, gateway and IPv6 restrictions before forwarding ports. Keep the dashboard private and TLS-protected; inspect privileged installers and pin versions.

Treat feeds as observation-first. Define never-block networks, false-positive handling and firewall rollback. Disable unwanted integrations individually and enforce egress policy; ENRICH=0 is not a global offline switch.

Back up the database, recordings, configuration and SSH identity off-host, then rehearse recovery. The stdlib-only application still needs SSH, OS packages and external sensor dependency trees.

Verdict

The call, and why.

⚠️ Interesting

Thoughtful pull-based collection and recovery, but not a turnkey security boundary. Pilot only with external sensor isolation, private dashboard ingress and deliberate egress controls; treat blocklists and attribution as heuristics. Static review only, not an independent audit.

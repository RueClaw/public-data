Key points

What matters most, in order.

1

Layout feedback is the differentiator

Font metrics size blocks before placement; named reports catch overlaps, crossing lines and label problems. SVG outlines preserve appearance, while describe() preserves meaning for an agent.

2

JSON-only is not a security boundary

Theme values flow into unescaped SVG attributes, then into browser-rendered HTML for PNG. This static injection finding was not exploit-tested. CLI Python input explicitly executes code, including check mode.

3

Outputs need ownership and provenance

MCP filenames are sanitized but writes overwrite and follow existing symlinks. Draw saves pictures, not the input source; failed layout checks can still leave files. Keep source history and use a dedicated output directory.

Measure, place, check

Panels, tiles, groups, cards, rings and status-aware connections form dense maps. Geometry checks are heuristics, not semantic correctness or perfect-layout guarantees.

Import and export

Mermaid flowchart import is a subset; styling/click directives are ignored. Python offers local icon embedding. JSON/MCP excludes icon paths. Outputs are SVG and optional PNG, not an editable workspace database.

Evidence: diagram engine · Mermaid parser

CLI or MCP → JSON/Mermaid parser → measured blocks and Diagram → layout report and SVG → optional headless-browser PNG. No built-in model, account or paid API is required.

Trust and privacy

MCP sends descriptions and optionally image bytes to the calling AI application, which may use cloud providers. Agent charges and privacy terms are outside the library. Theme values are not strictly validated or escaped at serialization; output-name filtering does not protect against preexisting symlinks.

Recovery and limits

Source text has a 200,000-character MCP cap, but dimensions and compute are not comprehensively bounded. Save writes before reporting layout failure. PNG success checks can accept a stale output. MCP picture=false suppresses image return, not PNG generation.

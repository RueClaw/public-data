Key points

What matters most, in order.

1

Evidence is the output contract

Every analysis returns an immutable Evidence bundle: supporting citations, explicit limitations, and named unknowns — plus tools to canonicalize, export, and diff bundles across app versions. The agent can't overclaim, because the tool reports its own uncertainty. Same anti-hallucination philosophy as Leviathan's shown N of M, applied to reverse engineering.

2

It refuses to guess the engine

When multiple installed engines (Hopper, Ghidra, IDA) could handle a target, opening it fails with capability_unavailable, selection_reason: "ambiguous", and the candidate list. You choose once, explicitly; the session never silently falls back. Broken engine → provider_unavailable with remediation. Both failure modes are designed, not emergent.

3

Consent-gated, fully reversible setup

Setup shows exact paths and changes before applying, backs up existing config, detects-but-doesn't-select agents, treats Hopper as a separate consent decision. rea uninstall removes only REA-owned registrations, preserves Evidence and unrelated MCP servers, and never follows purge symlinks. Owner-only snapshot permissions; safe no-follow file opens; analysis on a temp copy of the target.

4

Verified: 4,059/4,066 tests pass

Local run after npm ci + build: 4,059 passed, 7 failed — all 7 are Xcode NIB-decoding boundary tests that look host-specific (macOS 27 NIB serialization), not logic bugs. Acceptance tests exercise the compiled CLI and MCP factories end-to-end, which is why the suite is this meaningful.

Investigation model

Decompile (recover readable code, strings, structure) → Understand (evidence-backed explanation) → Build (draft an equivalent feature for your project). The agent workflow is installed as a version-matched skill.

Snapshots and reference source

Exact-repeat queries are answered from local snapshot files before any provider process starts — cache hits require target bytes, operation, params, tool and settings to all match. Historical source imports stay separate from observations of the current app.

Scoped doctor

rea doctor audits host, engines, and agent registrations — with scoped readiness (--provider ghidra, --client codex, --skill) so a missing engine you're not using doesn't fail the task at hand.

CLI quickstart

npx rea-agents setup                          # consent-gated MCP + skill install
npx rea-agents analyze-javascript-application /path/to/app --json
rea doctor --provider ghidra --json
rea evidence-export bundle.json canonical.json
rea compare left.json right.json

Monorepo: src/ (MCP server, CLI, provider adapters, evidence model), bridge/ (Hopper/Ghidra analysis bridges), native/ (bundled native controls, e.g. Windows Job Object/private-DACL for the Windows Ghidra boundary), skills/ (version-matched investigation workflow), tests/ (unit/boundary/acceptance tiers).

Provider adapters expose a uniform contract — inventory, function, memory, load-image inspection, atomic annotation edits — over very different engines. Ghidra runs headless on a temporary copy; IDA attached mode never saves your GUI database.

REA is the disciplined layer on top of the engines you already trust. If you only ever use one engine and don't care about evidence bundles, a direct plugin is simpler.

npx rea-agents setup registers the MCP with chosen agents and installs a version-matched skill. No-setup path: static JS/Electron analysis works with Node alone.

Native analysis needs Hopper (demo mode works), Ghidra 12.1.x + JDK 21, or IDA Pro. Legal/ToS note: reverse-engineering rights vary by jurisdiction and license — REA's local, read-only posture is the responsible default, but entitlement to inspect the target is on you.

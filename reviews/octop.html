Key points

What matters most, in order.

1

Multi-user is the product, not a feature

JWT-isolated users, one admin per household or team, and per-user teams of expert agents — each expert with its own workspace, providers, channels, and cron. Most self-hosted assistants are single-operator; Octop is household-shaped from the database up.

2

Experts are reusable, shareable agent configs

An expert bundles persona (16 MBTI templates or a custom prompt), workspace, providers, channels and cron. A boot-scanned library, an expert market, and in-deployment sharing mean good configurations propagate instead of being rebuilt — skill-system thinking applied at the whole-agent level.

3

One process, one database, restart-safe

Web UI, IM, and cron all route through a single in-process HarnessProcessor — no external queue or broker. The whole state rebuilds from the control-plane DB (SQLite WAL by default, PostgreSQL optional) on boot. Operationally simpler than multi-service assistants.

4

Verified: 3,712 tests pass

Local run: uv sync clean, then 3,712 passed, 2 failed — both failures are FnOS NAS-specific process tests on macOS, not core logic. Caveats: v1.0.2 beta with 734 open issues, the agent runtime itself lives in external octop-* PyPI packages, and the one-line installer curls a script from a Tencent COS bucket.

Pluggable workspace backends

Expert files can live on local disk, in a Docker sandbox, PostgreSQL, or COS/S3 — separate from the control-plane DB. Memory travels with the workspace, so an agent's identity is portable across backends.

Bidirectional ACP

Inbound: octop acp serves any Octop agent to ACP clients (Zed, OpenCode). Outbound: delegate coding tasks to OpenCode / Claude Code / Codex / CodeBuddy with permission gates. Both directions of agent interop in one product.

Beyond chat

  • In-browser terminal with AI-assisted command execution and troubleshooting
  • Headless Chromium automation with persistent profiles (Browser AI+)
  • Remote desktop: live screen + input from the dashboard on Linux/Windows/macOS
  • RAG knowledge bases, shareable within a deployment
  • AgentTeams (beta): a coordinator schedules multiple experts on multi-step work

src/octop/ splits into api (FastAPI surface), cli, config, i18n, and infra — where infra holds agents (builtin skills, expert library), connectors (OAuth + MCP gateway), channels, knowledge, plugins, and workspace backends.

The heavy lifting — agent loop, memory, IM normalization, browser automation — is imported from four sister packages (octop-harness, -gateway, -memory, -browser, sources in sibling TencentCloud repos). This repo is the composition layer.

State discipline: one control-plane DB rebuilds everything on boot; workspace files are a separate, pluggable concern.

Octop trades engine depth for product breadth — multi-user, channels, desktop/NAS clients — and wins the license. The multi-user expert model is the thing single-operator assistants don't have.

One-line installer provisions Python 3.12 via uv under ~/.octop/ — note it curls from a Tencent COS bucket; audit the script or pip install octop instead.

octop init runs a setup wizard; octop run starts everything. Docker sandbox backend available for workspace isolation. Desktop clients for Win/macOS/Linux plus FnOS NAS packages.

Verdict

The call, and why.

⚠️ Interesting

The most complete multi-user agent platform reviewed to date: JWT-isolated users, shareable expert agents, pluggable workspace backends, one restart-safe process — MIT licensed with a verified test suite (3,712 passing). Hold-backs: v1.0.2 beta with 734 open issues, the agent runtime is in external packages, Chinese-ecosystem gravity, and a roadmap item ("Managed Agents") that telegraphs a hosted future.

Sync recovery: material improvement, not a backup guarantee

Desktop sync now stalls when its encrypted chain disappears, retaining the key, setup and unsent changes. Native writes reject a missing chain instead of silently recreating it. An explicit folder-recovery action checks availability/existence, saves reseed obligations before creation and republishes available local scope data; an existing folder with a missing chain is refused rather than overwritten. This cannot restore data absent from both local state and backups. engine.ts; folderRecovery.ts.

Session/sync revision marks and per-scope rebase obligations protect against interpreting an older restored session as mass pin deletion. Missing profiles retain their sync links; joining waits for pending/damaged downloads. The documented one-day join fallback still risks late remote settings/profile records losing to newly published local defaults; unstamped local edits can lose during rebase. Test fixtures were inspected, not executed. sessionMarks.ts; syncFiles.ts; sync documentation; data-loss tests.

Newer main: Memory Saver and search

Memory Saver caps the loaded-tab budget and adds configurable sleeping of unused/pinned tabs. Hover wake can load eligible Chromium pages after 150 ms; its policy excludes private profiles, manual sleeps, battery saving and memory pressure. This trades latency against resources and potential traffic before a click; no benchmarks or live traffic tests were run. sleepPolicy.ts; hoverWake.ts.

Claude Tab-to-search is a URL shortcut, not a built-in desktop model service. The updated public privacy page separately describes phone AI and optional direct OpenAI traffic, including Android incognito summaries after connecting ChatGPT. These mobile/provider claims are outside the desktop implementation audit. engines.ts; privacy page source.

### Native browser, real compatibility work

Profiles, split panes, sidebar tabs, DevTools, sleeping background tabs and import paths are concrete modules, not just screenshots. Chromium extensions and built-in uBlock Origin offer a meaningful compatibility advantage over a WebKit-only shell. DRM streaming can switch to WebKit, so security/privacy behavior is engine-dependent. README CPU, download-size and notarization claims were not independently reproduced. README.md; packages/ardiacore/scripts/ubo.sh.

Encrypted sync without an Ardia sync server

Sync writes sealed files to a user-selected folder; iCloud Drive is the default carrier, not the only one. The design uses a 24-word recovery phrase, HKDF-SHA256 derived keys, AES-256-GCM, authenticated file identity and padded records. The inspected Rust key code has distinct derivation labels, framing and zeroization. The carrier still sees file counts/timing/sizes; a stolen phrase, compromised binary or unlocked endpoint defeats this protection. Losing all devices and the recovery kit loses access; sync is not an independent backup. docs/sync.md; packages/core-rs/crates/ardia-sync-core/src/keys.rs.

Stronger-than-average boundary documentation

The privacy inventory enumerates stacks, cookies, per-profile behavior, gates and off switches. Its test checks source citations and host literals, explicitly not runtime absence of traffic. Socket schemas, consent-generation checks and recovery tests make good engineering patterns; their presence must not be confused with a completed adversarial audit. docs/privacy.md; apps/browser/src/privacyEndpoints.test.mjs; apps/browser/src/state/automation/controlSocket.ts.

Process isolation and browser sandbox

The page engine is Chromium's multi-process architecture with custom browser/renderer hooks, rather than web pages running inside the React Native JS context. The main delegate derives from Chrome machinery and strips dangerous profile-opening switches, including remote debugging, certificate bypass, extension loading and web-security overrides. That is useful hardening, but this static review did not observe live renderer sandbox status or verify site-isolation behavior on each OS. engine/ardiacore/src/ardia/core/ac_main_delegate.cc.

The Linux launcher normally refuses to start when neither user namespaces nor a suitable setuid helper is available. It does not silently fall back to an unsandboxed browser; an explicitly supplied --no-sandbox option is honored and labeled. Flatpak has a separate launch path. The Linux smoke harness checks renderer seccomp/namespaces and forbidden sandbox switches, but was not run here. Avoid using the manual bypass or weakening system namespace policy merely to make a package start. scripts/linux/ardia-launch; scripts/linux/smoke.mjs.

Agent and extension authority

The local control socket is available while the user enables CLI control. macOS has a native program-approval doorbell, with bundled/team-signed code admitted under its rules. Every admitted connection is currently owner-level: the implementation literally returns owner from connectionAccess; per-plugin socket credentials are documented as not built. Linux/Windows do not have the same doorbell parity. This is powerful browser automation, not a narrowly scoped agent capability token. docs/control-socket.md; apps/browser/src/state/automation/controlSocket.ts.

Revocation guards check connection and consent generation across awaits, and partial apply results distinguish completed effects from unknown outcomes. However, the documented DevTools token can outlive a program's approval until control/server restart. The rollout still documents file-based token access; no claim of immediate revocation should be made. Socket password listings omit password values, but browser control can still act in authenticated pages. Silent upload/download arms, file-URL navigation and trusted-input methods materially increase the authority of an admitted automation client. Use separate accounts/profiles and explicit action approval outside the browser for consequential tasks.

Ardia plugins are separate from Chrome extensions. On macOS, main JS runs in an offline JavaScriptCore helper under a deny-default Seatbelt profile. Host-mediated net.fetch checks declared hosts, resolves/vets addresses and uses its own TLS connection. Network-enabled sidecars are broader: the sandbox permits outbound IP and local binding/listening, not just the broker's hostname allowlist. Installed plugin programs are explicitly unsandboxed, run as the user and may fully control Ardia when control is enabled. Do not extend the helper's sandbox promise to everything a plugin distributes. packages/shell/ios/PluginCore/PluginSandbox.swift; packages/shell/ios/PluginHostFetch.swift; docs/plugins.md.

Chrome extensions remain privileged browser code under Chromium's permission model; the full uBlock Origin component is not proof that arbitrary extensions are safe. Web Store installation still involves Google infrastructure and extension-update trust. No separate AI plugin repository or provider implementation was audited, so model selection, prompt retention and prompt-injection resistance remain out of scope.

Privacy, egress and credentials

“Google's pings are compiled out” needs qualification. The source disables many Google services and sets safe_browsing_mode=0, sacrificing Chromium URL-reputation protection. Google security-component downloads, Web Store/extension updates and selected search suggestions remain. Search suggestions can send typed text and, on some platforms, the selected engine's profile cookies; private-window exceptions are documented separately. WebKit fraudulent-site warnings are opt-in. engine/patches/build/gn_defines.sh; docs/privacy.md.

There is also a daily anonymous opened-today event sent by production builds regardless of the crash/usage-sharing toggle, with no Settings off switch. The code records version, platform/channel and first/daily/weekly/monthly flags, with a per-event random identifier rather than a permanent device identifier in that daily body. Optional usage/crash reporting and user-submitted reports are different paths; feedback includes install/session IDs and selected attachments. An IP address remains visible to the receiving service even when the payload lacks a persistent ID. apps/browser/src/state/telemetry/daily.ts; apps/browser/src/state/telemetry/transport.ts; docs/privacy.md.

Optional Live Folders contact GitHub, Bitbucket, Notion, Google Drive or a chosen Confluence site using granted tokens. Custom omnibox providers receive suggestion traffic after approval; plugin network requests can leave directly and bypass an HTTP proxy. Encrypted sync does not make these paths local-only. No core always-on LLM egress was established in the inspected desktop paths; installing an AI plugin adds its own provider and data-policy review.

Plugin secrets use per-plugin Keychain account namespaces and permission-gated secret methods rather than ordinary plugin settings JSON. They are still disclosed to the authorized plugin when requested. DevTools endpoint file loading checks owner/private-file properties, no-follow access, size and server identity. These are good containment mechanisms, not protection from malicious code already authorized as the user. apps/browser/src/state/plugins/secrets.ts; apps/browser/src/state/plugins/channelData.ts; packages/shell/ios/ControlPeerCore/DevtoolsEndpoint.swift.

Persistence and recovery

Chromium retains profile browsing data; the app separately retains session/settings documents. Session parsing distinguishes absent, unreadable, malformed and newer-version data, keeps aside copies and gates writes instead of blindly treating errors as a fresh empty session. The macOS document store uses atomic replacement for saves. Tests cover migration replay, session safety and persistence timing. Atomic replacement is not a full backup or a proven power-loss recovery contract across every platform. Importing passwords and logins increases the value of that persistent state. apps/browser/src/state/session/sessionSafety.ts; apps/browser/src/state/session/sessionDocument.ts; packages/shell/ios/DocumentStore.swift.

Update supply chain and licensing

The inspected engine build pins Chromium 158.0.8127.88 and Helium repositories to exact commits. Do not infer the built engine patch level from a newer engine release tag appearing in the repository's release feed. Prebuilt engine downloads are checked against repository-pinned SHA-256 entries; that proves agreement with the trusted manifest, not independent reproducibility. A compromised repository/manifest remains a supply-chain risk. engine/patches/build/helium-pins.ini; packages/ardiacore/scripts/fetch-engine.sh.

The macOS app has a Sparkle feed and public Ed25519 key, and release scripts import signing material and support notarization. Those are stronger signals than an unsigned download URL; no downloaded DMG, notarization ticket, signature chain, rollback behavior or cross-platform updater was dynamically validated. Automatic update checks also gate a remotely fetched kill-switch document. Browser engine security patch cadence is a deployment criterion, not a cosmetic feature. apps/browser/macos/Ardia-macOS/Info.plist; .github/release/signing.sh; docs/privacy.md.

This is a desktop browser, not a server to self-host. The documented macOS source build needs Xcode 26+, CocoaPods, Node 24 and pnpm 12, and may fetch the pinned prebuilt engine. Building Chromium itself is a substantially larger trust/resource commitment. Apple-Silicon macOS is the prominently advertised release; Linux has several packaging formats, while plugin and native-tool parity varies. Some passkey/saved-card functionality depends on the upstream signing team identity, so a fork is not automatically feature-equivalent.

Recommended pilot: use an isolated data directory, do not import valuable credentials initially, leave automation/plugins off until needed, check actual engine/sandbox state and network traffic, and exercise restore/export before migration. If zero vendor telemetry or Chromium Safe Browsing is mandatory, the inspected defaults are not a fit. No installation was performed for this review.

Verdict

The call, and why.

Credible browser engineering, but not a blanket daily-driver or agent-safety recommendation. Daily telemetry has no Settings opt-out, Chromium Safe Browsing is disabled, and admitted automation and plugin programs can hold broad authority. Static review only; pilot without valuable logins.

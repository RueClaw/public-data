Key points

What matters most, in order.

1

Real interventions, not prompt presets

Steering hooks and a separate measurement plane share one generation engine. Manifolds, Jacobian lenses, neurons, heads and SAEs support paired experiments; labels still require independent validation.

2

Strong local boundaries, not tenancy

Loopback/Host/Origin checks, bearer authentication and bounded archives are real implementation controls. One key grants shared session authority, and enabling model repository Python grants local execution privileges.

3

Back up chats; inspect pack exports

Saved chats live in browser IndexedDB, while fitted artifacts and corpora live on disk. Pack publishing includes corpora and defaults new repositories to public; a manifold pack is not a full backup.

Researchers can generate a reply, select tokens, inspect alternative-token probabilities and internal measurements, and fork the conversation with altered steering. Six rooms organize Workbench, Units, Lens, Probes, Artifacts and Model. OpenAI- and Ollama-compatible endpoints are local serving interfaces: their names do not imply forwarding prompts to those companies.

One intervention engine, separate measurement plane

A DrowseSession owns a GenerationEngine. SteeringComposer resolves expressions and installs per-layer SteeringManager hooks; the read plane independently plans hidden-state capture and instrument measurements. Probe-dependent gates connect them. Generation transactions and the server session lock serialize access to the mutable model. OpenAI/Ollama stateless requests do not append to the native conversation tree. This is a consistent research core, not independent implementations behind each UI surface. Architecture, engine, composer, app.

Geometry is more than a named prompt preset

Concepts are fitted from authored or generated corpora. A two-node flat manifold represents a bipolar direction; other fits use affine or curved geometry. Neutral-activation whitening separates write directions from read covectors. Layer selection, ablation, token/layer scopes and probe-triggered gates act inside model forwards, rather than merely prepending an instruction. Fit identity includes authored content, rendered token positions, model identity and policy version; stale results are not silently treated as current. Fit pipeline, geometry, steering.

Rich readouts are hypotheses, not semantic guarantees

R-family lenses rank what a vector tends to make the model say; S-family lenses rank input-like content, with depth-dependent weighting. Units expose neuron/head writes and reads; optional neuron-lens catalogs supply generated labels and firing normalization. SAEs add sparse features. These are implemented mechanisms, but a probe named “deceptive” is not independently calibrated evidence of deception. Corpus construction, neutral baseline, model/dtype, layer choice and intervention strength can change a reading's meaning. Generated unit labels are interpretation aids, not ground truth. Reproduce paired unsteered/steered experiments and held-out behavioral effects before using a score in consequential decisions. Lens, catalog, methods.

Authentication and execution

Good defaults: the CLI binds loopback. Without a key, API access checks the peer and Host; browser Origins must match or be explicitly allowed. Bearer comparison is constant-time. WebSockets authenticate before acceptance using a bearer header or encoded subprotocol, not URL credentials; stale token query parameters are scrubbed. Private responses are no-store. CSP, frame denial, no-referrer and device-permission restrictions are set. Request bodies default to a 64 MiB cap. Security tests cover cross-origin clearing, authentication before body consumption and response headers. Security middleware, tests.

Not tenant isolation: one server owns one shared session/model with one configured API key, not per-user roles or independent stores. Native API access includes conversation and artifact operations. A trusted local process can call a keyless service; browser-origin defenses do not stop local malware. An authenticated collaborator is not a read-only viewer. Use separate processes/stores for mutually untrusted users, and TLS plus deliberate proxy handling for remote access. Body bounds are not GPU quotas or fair scheduling.

Model code remains a major trust boundary: repository Python defaults off; the environment toggle or explicit Python argument enables it. That grants model code the server process's privileges, not a sandbox. Config/tokenizer/weight reads are pinned to one resolved Hub revision, a consistency control but not a publisher signature. Native dependencies and optional acceleration packages still execute code during install/runtime. Loader.

Archive handling is substantive: .drowse imports reject absolute/traversal/noncanonical paths, duplicate and case-colliding names, special files, and oversized/high-ratio archives. Limits include 4,096 entries, 512 MiB per file and 2 GiB expanded total. Tensor validation is separate. CRC and cache fingerprints do not prove author identity; a valid pack is not necessarily trustworthy science or authenticated provenance. Archive codec.

Network and costs

  • Local inference needs no OpenAI/Anthropic subscription or per-token provider payment. Costs are hardware memory, electricity, disk, downloads and fitting time. First default launch downloads weights and fits 17 bundled probes; lens/SAE fitting is additional work. No hardware budget was measured here.
  • Hugging Face serves weights, packs, lenses/catalogs and optional datasets. Gated models may require accepted terms and Hub credentials. Drowse delegates Hub authentication to the client library; this is not an isolated credential broker.
  • The dashboard API key is held in a module variable rather than written to browser storage by the HTTP-auth module. This does not protect against trusted-origin script compromise or an unencrypted remote connection. HTTP auth
  • Optional Neuronpedia detail retrieval sends model/source/feature identifiers to Neuronpedia. External catalog links leave the local origin. The contact form explicitly POSTs entered fields to drowse.ai and retains drafts in sessionStorage; server-side contact retention is outside scope. “Local” does not mean “no network anywhere.” SAE descriptions, contact
  • Pack publishing can disclose corpora. Push always exports the corpus, filters fitted tensors, and defaults new repositories to public unless private is requested. It removes stale root pack/artifact layout in the target Hub repository. Use a dedicated destination, inspect exports and dry-run before publication; excluding tensors does not exclude training text. Persistence and recovery

The filesystem store holds authored manifolds/corpora, templates, fits, neutral statistics, lenses, SAEs and source bindings. It is not a conversation database. The live server does hold the native tree in memory: “keeps no conversations” means no automatic durable server chat storage, not that requests never enter memory. The browser saves chats between replies in IndexedDB; preferences/drafts use browser storage. No application-level encrypted-at-rest chat vault or centrally managed retention policy was established. Treat browser profiles, downloads, corpora and backups as sensitive. Conversation library, state documentation.

Chat backups contain a versioned record plus SHA-256, validate before import and enforce size limits; archives can carry multiple chats. Hashes detect accidental changes, not malicious rewriting by someone who can recompute them. Explicit deletion exists, but no universal time-based purge was found in reviewed chat/store paths. Browser clearing, quota errors, origin changes or an unsaved in-flight reply can affect recovery. Export before clearing data or upgrading. Python users explicitly choose a LoomTree save path. Chat backup.

Artifact writes use same-directory staging, fsync/replace and stable cross-process locks. Fits publish only if the authoring revision still matches; incomplete tensor/sidecar pairs are cache misses. These are strong crash/concurrent-edit measures, not a substitute for backing up authored corpora. A .drowse pack transports one manifold closure and referenced template, not model weights, lenses, SAEs or the full home directory. GGUF control-vector export is narrower still. Atomic IO, fit publication.

Migration is an operational cost: README documents no general automatic old-format migration, no reading the old Saklas home, a pre-5.4 lens conversion script, incompatibility with 5.x saved conversations in 6.0, and refitting changed frames in 6.1. Current backup code recognizes some legacy names/versioned records; that is not blanket historical compatibility. Keep pre-upgrade exports and the original environment until restore is proven.

Python 3.11+ is required. CUDA or Apple Silicon MPS is recommended; CPU support is not a promise of interactive large-model performance. Quantization is CUDA-specific and ignored with a warning elsewhere. FlashAttention auto-selects when installed. A model fitting in RAM does not assure that retained activations, KV cache and analysis fits fit too. UI builds require Node 24, but the packaged server already includes the built UI.

Support is feature-dependent: README lists exercised model families but says lens fits/unit reads refuse MoE and hybrid stacks, role extraction needs a suitable chat template, and published lenses/SAEs cover selected checkpoints. MPS fallbacks and text-only extraction from some multimodal checkpoints are real code, not universal compatibility. Windows is declared OS-independent and has lock handling; this review did not establish Windows GPU/packaging parity.

Python dependencies mostly use lower bounds, not a full environment lock. Frontend dependencies are pinned with a package-lock, including a tagged GitHub tarball for Ledger. Use a version-pinned isolated environment, retain dependency resolution records and qualify a small checkpoint before investing in large fits. No installer, updater or migration was run.

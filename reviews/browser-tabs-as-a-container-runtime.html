Key points

What matters most, in order.

1

No hypervisor does not mean no host authority

The kernel runs as Wasm; arm64 programs remain emulated. A native supervisor bridges files, TCP, DNS and terminals, so the browser sandbox is only one boundary.

2

A tab is also the failure domain

Root writes use tmpfs; persistence requires explicit volumes. Page loss ends the container, and checkpointing is missing. Reusing a personal browser weakens the dedicated-profile model.

3

Fast small starts, slower real work

The author reports roughly 0.87 s for a small Alpine command and about 540 MiB idle host memory. His comparison shows 11–36× workload slowdowns; these are not independently reproduced results.

What is actually supported?

The README distinguishes Docker runtime integration from standalone image pulls and tocker’s minimal daemon plus real Docker client. The design explicitly excludes UDP, CPU throttling, checkpoints, x86-64 guest images and building images without Docker.

Benchmark scope

The startup figure totals 867 ms: browser 503, boot/mount 84, echo/exit 256, other 24. It is not a cold image-download benchmark. The workload figure reports find 36× slower, Python arithmetic 31×, JSON import/parse 28×, gzip 14× and SHA-256 11×. Near-native kernel execution is not near-native application throughput.

Raw samples and a fully pinned benchmark environment were not provided in the article. Test definitions cover basic runtime and exec behavior; their presence is not a verified passing run or complete Compose/macOS compatibility.

Separate boundaries

Dedicated Chromium profiles keep the sandbox enabled by default and drop browser identity when the supervisor is root. The supervisor retains its own authority. Existing-browser and dashboard modes are not the same process/profile isolation.

Capabilities and egress

The loopback server uses a random 16-byte URL token. Protect it as bearer authority. COOP/COEP enable shared memory, not tenant authentication. The TCP bridge dials from the supervisor’s network context; host mounts explicitly expose filesystem capabilities. Local port binding is not an outbound firewall.

Storage and failure

Guest init adds a tmpfs writable root; live volumes carry persistent data. The supervisor treats page loss as failure. Unkernel’s own disk/snapshot features are not automatically present in this integration; see the related Unkernel review.

Evidence limits and reuse

No installs, browser demos, service probes, source execution or benchmarks were performed. Article license was not established; the review summarizes rather than copies assets. The tabc wrapper is MIT, while its kernel and other components retain their own license terms.

Verdict

The call, and why.

⚠️ Interesting but verify

Worth studying for trusted interactive Linux workloads and runtime design. Not a drop-in Docker replacement or a proven hostile-code boundary: native host bridges, ephemeral roots and emulated arm64 applications define the real tradeoffs. Static review only; no runtime tests or benchmarks.

What It Is

Reel wraps gpu-screen-recorder in an Omarchy Quattro shell widget, with a Rust CLI usable independently. It selects a monitor, region or a window's visible rectangle; supports pause/resume, audio, webcam overlay, manual zoom and local history. Window capture is explicitly not isolated application capture: overlap and movement can expose other windows. Desktop audio and cursor capture default on; microphone, webcam and auto zoom default off. README, manifest.

Automatic zoom is local deterministic processing, not AI: pointer clicks become camera blocks; low-resolution frame differences help retarget quiet clicks toward changing content. No LLM provider, account, API key, model download or paid inference is involved. Compute, disk capacity and encoding time are the operating costs; performance was not measured. activity.rs, project.rs.

Key Features and Architecture

1. Separated UI and engine. QML launches argument-array CLI commands. The service watches state, refreshes history and polls every three seconds while busy to notice dead workers. Rust separates recording, targeting, telemetry, camera planning, rendering, finalization and quarantine recovery. This is real implementation, not a UI-only demo. Service.qml, main.rs. 2. Two recording stages. A raw capture is hidden from ordinary history until the save pass trims/normalizes/processes it. New recordings are gated while saving. State reconciliation detects exited recorder/finalizer PIDs; a durable quarantine ledger preserves problematic captures rather than presenting unfinished footage as completed. This is useful recovery design, not a guarantee against power loss or corrupted media. recorder.rs, finalize.rs, state.rs, quarantine.rs. 3. Editable camera projects. Takes with telemetry get a hidden project JSON and raw JSONL, even when auto zoom is disabled. Keyframes are normalized/clamped and rendered through FFmpeg; dense paths use generated sendcmd scripts. Re-rendering normally writes a separate rendered video. The original recorded cursor remains baked into the pixels; this is not a fully separated cursor/video editing system. project.rs, render.rs. 4. Practical history. Thumbnails can be rebuilt; files can open in mpv or Omacut, be renamed with companion data, copied by path, dragged out or shared. Rename validates names and recording-folder containment; companion moves are best-effort, not a transactional archive operation. commands.rs, Panel.qml.

Security, Permissions and Privacy

Desktop authority, not a sandbox

This runs as the logged-in desktop user, launching tools from PATH and controlling the compositor, capture, audio and camera. There is no web server, multi-user authentication layer or CORS surface in the inspected design. Local state and a Unix recorder socket replace HTTP APIs. Treat the plugin, native binary and all helper executables as trusted desktop code—not as an untrusted-document viewer.

Pointer telemetry opens Linux input devices and filters for pointer capabilities; persisted events contain timed coordinates/buttons and capture metadata, not a general typed-text log. The recommended membership in the input group nonetheless grants broader raw-input access to processes running as that user, not a narrow Reel-only permission. Avoid granting that capability casually. A denied input device degrades telemetry/auto zoom rather than blocking ordinary recording. telemetry.rs, event schema.

Capture rectangles, previews, window labels, audio and screen pixels can reveal sensitive material. Runtime, thumbnail and sidecar directories are set owner-only, and persisted telemetry is chmod 0600, but several permission-setting errors are ignored. These are best-effort local protections, not encryption; normal videos are not shown to have the same enforced mode. paths.rs, sidecar directory, telemetry persistence.

Confirmed static retention mismatch

Documentation says project and telemetry files are removed when a take is trashed. However, main dispatches Trash directly to commands::trash, which removes/trashes the video and removes three preview locations only. Neither the successful-video nor missing-video branch deletes the hidden project or telemetry. The panel delegates to that CLI and adds no sidecar cleanup. At this revision, deleting a take through Reel can leave interaction traces and project metadata on disk. This is established by source-path inspection, not a runtime reproduction. docs claim, dispatch, complete trash function.

The same function falls back from gio trash to fs::remove_file whenever gio is absent or unsuccessful. Therefore the UI promise to move a file to trash is not a recovery guarantee. There is no fallback confirmation distinguishing permanent deletion. Recommend failing closed or explicitly asking before permanent removal, and deleting/retaining companion artifacts under one clear policy.

Network, credentials and updates

The shell checks at startup and hourly; the engine fetches the installed git origin's HEAD with a timeout and caches results for an hour. It reads the fetched manifest without executing it during the check. This reveals routine Git connection metadata to the configured origin; it is not a video upload. Git can inherit local credential helpers/SSH context even though terminal prompting is disabled. No application credential store was found. “Only network access” should be read narrowly: user-triggered sharing delegates to LocalSend through omarchy share, and actual updating also contacts the remote. update code, share action.

Updating executes omarchy plugin update followed by bash on the newly fetched installer; this is an explicit upstream-code trust boundary. The installer restarts the shell, and active recording/saving is refused. Release hashes and CI byte-comparison improve integrity diagnostics but do not substitute for independent signatures or trust in the upstream account. The shipped native engine is not independently rebuilt in this review.

Project imports are trusted local inputs

Project loading validates schema version and camera geometry, but accepts absolute take paths and normalized relative paths outside the project folder. It is not a confined importer. The render CLI's original-file protection compares paths lexically; equivalent paths using symlinked parent directories are not canonicalized before the final rename. Existing rendered outputs can be replaced. Treat third-party project JSON and explicit output paths as trusted instructions to read/write local media; review paths and back up inputs. This is a static robustness concern, not a demonstrated remote exploit. project path resolution, render guards/output publication.

Data Handling, Export and Recovery

Default videos live in the user's XDG Videos/Reel folder. Companion data lives in a hidden .reel directory beside takes; durable previews live in the user's .reel/previews directory. Runtime logs/state and the persistent quarantine ledger occupy separate XDG locations. There is no inspected timed-retention policy, encrypted archive, automatic backup or cloud synchronization. Uninstall intentionally preserves recordings, settings and state. Include companions when backing up editable projects, and deliberately audit them when deleting sensitive footage. paths.rs, uninstaller.

Export is ordinary MP4/MKV plus editable JSON, not a proprietary hosted format. Re-rendering re-encodes video to H.264 and audio to AAC; it can retry without audio after failure, so check the resulting file rather than assuming every successful render retained sound. Recovery preserves failed raw captures, but hidden/quarantined footage may still contain the countdown/overlay content intentionally withheld from history. render.rs, state.rs.

Installation and Operating Fit

This is a Linux/Omarchy Quattro/Hyprland integration, not a generic cross-platform recorder. The supplied binary is Linux x86_64; other architectures require a Rust source build. Capture needs gpu-screen-recorder and FFmpeg/ffprobe, with Omarchy's picker, slurp, grim and mpv supporting the advertised workflow. Installer checks classify some advertised workflow tools as optional, so a successful install alone does not prove every feature works. GPU/driver/compositor compatibility needs a real, separate desktop trial.

The installer links the command, enables the plugin, optionally backs up/merges a marked Hyprland bindings block, and restarts the shell. Service startup also invokes configure automatically. The wrapper can prefer a sibling development native binary over the committed dist binary. Review what executable will run; do not treat enabling the plugin as a passive manifest import. install.sh, configure, wrapper.

Recommended Next Steps

Before routine use: fix sidecar cleanup and the permanent-delete fallback; canonicalize/protect render destinations; then test non-sensitive captures across pause, crash, low disk space, window overlap, audio failures and updates on supported hardware. Keep input-device permissions optional and narrow where possible. The code is worth studying, especially the two-phase capture/quarantine pattern, but the privacy cleanup gap prevents an unconditional deploy recommendation.

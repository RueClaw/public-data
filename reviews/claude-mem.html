Key points

What matters most, in order.

1

Useful progressive recall

Hooks capture activity, a second model distills it, and later sessions receive an index before fetching details. Memory is generated interpretation, not guaranteed factual replay.

2

Capture defaults need attention

Secret redaction is off; screenshot capture and telemetry are on. Raw tool receipts persist indefinitely by default. Local storage does not mean local inference.

3

Strong observer lockdown, weaker worker trust

Observer tools, MCP and inherited settings are disabled. The worker instead trusts loopback; a broad bind without a TV token warns rather than refusing startup.

1. Capture before summarization. Session routes initialize and strip user prompts; shared ingestion applies tool skips, project/privacy decisions, media handling and tag stripping before serializing tool I/O. It dual-writes a durable tool-use receipt alongside queued observer work. Receipt failure is logged while the observation can still queue, so this is not an atomic, lossless audit ledger. Entirely private stored prompts suppress observation/summary creation; a *missing* prompt row explicitly allows ingestion to avoid freezing sessions after startup races. src/services/worker/http/shared.ts, src/services/worker/http/routes/SessionRoutes.ts, src/services/worker/validation/PrivacyCheckValidator.ts.
2. Model-derived memory. Prompts render bounded tool parameters/outcomes into an observation schema; the model can emit observations or a noise skip. ClaudeProvider manages streamed/resumed observer sessions and end summaries. Compression and truncation reduce payloads but can discard a crucial qualification or error. Record IDs establish provenance to stored records, not proof that a generated claim is true. src/sdk/prompts.ts, src/services/worker/ClaudeProvider.ts.
3. Progressive retrieval rather than full replay. Search returns a small index, timeline supplies surrounding work, and get_observations expands chosen IDs. Filter-only retrieval uses SQLite; text queries use Chroma when configured, supplement empty categories with SQLite, and use SQLite when Chroma is disabled. Chroma errors are explicit, not universally silent fallbacks. File-oriented hybrid search first finds SQL metadata matches and then ranks/hydrates within that scope. src/services/worker/search/SearchOrchestrator.ts, src/services/worker/search/strategies/HybridSearchStrategy.ts.
4. Bounded injection. ContextBuilder assembles session-start context. ContextBudget measures characters and drops full narratives, last summary/message, then timeline entries to meet the hook delivery budget; it can still report overBudget when nothing droppable remains. It is not an exact tokenizer or guarantee of perfect context selection. Cross-harness startup context is opt-in. src/services/context/ContextBuilder.ts, src/services/context/ContextBudget.ts.
5. Not merely passive memory. The file-read gate can deny a whole-file Read for qualifying large files with observations and redirect the agent toward targeted reading/smart navigation. This changes the working agent's behavior, so test editing and debugging workflows as well as search. tests/evals/read-gate/README.md.

Retrieval quality and cost

The README's roughly 50–100 token index entries versus 500–1,000 token full records explains a plausible roughly 10x *result-payload* reduction when most details are never fetched. It does not demonstrate 10x total task savings, preserved recall, or improved correctness. Observer generation, repeated context, tool-schema overhead, misses and extra search turns all count. Moving observer traffic off a subscription plan reallocates billing; it is not free computation or a universal doubling of useful work.

There is real evaluation machinery: the file-read-gate suite compares ON/OFF arms with seeded memories and deterministic graders. Its documentation reports large-file savings of 35% on Sonnet and 32% on Opus, while an earlier small-file experiment increased Opus cost by 20%; the threshold was adjusted accordingly. Those are upstream reports, not reproduced results. The harness disables observer capture and Chroma to isolate the gate, so it does not establish full-pipeline memory economics or semantic retrieval quality. No broad, independently verified recall/precision, stale-fact correction or longitudinal task-success result was established here. tests/evals/read-gate/README.md.

Privacy and Network Data Flows

Local storage is not local inference. Claude observer requests use Claude credentials/subscription or API settings; Gemini sends content to Google's generativelanguage API; OpenRouter routes to its endpoint and downstream model provider, with configurable endpoint overrides including the cmem gateway. OpenAI-compatible and Codex providers add more deployment choices. A local endpoint may reduce remote generation egress, but must be selected and verified; it does not automatically disable telemetry or sync. src/services/worker/GeminiProvider.ts, src/services/worker/OpenRouterProvider.ts, src/services/worker/OpenAICompatibleProvider.ts.

Cloud Sync is opt-in and separate from observer inference. TeamBrain, Notion export and optional notification integrations are additional intentional disclosures, not implied by choosing local SQLite. Provider retention, training use and hosted deletion guarantees were not independently verified. A confidential project should be excluded before capture, not merely kept out of startup context.

Defaults matter: secret-pattern redaction false; generic credential matching separately false; media capture true; media inference false; excluded-project list empty; raw tool-use retention zero (forever); daily log retention 30 days; automatic SQLite backups false. These values are directly in src/shared/SettingsDefaultsManager.ts.

Balanced lowercase private-tag blocks are removed, including nested blocks; unclosed private tags intentionally remain ordinary text. This is a specific capture transformation, not a promise to erase the host agent's original transcript or prior provider requests. Regex secret redaction, when enabled, has broad vendor patterns, custom rules and a one-million-character fail-closed marker; it does not detect all confidential source, personal information, screenshots or arbitrary credentials. Generic patterns remain opt-in and documented coverage gaps exist. Folder-Markdown exclusion controls generated context files, not all capture. src/utils/tag-stripping.ts, src/utils/redaction.ts, docs/public/usage/auto-redaction.mdx.

Telemetry consent defaults on and includes separately scrubbed error capture unless disabled. DO_NOT_TRACK and explicit telemetry controls are honored; error telemetry has its own kill switch under the general consent gate. This is more careful than indiscriminate payload logging, but “anonymous analytics” still means outbound events and identifiers, not no-network operation. src/services/telemetry/consent.ts, src/services/telemetry/telemetry.ts.

Credential, HTTP and Prompt-Injection Boundaries

Strong observer tool restrictions. buildHardenedSdkOptions sets tools and allowedTools empty, an explicit deny list, dontAsk permission mode, a deny-and-audit canUseTool callback, no MCP servers or inherited settings, strict MCP configuration and a separate observer directory. This is materially stronger than telling a model not to execute tools. The source also documents a previous argv-normalization failure and regression coverage for forwarding the empty tools flag. A separate working directory is not an OS sandbox. src/sdk/hardened-options.ts, tests/security/observer-tool-enforcement.test.ts.

EnvManager isolates selected provider credentials and writes its credential file with restrictive permissions (0600; data directory creation 0700). Those are filesystem protections, not encrypted secret storage. The consuming agent and installed hook code still run with their user's local authority. src/shared/EnvManager.ts.

Worker and server are different security products. Worker defaults to 127.0.0.1, uses Host/DNS-rebinding and Origin checks, refuses framing except TV, and blocks foreign-page DELETEs. It does not generally authenticate local API callers; CORS admits other localhost ports for reads. Local untrusted programs/pages remain relevant attackers. Opening its bind without a TV token only produces a warning, explicitly noting full API/provider-key exposure through settings. Do not publish this worker behind a bare port forward or assume CORS authenticates non-browser clients. With a TV token, a separate guard restricts remote clients to four read-only paths; this is a broadcast token, not per-user authorization. src/services/worker/http/middleware.ts, src/services/worker/http/origin-policy.ts, src/services/worker-service.ts.

The separate server middleware defaults to API-key authentication and scope verification. Local-dev bypass requires explicit settings, loopback peer/Host and no forwarding headers. That is useful hardening, but this review did not test tenant isolation across every server route; redaction configuration is currently worker-local rather than tenant-scoped. src/server/middleware/auth.ts.

Persistent prompt injection remains possible in principle. Source files, tool output and imported memories are untrusted material. Stripping selected wrapper tags and disabling observer tools do not validate the semantic truth or safety of a stored instruction. A poisoned observation can later influence a fully capable coding agent. Treat retrieved text as cited historical evidence, not standing policy; independently verify commands and changed facts. No adversarial end-to-end injection test was run, and no exploit is claimed.

Retention, Deletion and Portability

SQLite is the authoritative record store, with separately retained logs, media, vector data and optional backups/sync copies. Default indefinite tool receipts mean storage contains more than compressed observations. Retention of linked tool-use rows is configurable, but is not a universal expiry policy for every memory and derivative.

Deletion is more deliberate than a simple SQL DELETE: synced rows require an available sync identity; acknowledged rows refuse an unreplicated delete when sync is unavailable. Cloud deletions queue tombstones; context is invalidated after commit. Chroma cleanup runs asynchronously on a best-effort basis and logs failures. This is sensible convergence engineering, not verified physical erasure from vector storage, backups, provider systems or already injected contexts. Single-observation deletion is not equivalent to removing its whole source session. src/services/worker/http/routes/DataRoutes.ts.

Optional backups use verified VACUUM INTO snapshots and rename completed files, avoiding an unsafe live database-file copy; default retention is seven snapshots when enabled. A database snapshot is not a full portable backup of media, credentials and all external state. The export script emits query-selected observations, summaries, prompts and parent-session metadata; it is not an exhaustive machine backup or guaranteed raw receipt/media archive. Import validates record shapes. Test restore and export/import round trips before relying on them. src/services/backup/BackupManager.ts, scripts/export-memories.ts.

Installation, License and Maturity

The installer edits host integrations, adds a launcher, provisions runtime dependencies and starts services; README says Bun and uv can be installed automatically. Interactive setup can route through hosted sign-in and an observer trial requiring a payment method, while explicit provider/offline choices skip account interaction. Update/upgrade invokes the installation flow again, rather than being a content-only refresh. Inspect its proposed changes and pin versions for controlled deployments. No installer or marketplace plugin was run in this review. src/npx-cli/index.ts, src/npx-cli/commands/install.ts.

Root LICENSE is Apache-2.0 and NOTICE attributes Alex Newman; this is the license of the reviewed revision, not an assertion about every historical release or hosted service. Start with a disposable, non-sensitive project and one supported harness. Before live capture, decide provider egress, telemetry/error reporting, screenshots, exclusions, redaction and retention. Keep the worker loopback-only; use the authenticated server design for actual remote multi-user needs, not a permissive worker bind. Protect its data directory and backups as sensitive data. Test one capture → observation → restart → retrieval cycle, excluded content, deletion with sync offline, restore, and an intentionally wrong/stale memory. Compare no-memory and memory runs on the same tasks including observer spend and failures.

Bottom line: the architecture is useful and visibly hardened in several important places, but automatic memory creates a durable new data and instruction surface. Its current defaults prioritize frictionless capture over strict minimization. A measured, configured pilot is justified; an unqualified install recommendation is not.

Verdict

The call, and why.

⚠️ Interesting

Pilot on non-sensitive projects, not a privacy-safe default. Progressive retrieval and hard observer tool restrictions are strong ideas, but capture defaults, provider egress, loopback trust and unproven whole-pipeline economics need explicit qualification.

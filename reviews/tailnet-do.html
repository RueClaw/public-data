Key points

What matters most, in order.

1

Public proxy, private authority

The example accepts an arbitrary URL with no authentication and fetches as the object’s tailnet identity. Status also exposes internal details and potentially an enrollment URL. Network grants do not identify the original HTTP visitor.

2

A shared engine is not tenant isolation

The first object selects the isolate-wide DoH resolver; log sinks receive shared engine logs. Persistent identities are separate, but runtime failures, memory pressure and host hooks are shared.

3

TCP plus DNS, not a general VPN

Other forwarded UDP is dropped. Host sockets face Cloudflare destination restrictions, while 20-second alarms, buffered bodies and incomplete cleanup/cancellation complicate operations and costs.

A real tailnet identity with an application-sized API

JS API and engine setup provide a compact embedding surface. The wrapper memoizes one start promise per object context and exposes raw TCP streams as well as buffered HTTP. MagicDNS resolution is delegated to Tailscale's user dialer. This is narrower and more platform-specific than a complete Tailscale daemon.

Caller identity is available, but policy remains necessary

whois maps the connection address through LocalBackend.WhoIs and returns login/display/node names and tags, or null. This is useful identity context, not automatic application authorization: handlers must reject unknown callers and explicitly decide which users/tags may perform operations. Tagged devices should not be treated as human identities. Network reachability is governed by the node's tailnet policy, not by the public HTTP caller's original identity.

Exit-node forwarding is deliberately incomplete

Host hooks send forwarded TCP through Cloudflare sockets, send UDP port 53 queries to DoH, and drop other forwarded UDP. Applications with TCP fallback may recover from QUIC loss; arbitrary UDP applications do not magically fall back. There is no basis here to promise full VPN/IP-protocol parity.

1. A request or alarm creates/loads the named object and its Tailnet instance.
2. One isolate-wide enginePromise loads Go/Wasm and installs host callbacks. Each object gets its own backend/netstack and persistent state prefix.
3. Tailscale control/relay connectivity carries encrypted overlay traffic; registered local ports dispatch to JS handlers with WhoIs results.
4. Worker RPC fetch/connect originates as the object's node. HTTP crosses a buffered JS/Go boundary; TCP uses adapters.
5. Forwarded exit/subnet TCP goes through cloudflare:sockets; DNS uses the configured DoH endpoint, defaulting to Cloudflare DNS.

The two patches are small and inspectable. That is a good maintenance shape, but they change networking and DNS policy seams and require regression coverage against the exact upstream revision.

Security and trust boundaries

High priority: the example is an unauthenticated private-network proxy

examples/exit-node/src/index.js accepts /tailnet?url=... and passes the URL directly to tailnetFetch. There is no caller authentication, target allowlist, per-user authorization or request budget. Other paths expose node status. If this Worker is publicly reachable and its node is enrolled, an unauthenticated visitor can issue HTTP requests as that node to destinations its tailnet permissions allow. This is a static data-flow finding, not a claim that any live deployment was exploited.

The Go HTTP client uses ordinary redirect behavior without a destination policy (client construction, fetch). Allowlisting only the first URL would therefore be insufficient. Restrict schemes, resolved destinations, ports and redirects; authenticate before touching the object; constrain the node with least-privilege tailnet grants; preferably expose fixed application operations rather than arbitrary URLs. CORS is not authentication and cannot stop direct HTTP clients. The example contains no explicit cross-origin policy either.

Enrollment, status and credentials

Auth keys are read from environment secrets, then passed to the backend; no concrete credentials were found in the inspected source. Without an auth key, the backend initiates interactive login and stores its loginURL in status notifications. The example returns that status publicly. Treat enrollment URLs as sensitive and never expose them or internal node names/addresses/peer counts on an unauthenticated status endpoint. JS status merges notifications and does not explicitly clear a previous loginURL on successful login (status handling).

The state adapter hex-encodes state into object storage. Hex is not encryption; machine/node identity material in that state must be protected through Cloudflare account, binding, backup and operator controls. There is no application-layer key wrapping, rotation runbook, or secure wipe guarantee here. logout delegates to the backend; it is not a complete object teardown or alarm/storage deletion API. All() returns an empty iterator, so state enumeration semantics need compatibility tests rather than assumptions of a complete store implementation.

Objects are separate identities, not isolated tenants inside the library

loadEngine/logSinks is isolate-global. The first node's dohURL initializes the shared engine and later nodes do not get an independent resolver. Every registered onLog sink receives engine log lines, with no node-level routing or deregistration. Go's DNS/UDP hooks are global too. Separate storage prefixes do not isolate resolver selection, logs, runtime crashes, memory pressure or CPU consumption. Do not place mutually untrusted tenant configurations/callbacks into one shared Worker isolate on the assumption that this library provides a security boundary.

DNS and relay privacy require explicit decisions

Traffic crosses Tailscale control/DERP infrastructure and Cloudflare's runtime; DNS queries leave to the configured DoH provider. The overlay encryption ends at the object: Cloudflare-hosted application code sees endpoint plaintext, and forwarded plaintext application protocols remain plaintext on egress unless the application uses TLS. DERP mediation is not a guarantee of direct-peer performance or traffic anonymity.

Patch 0002 preserves upstream source admission but replaces HandlePeerDNSQuery with a callback that does not receive the nameAllowed filter or caller address. The pinned upstream peer API distinguishes source admission from query-name filtering. The override therefore skips that resolver-level filter when one would apply; this is not evidence that all Tailscale ACLs are bypassed. Verify intended DNS policy and split-horizon behavior before use. The forwarded UDP DNS path also sends port-53 traffic to its chosen DoH provider rather than respecting the original DNS destination.

Persistence, concurrency and recovery

- Identity survives object recreation: state is written through synchronous SQLite KV with an explicit prefix. This does not persist open sockets, JS handler state or active HTTP requests.
- Keepalive has a cost and is not an uptime guarantee: default alarms reschedule every 20 seconds, about 4,320 invocations/day or 129,600 per 30 days per object. Deployments, crashes and eviction still require recovery.
- Shared engine failure is sticky: start promises per object can be retried, but the global enginePromise is not reset on load failure; go.run failures are logged without a recovery protocol. There is no public node dispose/engine restart path.
- Unbounded HTTP bodies: request/response conversion buffers bodies in JS and Go. The inbound server uses io.ReadAll without an explicit application byte cap or server timeouts; response reads are also unbounded. The outbound fetch has a 60-second context, but cancellation from the caller's Request signal is not carried across the bridge.
- Timeout semantics are incomplete: hostDial/hostDoH accept a Go context but do not wire cancellation to the JS socket/fetch; jsConn deadline setters are no-ops. A five-second Go DNS context does not itself abort the JS DoH request.
- Resource cleanup deserves tests: exported connection js.Func callbacks are not released when closed; unlisten deletes the port map entry without closing the HTTP server/listener it created. Socket.closed resolves on explicit finish/error/cancel, not normal readable EOF alone. Repeated connections or listener replacement may retain resources.
- Limited validation: listener ports are cast to uint16, with no public range validation. Routes are parsed and rejected on invalid prefixes. Listener maps and read/write paths use mutexes, but no stress, object-restart or multi-node-isolate tests are included.

Evidence: socket and HTTP adapters, alarms and API, Go connections, listeners/HTTP. These are static hazards and contract gaps, not measured leak rates or crash reproductions.

This is Cloudflare-hosted code, not generic VPS self-hosting. Prerequisites are a compatible Workers/Durable Objects account, SQLite-backed object binding/migration, Wrangler, a matching Go toolchain and compiled Wasm, plus an authorized Tailscale tailnet or compatible control plane. The README mentions custom controlURL/Headscale; compatibility was not tested. Exit routes must be approved and client/policy configuration must permit their use; advertising routes is not equivalent to approving them.

A subnet-router advertisement does not create physical access to a private LAN. Forwarded sockets originate at Cloudflare. Its TCP documentation lists disallowed destinations including private IPs, localhost and Cloudflare IPs, as well as port-25 restrictions. Ordinary tailnet dialing uses the overlay instead, but this does not make arbitrary private subnets directly reachable through the host-forwarding hook. Cloudflare placement hints are preferences, not a contractual country-specific egress guarantee; the example does not set a hint.

Cloudflare's Durable Objects pricing at review time offers SQLite objects on Free and Paid plans. Free includes 100,000 requests/day and 13,000 GB-s/day; excess free usage fails rather than silently granting paid capacity. Paid includes 1 million requests/month and 400,000 GB-s/month, with excess rates listed as $0.15/million requests and $12.50/million GB-s, subject to documented billing rounding. Storage and the Workers plan are separate considerations. Persistent outbound sockets/active objects can accrue duration charges; frequent alarms undermine a simplistic “serverless means idle is free” assumption. Tailscale plan/usage terms also apply. No deployment cost or performance was measured, and no paid services were invoked.

Install/update behavior

The build scripts initialize the pinned submodule, apply local patches, build js/wasm with many feature-omission tags, and replace wasm_exec.js with the matching Go runtime helper. Wasm is not committed. There is no install-time lifecycle script, auto-updater, release binary verification flow or CI build provenance in this checkout. Building can download the Go toolchain/dependencies and submodule; none was run for this review. Wrangler deployment creates/updates cloud resources and the example enables observability. Pin and audit tooling, preserve identity storage/migrations, canary upgrades and test rollback. Client-update and several security/operational features (including tailnet-lock, SSH and logtail) are omitted by build tags; this is not full daemon feature parity.

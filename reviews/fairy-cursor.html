Key points

What matters most, in order.

1

Screenshot takeover changes the safety baseline

The app redirects system screenshots and purges its private capture folder. Retention defaults off; restore memory is bounded and volatile. A crash can leave redirection active, and next activation purges intervening files.

2

Desktop permissions and local data deserve care

Accessibility, Screen Recording and Finder/browser Automation enable the workflow. Notes save window titles and full URLs; terminal pastes persist image files. The app’s local-only claim is not a traffic audit, and the separate website has analytics and feedback submission.

3

Good policy tests are not integration proof

11 XCTest files contain 165 test-named functions, but none were run here and no tracked CI workflows were found. Clipboard reads are not durable delivery receipts. Source dependencies are not locked, and release signing was not independently checked.

Carry and deliver

Double-click routes screenshots into Finder, text fields, terminals and recognized canvases. Clipboard restoration and copy-on-select handling are explicit, but acceptance often means only that some process read the pasteboard.

Contextual notes

Atomic Markdown writes, 400 ms debounce and Trash deletion are useful. Open notes prefer in-memory state over external edits; metadata can include sensitive URLs and document titles.

Recording

60 Hz output-clock design, zoom, ink and a near-3840-pixel longest-dimension cap. Audio is off; actual performance was not measured. Cursor enlargement uses private SkyLight APIs.

FairyCore holds pure policies; FairyKit defines the host contract; screenshot, notes and recording capabilities compile into one process. This is modularity, not permission isolation.

Recovery

Orderly deactivation restores screenshot settings and waits up to three seconds for recording finalization. A crash bypasses cleanup; released cards are not serialized. Legacy note migration can mark completion despite suppressed write errors.

Verdict

The call, and why.

⚠️ Interesting

Thoughtful interaction engineering, but not a dependable capture archive by default. Pilot with non-sensitive captures: screenshot takeover can lose data across crashes, paste acceptance is heuristic, and distributed binaries were not verified.

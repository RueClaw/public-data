Key points

What matters most, in order.

1

Real control, no jailbreak

AirPlay supplies pixels; Bluetooth HID supplies taps and typing. The tested setup is one iPhone 17 Pro on iOS 26 with Arch/Hyprland and NVIDIA, not a broad compatibility matrix.

2

Consent is not a security boundary

Unlock asks the owner, but passcodes remain same-user-readable plaintext. Takeover fails open if its local service disappears; send/buy/delete approvals are instructions, not transaction gates.

3

Inspect every transport

The loopback WebSocket lacks origin/token validation. Bridge reports have HMAC integrity but no encryption; the companion API binds to the LAN with signed requests but no TLS.

phoneuse lets a Linux desktop view and manipulate an unmodified iPhone using ordinary Screen Mirroring and AssistiveTouch. It is not Android ADB automation, an iOS accessibility-tree reader, an iMessage database client, or a standalone reasoning agent. CLI and stdio MCP tools provide screen capture, OCR, coordinate/label taps, swipes, typing and app navigation to an external agent. Human operators can use GTK and browser mirrors directly. README, MCP

The optional LilyGO ESP32 bridge moves the Bluetooth transmitter next to the phone while the computer sends commands over Wi-Fi. A newly added companion server and protocol support phone-side takeover/unlock approval and APNs Live Activities; this checkout contains no iOS application source or verified app distribution. Do not confuse the optional companion design with a requirement for the core app-free path. Companion implementation, protocol

1. Two independent channels. Screen video arrives through AirPlay; input goes back as keyboard/mouse reports, not through AirPlay. The root daemon exposes a group-writable Unix command socket, used by CLI, browser and desktop input adapters. The bridge can replace direct Bluetooth without presenting two keyboards at once. Daemon, bridge client
2. A restartable frame fan-out. UxPlay feeds a dedicated hub that decodes once and re-encodes with NVENC or x264, retaining the last frame and producing keyframes for new viewers. Viewer restarts need not interrupt AirPlay; hub or receiver restarts still require the owner to restart Screen Mirroring. Bounded browser frame queues drop stale work rather than accumulate latency. Hub, browser
3. Feedback rather than blind sleeps. The frame service detects meaningful visual change and settling while discounting persistent animation. MCP actions default to a three-frame strip at approximately 0.1/0.4/0.8 seconds, plus OCR of the last frame—not the README's blanket claim that every action waits for settling. A settled single image/text view is another mode. Neither proves the intended app transaction succeeded. Frames, MCP
4. Text-first targeting and stale-view detection. Label matching can refuse absent text; visual descriptions fall back to a grounding model that can still return a coordinate when the target is absent. Positional tap guards compare nearby image content, but permit force overrides and fail open on absent/old evidence or read errors. This is an ergonomic safeguard, not an authorization boundary. CLI

Browser mirror: loopback is not enough

The browser server binds to loopback port 8777. Several sensitive HTTP mutations validate an exact localhost Origin, which is worthwhile. However, the WebSocket handler prepares /ws without any Origin or token check, then streams phone frames and accepts input messages. The client-provided “playing” flag and a live mirror are the input gates; there is no browser identity check. A foreign website able to reach that loopback WebSocket could therefore access the screen/control path. Browser local-network protections may constrain reachability, so this is a static missing-control finding, not a reproduced browser exploit. Validate Origin/Host and add a per-session secret before using a real personal phone. web.py, ws / Tab.handle / same_origin

Pairing and privileged host access

The BlueZ agent accepts Just Works pairing. Despite an earlier comment describing a limited pairing window, setup actually calls open_pairing(0), leaving the adapter discoverable/pairable indefinitely. The profile sets RequireAuthentication and RequireAuthorization false, and the architecture permits a new paired device to replace the current connection. This is not evidence that an arbitrary nearby device can directly read the iPhone; it is an unnecessarily broad pairing/device-selection boundary. Use a bounded owner-approved window and explicit device binding. hid_daemon.py, Agent / setup_dbus

The HID command socket is mode 0660, root-owned with the wheel group selected by the installer. Members can send low-level commands outside the CLI's mirror, unlock and takeover checks. The service runs Python as root from the installed repository directory, without sandbox hardening in the supplied unit; a user-writable checkout consequently becomes trusted root-executed code on service restart. Desktop input capture reads Linux input devices; read-only does not mean privacy-free. Restrict both source-tree ownership and device/socket access. Installer, input adapter

Unlock approval is useful, but not isolation

The normal unlock route creates a request ID, waits up to two minutes for the browser/desktop/companion answer, and does not disclose the saved code in normal tool output. Storage is plaintext, protected by mode 0600 and a 0700 directory, not a vault. The unlock helper refuses permissive file modes, detects lock screens through OCR, types once and checks afterward; the three-attempts/hour counter is in process memory and resets on restart. OCR/English lock-screen heuristics can be wrong. unlock.py, UnlockRequests

The helper function itself is not a separate authorization service; approval lives in its caller. A same-user shell agent can read the stored code, spoof Origin headers, or use the underlying daemon if granted access. Thus “the agent never sees the passcode” describes the intended tool flow, not a guarantee against a compromised same-user agent. Prefer manual unlock and do not grant a phone agent unrestricted shell access.

Bridge: integrity is not confidentiality

BLE provisioning uses X25519, a displayed comparison code and AES-GCM for Wi-Fi credentials. UDP control on port 47700 uses HMAC-SHA256 truncated to eight bytes, sessions and increasing sequence numbers. Cached replies suppress duplicate report execution after a lost reply; four sessions support concurrent clients. These are substantive reliability/authentication mechanisms. Bridge protocol, firmware link

Ordinary HID REPORT/KEYS payloads are authenticated but not encrypted. A party able to observe LAN packets can infer typed characters—including a saved passcode when entered through the bridge—from keyboard reports. Wi-Fi credential sealing does not protect those keystrokes. Discovery is unsigned, and firmware persists the control key/network settings in NVS without flash-encryption or secure-boot settings evident in the supplied defaults. Treat the network and physical bridge as trusted; encrypt all control traffic before credential-bearing use. link.c, settings.c, defaults

Companion listener and outbound data

The browser process attempts to start the companion API on all IPv4 interfaces, TCP 8778, even though the companion app is optional. It advertises through Avahi. Authentication uses a one-use, ten-minute pairing link with a 32-byte key; signed requests include method/path/body hash, timestamp and nonce, with replay tracking. Passcode/Wi-Fi fields are AES-GCM sealed. This is stronger than an unauthenticated LAN API, but ordinary requests/responses use HTTP, not TLS, and state/action labels are not confidential. Nonce history is in memory; restart loses it. Pairing URLs are bearer secrets and need private handling. No app implementation was available to verify Keychain storage or phone-side approval behavior. companion.py

Core mirroring and local OCR need no cloud model API. Nevertheless, MCP returns images and OCR text to the external agent, so that harness may transmit private messages, notifications, photos and account information to its model provider and retain them in transcripts. There is no task-specific screen redaction or iOS accessibility-tree permission scope: this is pixel access to whatever is visible. Screenshots and diagnostic input/video/Bluetooth captures are sensitive artifacts; some temporary screenshots are removed, but explicit captures and traces persist and error paths are not a complete retention policy. Runtime paths fall back to a shared temporary directory when XDG_RUNTIME_DIR is absent. MCP, CLI, telemetry

If APNs is configured, action text, session state/counts and unlock notifications leave for Apple's push service using an operator-supplied signing key. Local vision still consumes RAM/GPU, disk and model-download bandwidth. External agent inference has its own image/token charges or subscription limits; no end-to-end spend cap is implemented here. Upstream image-token/latency figures are observations or estimates, not verified pricing or performance guarantees. APNs, companion activity loop

Prompt injection and consequential actions

MCP instructions and the shipped skill tell the agent to ask before sending, posting, buying, deleting, modifying accounts/security or approving permissions. These are good instructions, not enforced transaction gates. Generic tap/type/Enter tools can perform all those operations; there is no recipient/amount binding, purchase confirmation receipt, app allowlist or screen-content trust classifier. Malicious text in a web page, message or screenshot can enter the same model context as legitimate observations. Keep that content untrusted, require a human approval immediately before the final consequential action, and verify the actual destination and outcome. MCP instructions, skill rules

Reliability, Recovery and Concurrency

The implementation has real engineering beyond a gesture demo: Bluetooth reconnection and calibration, skippable hover backpressure, bridge acknowledgement/deduplication, key release on browser disconnect, fresh keyframes, frame settling and automatic child-process restart. The author reports roughly 100 ms visual response and slower bridge report delivery; this review did not reproduce those measurements. Architecture, bridge measurements

Takeover pauses normal CLI/MCP actions through a browser-service check, but that check continues on connection errors and non-409 HTTP failures. Browser restart also loses its in-memory pause state. Low-level HID clients bypass it entirely. A 20-second activity timeout is a UI indicator, not an exclusive per-agent lease. Shared last-view/action files, multiple socket clients and simultaneous physical-phone use can interleave; report-level locks do not make a multi-step gesture or purchase atomic. Run one controller at a time. cli.agent_turn, web agent state, daemon command threads

Automatic reconnect cannot establish whether an app already sent a message before a failure. Do not retry a consequential action merely because its screenshot/acknowledgement failed. Re-observe and reconcile first. Auto-correct, US keyboard layout, notification overlays, iOS updates, stale coordinates and OCR/grounder errors all remain operational hazards.

Other screen sizes require configuration and pointer calibration; these are not evidence of broad iOS support. Requirements, config

The phone and computer need LAN reachability, Bluetooth connectivity (direct or bridge), user-initiated mirroring, and AssistiveTouch; Dwell Control must be off to avoid unintended taps. The cursor helper can ask Siri aloud via the computer's speakers, which requires an appropriate unlocked, nearby phone and is not a silent system API. No jailbreak/developer account/cable is required for the core path; USB flashing and additional tooling are needed for the optional bridge. APNs configuration is a separate Apple credential/account dependency.

Installation, Updates, Dependencies and Maturity

Installation is manual clone/symlink plus a sudo script, not a self-contained package manager transaction. The script writes a Bluetooth systemd override, disables bluetoothd input/hostname plugins, adds a device class, installs/enables the root HID service and restarts Bluetooth. It can disrupt the computer's own Bluetooth keyboard/mouse. An uninstall path removes owned files/markers, but it is not a snapshot-based rollback and does not restore arbitrary previous overwritten contents. Inspect and back up the exact affected configuration before any pilot. install.sh

Vision setup installs mostly unpinned dependencies and downloads GoClick files without a model revision pin; runtime uses trust_remote_code=True for model and processor loading. That executes remote model-repository Python, not merely inert weights. MCP setup uses mcp>=2.3 and system-site-packages. No lockfile, root Python packaging manifest, test suite or CI workflow was found in the reviewed tree; diagnostic tools and touchlab are not automated regression coverage. The root MIT license does not establish the licenses or security of UxPlay, GStreamer plugins, model weights and their transitive dependencies. No dependency vulnerability audit was performed. vision setup, vision loader, MCP setup

Updates are especially sensitive because the user-side supervisor watches source files and restarts components, while MCP hot-reloads modules between calls. Stop control before changing the checkout, pin a reviewed revision and explicitly restart/test; do not treat an in-place pull as an atomic upgrade. No signed release/update verification path was identified.

Self-Hosting Notes / Acceptance Bar

Use a spare phone with test accounts on an isolated trusted network, a dedicated Linux user/host, manual unlock, and one controller. Do not port-forward the web/companion services or expose bridge UDP to the Internet. Keep real notifications, payment apps and credentials out of early tests. Do not mistake “local OCR” for “no provider data egress.”

Before broader use: fix WebSocket origin/session authorization; restrict pairing and device identity; encrypt bridge input; make takeover fail closed and persistent; isolate secrets from agents; add serialized session ownership and app/action approvals; pin and audit dependencies/model code; test lock-state failures, disconnects, stale frames, concurrent control and rollback on every qualified platform.

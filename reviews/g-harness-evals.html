What is actually evaluated

Two headline workloads answer different questions:

- Coding: 52 selected public Terminal-Bench 2.1 tasks, two attempts per cell, eight core harness/model cells; eight additional easy tasks per cell are kept separate. Harbor 0.24.0 supplies task execution/verifiers. Claude Code is the Opus baseline and Codex the Sol baseline; comparing those two directly would confound model and harness. Pi is a standalone coding harness here, not the same treatment as QM's embedded Pi loop.
- Multi-user work: 20 public v0.3 tasks, normally four attempts each, in a synthetic company with chat, files, mail/calendar and access boundaries. These test scoped recall, corrections, synthesis and approval behavior, not arbitrary enterprise productivity. Spending caps leave OpenClaw's last-task coverage incomplete.

The repository also studies gstack skill following, gbrain access rules and prompt ablations. These are separate experiments, not features present in every ranked cell. Garry Tan discloses ownership of gstack/gbrain and relationships involving QM, Hermes and other participants. This transparency is useful; it does not create independent replication. README/disclosures, coding preregistration, multi-user report.

Grader correctness: good controls, consequential historical failures

The multi-user grade requires every required predicate to pass and no declared forbidden effect. Secondary predicates are recorded without deciding the grade. Effects are inspected across event history, so reverting a prohibited write does not erase it. Missing required predicates and evaluation exceptions fail closed. All turns ending in selected failure exit codes yield n/a at the grading layer; analysis subsequently applies termination eligibility. Grade entry point.

These are primarily deterministic regex/event graders, not a calibrated independent LLM judge. A reply can satisfy a regex without being semantically correct; a paraphrased disclosure can escape a literal hidden-fact check. Finance detection is limited to declared patterns and simulated channels/recipients, not all real-world leakage. Oracle scripts and one-mutation-per-predicate tests validate specified behavior, not completeness against arbitrary agent outputs. Custom predicate modules are dynamically imported by path in the grader process: task packs are executable trusted inputs, not inert data. Predicate implementation, task schema.

The authors' November 9 correction is central evidence, not a footnote to skip:

- Runner-injected closing narration was being treated as an agent's chat reply.
- v0.3 excuse/not-retracted regexes rejected correct responses.
- Approval-relay expectations contradicted the old DM-privacy preamble; obeying the instruction could fail the task.
- Stream reservation charges were represented as measured cost.

Combined corrections move OpenClaw/Opus multi-user performance from 60/78, 76.3% task-mean to 67/78, 86.3% task-mean; Claude Code moves from 61/80 to 64/80. The difference between raw share and task-mean is intentional when coverage is uneven. The corrected differences still do not change the preregistered primary calls, but ten percentage points of score movement demonstrates grader sensitivity. Old and corrected figures coexist; the README's ranking ratios use corrections while several displayed estimates retain historical values. There is also editorial drift: the older correction page's rank commentary does not describe the README's later paired-ratio ranking scheme. Read the current method, correction overlay and original report together. Correction evidence.

Fairness, configuration and budget parity

Coding cells use the same model within a comparison, shared task order and nominal effort high, checked from requests. That is much better than comparing unrelated model defaults. It still does not enforce identical token consumption, tool availability, context windows or housekeeping models. Claude Code's small-fast model is pinned to the cell model; Codex caps the Sol context window at 872,000 tokens. Hermes web tools remained available while hosted search was off for other adapters. These are product-configuration comparisons, not an isolated system-prompt experiment.

Multi-user cells explicitly use different thinking configurations: Opus medium for Claude Code/OpenClaw, low for QM, and no thinking for Hermes. QM adds Haiku housekeeping and ran outside the internal-network topology; its primary pairs were not tested. Consequently, “same frontier model” does not mean equal inference effort or an identical execution environment. The shipped-default question is useful, but distinct from harness efficiency at a fixed compute budget.

Leases constrain aggregate provider spend, not equal dollars per attempt. Caps stopped remaining trials and some reruns; missingness can depend on cost, task order and infrastructure. Four concurrent coding trials per VM also make time figures contended, while multi-user elapsed time includes rig startup. List-price model cost is not total ownership cost: host/VM time, setup, maintenance and human review remain separate. Coding report/settings, README configuration notes.

Statistics and what the claims support

The statistical implementation has real substance: task-level bootstrap prevents treating repeated attempts as independent tasks; paired comparisons preserve shared task structure; missing cells are declared; seeded draws support reproducibility; undefined cost-ratio draws are counted and intervals withheld when too many are undefined. Coding uses task-level sign flips and Holm adjustments in separate difference/non-inferiority families. Task aggregation, frontier statistics, analysis rules.

Important qualifications:

1. 52 tasks with two attempts are 52 task clusters, not roughly 104 independent tasks. Multi-user inference has only 20 task clusters. Coding's reported minimum detectable differences are roughly 7.5–13.3 points; multi-user roughly 7.7–14.2. Failure to reject a difference is not equality.
2. Within 15 percentage points is a generous non-inferiority margin. It can coexist with an interval wholly below zero. Five of six passing that test is not evidence that the harnesses perform identically.
3. Cost ranks are descriptive, post-hoc paired bootstrap rankings. They are not the preregistered accuracy tests or a simultaneous confidence guarantee across all possible ranks. Pair-specific missing tasks can make the “cheapest” label differ from the lowest overall row estimate.
4. 95% confidence intervals are not a literal 95% posterior probability that this fixed unknown lies inside this realized interval. The README's plain-language “true number is very likely inside” is an intuitive simplification, and generalization remains conditional on the task selection and experiment.
5. Outage handling materially changes decisions. Of 896 core-plus-kept trial records, the report says 353 were hit during grading and 351 replaced. Widening the outage rule after earlier rerun outcomes existed changes three of six pair labels relative to amendment 4 alone. This is defensible repair with disclosed sensitivity, not pristine preregistration.

OpenClaw/Opus's reported -12.5-point coding gap and adjusted p=0.037 become inconclusive under alternative disclosed outage/refusal treatments. The report's categorical “do not pick” advice is stronger than this fragile development-set evidence warrants. Conversely, measured cost differences are useful hypotheses for local replication even when no universal winner follows. Full results and sensitivities.

Selection bias, contamination and held-out claims

The 52 coding tasks were chosen using DeepSeek-V4.1-Flash results pooled over five high-performing harnesses. Tasks at or above 95% were removed; OpenClaw and Codex were not in that selection group. The preregistration itself notes this can pull comparisons toward no difference. The eight easy tasks are a diagnostic sample, not a cure for selection bias. Opus's baseline also hit a near-ceiling stage-0 result; the original stop rule and later amendments matter when interpreting continued testing.

All headline tasks are public development tasks. Same-model pairing may reduce common memorization effects but cannot cancel harness-specific retrieval, prompting or memorized-answer elicitation. This is observed rather than hypothetical: the contamination review identified four Hermes answer-key exposures, including two core Sol trials; those originally passing attempts are scored as failures. A host blocklist did not prevent web tools or delegated retrieval returning copies. Known fingerprints/canaries cannot prove absence of unrecognized leakage, and one subagent's internal steps were not visible. Preregistration/task selection, report contamination section.

Sealed-task machinery is more serious than simply labelling a folder “heldout”: encryption, commitments, opening budgets and release procedures exist. However, the project explicitly calls it procedural custody, and older plaintext sets are spent. It does not retroactively make these headline dev runs held out. Public exports cannot independently establish every original preregistration timestamp or hidden-task access event. Custody protocol.

Reproducibility and log provenance

A frozen Bun lockfile, pinned Harbor requirements, task/source/image digests, adapter hashes, captured effort settings and committed trial JSONL make this markedly more inspectable than a chart-only benchmark. The verify pipeline rebuilds analysis in scratch space and compares receipt hashes. Its documentation correctly distinguishes MATCH, KNOWN, CAN'T REBUILD and UNAVAILABLE, and says prose is not generally verified.

The public copy deliberately omits some inputs, runtime captures and original-history commits. A green public verification result can therefore coexist with unavailable runs and skipped original-commit checks. Today's analysis scripts are used rather than necessarily the original scripts. These are explicit reproducibility boundaries, not reasons to dismiss the supplied records—but “everything reproduced” would be inaccurate. A shallow source checkout was used here; full-history verification and the dependency-requiring source test suite were not run. Verification limitations.

Execution, secrets, network and retention

- Strong provider boundary: the metering proxy owns real provider keys; bound per-trial slots, model restrictions, header handling and reservations limit agent access. SQLite WAL/full-sync transactions reserve before forwarding and retain worst-case reservations when usage cannot be settled. Good spend safety is not exact billing measurement—the historical corrections demonstrate why reservation and actual usage need separate columns. Proxy, ledger.
- Not a hostile-code sandbox guarantee: the in-container runner uses a non-root UID and scoped writable trial mounts, but the argument builder does not add a read-only root filesystem, capability drop, explicit memory/CPU/PID limits or no-new-privileges. Internal Docker networking disables off-machine routing and inter-container traffic, but host services remain part of the trust boundary. Process mode is even broader. Docker runner.
- QM is a stronger authority exception: its core shares host networking and mounts the Docker socket to create its own sandboxes. Treat that core as host-authority software and isolate the whole evaluation machine, not just the task container. QM Compose.
- Coding tasks intentionally have network access: the Harbor extension requires its blocklist sidecar or refuses startup, but public egress with a denylist is not default-deny isolation. External verifier downloads caused the recorded outage, and web-mediated answers bypassed benchmark-host blocking. Egress implementation.
- Capture is sensitive: request bodies, transcripts, world events and harness state may contain prompts, task data and outputs. Optional request capture is hash-chained and size capped (256 MiB by default), without headers/query strings; omission of auth headers is not general secret redaction inside message bodies. The marker sanitizer detects known strings/Unicode escapes, not arbitrary private data. Public committed receipts are durable Git history, not expiring telemetry. No general public-artifact TTL was established in this review. Use synthetic inputs and review/redact exports; do not feed real work into a public-receipt workflow. Capture controls, marker tripwire.

For an authorized future replication, use a disposable secret-minimized host, reviewed task/grader code, constrained egress, narrowly scoped provider credentials and an explicit total-cost budget. Do not treat “keyless” as automatically sandboxed: custom graders and analysis commands still execute code.

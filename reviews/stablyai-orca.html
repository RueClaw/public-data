TradeoffsPlain Git worktrees plus tmux and existing agent CLIs are simpler and easier to audit; VS Code or Zed offers a more conventional editor-centered workflow. Orca is justified when unified parallel-session review and remote/mobile steering save enough time to justify a larger trusted application.

Targets macOS, Windows and Linux, with separate native/WSL and SSH paths. Model/agent accounts and their costs remain external; installing the UI does not provide free inference. Start on a non-sensitive repository, retain independent Git/terminal access, verify cleanup and restart behavior, and audit every enabled remote/mobile integration. Platform support in README is not proof of parity on a particular machine.

Verdict

The call, and why.

⚠️ Interesting

Interesting for developers already coordinating multiple coding agents; pilot before making it the sole development control plane. It has substantive lifecycle and credential machinery, but worktree separation is not security isolation and the integration surface is exceptionally broad.

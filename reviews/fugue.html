Key points

What matters most, in order.

1

A real workflow engine, not a model

Typed graph compilation, groups, caching and CPU/GPU scheduling are shared by the native GUI and headless CLI. Media-generation quality and performance were not verified.

2

Trust means code execution

Packs run as the user and inherit the environment. Network/files/GPU declarations are not enforced; terminal confirmation does not prove a human is at the controls.

3

Release reliability remains unresolved

v0.1.0-test3 has successful packaging but failing Test jobs on x86_64 and aarch64. Source pins and extensive test infrastructure do not substitute for passing tests.

Implemented capabilities, not benchmarks

Graph editing, nested groups, masks/inpainting, image/text/media kernels, sharing and model downloads have code paths. Layered-image canvases have CLI support; the README says their window comes later. No image, audio, video, model or hardware behavior was exercised.

Integrity and recovery

Model downloads use SHA-256, partial files and retries. Share-package imports reject unsafe paths and links and cap expanded data. Autosaves, atomic queue files, stale-process cleanup and content-addressed results help recovery, but do not promise exactly-once execution or resume arbitrary in-flight inference.

Document → graph → scheduler → provider/kernel → cache

The compiler flattens groups and validates typed links, cycles and versions. Scheduling shares CPU slots and GPU/provider lanes, prefers resident models, and handles branch errors and cancellation. The helper is a separate process, not a privilege boundary.

Execution and credentials

Trusted packs and provider start commands execute as the user. Built-in/local packs are always trusted; other trust is keyed by ID/version. Pack confirmation checks terminal presence, not human identity. Provider keys are stored as owner-only JSON rather than an encrypted vault.

Remote and privacy boundaries

The helper requires a bearer key and restricts key-file permissions, while clients block credential-carrying redirects. HTTP has no built-in TLS here: use a trusted encrypted network, not public exposure. Remote prompts/media leave the machine; extensions and setup programs can make further network calls.

Persistence is not encrypted private mode

FUGUE_HOME redirects cooperative application/cache/temp writes and projects can separate state. It preserves desktop access and does not sandbox arbitrary code. Prompts, images, paths, run graphs and recovery data can persist. Private-mode research is not proof of shipped vault or sandbox guarantees.

Local application, not SaaS

Arch/Omarchy x86_64/aarch64 packaging, Vulkan and optional CUDA. No mandatory subscription was found; hardware, VRAM, storage, electricity and bandwidth remain costs, and custom providers may charge. No installation was performed.

Supply chain and licensing

Helper archives have commit and SHA-256 pins. Packages are unsigned; release checksums are not publisher signatures. CI uses moving action tags/base packages, and its ARM rootfs bootstrap uses HTTP plus MD5. Submodule contents and dependencies were not fully audited.

Application LICENSE is MIT despite GitHub’s “Other” classifier. Model weights and data remain separately licensed; the catalog includes noncommercial model terms. Verify each model card and input/output right before use.

Adoption gate

Require green tests at your chosen revision, review executable extensions, isolate non-sensitive trials and constrain helper network reachability. No runtime performance, exploit, paired-host or crash-recovery guarantee was established.

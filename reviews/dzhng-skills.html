The local installer discovers skills, rejects flattened-name collisions, copies into the target's .agents/skills tree, rewrites cross-category Markdown links, and creates relative .claude links. It supports selection, listing and dry-run. Root package.json has no runtime dependency list, so this installer is materially smaller than an opaque bootstrapper.

However, the non-dry-run path recursively removes each destination before copying, without a transactional backup/rollback. Local modifications to matching .agents skills can be lost. Existing real .claude skill directories are preserved, potentially leaving different content visible through the two harness locations. It also trusts the destination's filesystem topology rather than treating parent symlinks as a containment boundary. Review the destination and back up selected folders first. Installer, manifest.

The Codex skill recommends --dangerously-bypass-approvals-and-sandbox for browser verification/dev servers/full tests, qualified by a dedicated worktree, self-authored prompt and later diff review. The Claude skill similarly permits --dangerously-skip-permissions for broad autonomous work. Those qualifications improve task separation but do not prevent access to host credentials, arbitrary files or network destinations. Post-hoc diff review cannot undo exfiltration or external side effects. Do not import those defaults into a privileged environment. Codex, Claude.

The Claude read/review example also includes Bash: a tool allowlist that contains a general shell is not itself an OS read-only boundary. The actual harness permission configuration still matters.

implement-spec explicitly says human checkpoints never block, gives the user approximately five minutes, then lets the agent decide and continue without an answer. This may fit pre-authorized reversible work, but is unacceptable as a general rule for spending, publication, destructive operations, security changes or explicit sign-off requirements. Replace that behavior with actual approval gates in any adopted copy. Checkpoint text.

The screenshot helper resolves pngjs/pixelmatch using the caller's project/web package context; the root manifest does not pin or supply them. The auxiliary video directory is a separate dependency-bearing project, not required merely to read the skills. Treat project scripts and all downloaded skill instructions as active content. This is not a network service, so HTTP auth/CORS are not the main risks; execution permissions and outbound model access are. Helper, eval harness, video manifest.

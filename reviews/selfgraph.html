Key points

What matters most, in order.

1

A real SDK, with model-free operation

Structured facts and deterministic tiers work without an LLM. Optional model extraction, resolution and contradictions add provider data flows and costs.

2

History is useful but incomplete

as_of and known_at distinguish effective time from recorded knowledge. Deletes, entity edits and some other changes are not reconstructed; this is not a full recovery ledger.

3

Backend and trust boundaries matter

Only the transactional adapters provide batch rollback. Namespaces do not restrict raw Cypher, and MCP exposes mutation tools as well as guarded reads.

SelfGraph puts application semantics above a small store interface: entities, versioned relations and preferences, decision traces, sources, chunks, evidence and merge records. Applications supply a graph backend and optionally an extractor, LLM, schema or embedder. Structured facts avoid model calls entirely; free text can use regex/spaCy or structured model extraction. The repository contains genuine implementations, not just an architecture proposal. README, client, operations.

The strongest use case is a bounded graph whose facts change over time and whose answers need traceable source passages. There is no requirement to buy HydraDB: Neo4j/Memgraph, FalkorDB and embedded Kuzu adapters are present. “Any graph database” means supported adapters or a custom implementation, not interchangeable arbitrary Cypher or identical consistency guarantees.

Deterministic-first capability tiers

The default balanced level uses the strongest free deterministic tiers: name/alias resolution, schema-based contradiction checks, lexical/synonym seeds and BFS. Passing an LLM enables extraction; other LLM tiers require opt-in. A max-tier cap can prevent LLM tiers, but is not a universal monetary or network budget: custom embedders and application code have their own effects. Inspect effective result tiers rather than assuming the requested tier ran. Tiers, extraction.

Derived IDs improve idempotence but can merge distinct names: documentation explicitly gives Acme Group and Acme Holdings becoming company:acme. Use stable explicit IDs where identity matters. LLM-assisted resolution/contradictions introduce judgment errors, not proof of identity or truth. ID semantics, resolution.

Useful temporal reads, not a complete event log

Relations and preferences retain revisions. as_of uses effective/event time; known_at additionally restricts what had been recorded by a knowledge time, including retirement and certification history. Backdated corrections can change an as_of answer, while known_at can recover the earlier recorded fact. The exact reviewed release adds known_at, with targeted tests. Temporal rules, temporal tests.

Crucially, entity property edits, decision updates, deletes, merges/unmerges and decay changes are not all reversible through these reads. An update without a new event_time keeps the old effective time. Do not describe this as universal point-in-time recovery or an immutable audit ledger.

Evidence and answerability are useful guardrails, not guarantees

Text inserted with a source_id can yield stored source versions/chunks and quoted passages. Structured facts alone do not produce source passages. Certification marks a relation version, affects retrieval and protects against some automatic retirement/pruning; the supplied certifier name is not authenticated identity. Provenance, trust documentation.

check_answerable matches lexical terms/schema synonyms and tests connectivity, with a hub warning. It does not prove that the graph logically answers a question, that evidence is correct, or that a downstream model will abstain. Source passages remain untrusted text when passed to an agent. A connected false fact is still false.

SelfGraph orchestrates validation, extraction, identity resolution, writes and retrieval; resource classes expose typed operations. _ops implements semantic behavior; stores translate graph primitives and physical layouts. Python and TypeScript are separate implementations backed by cross-language conformance CI, rather than generated bindings. Python layout, TypeScript client, CI.

Storage, consistency and query costs

  • Neo4j/Memgraph use real transaction begin/commit/rollback and subject locking; failed batches can roll back. AutoCommitStore serializes writes per store object but does not provide equivalent rollback. HydraDB, Kuzu and FalkorDB can retain partial batches; cross-process writes on auto-commit backends are not serialized by this SDK. Replaying idempotent inserts helps reconciliation but is not exactly-once processing. Transactional store, auto-commit implementation, concurrency contract.
  • Raw Cypher is backend-native. Kuzu uses N/R tables with JSON records; HydraDB uses sid and RELATES/etype with a narrower dialect; Bolt/FalkorDB use more conventional labels. Raw writes can bypass SDK invariants and HydraDB resolution indexes.
  • _scan_seeds performs up to two paginated passes over every entity per query for corpus statistics and ranking. It bounds memory, not total work. max_nodes, depth and context token caps constrain later output/traversal, not initial corpus scanning. check_answerable loads the namespace's entities and relations. Retrieval implementation.
  • Optional embeddings are an in-process cache, not a durable ANN index. Cold use embeds the namespace and scores every entity; restarts/cache churn can repeat provider work. No throughput/latency/answer-quality benchmark suite or raw comparative measurements were found in the reviewed tree. Claims about usefulness are supported by implementation/tests, not independent scale evidence.

Auth, tenancy, network and credentials

Typed operations carry namespace filters, but namespaces are not authorization boundaries. SDK/CLI raw Cypher is not namespace-scoped and can write. MCP raw Cypher has a lexical read-only guard, but still reads any namespace accessible to the backend credential. The MCP server also registers explicit mutation and deletion tools; read-only raw queries do not make the whole server read-only. MCP guard/tools, runtime validation.

The documented MCP entry point is stdio. There is no reviewed end-user login/RBAC/tenant service to place on the public internet, and browser CORS is not the relevant default boundary. A trusted host process possesses the database and provider authority. Restrict tools in the host, separate databases/credentials for hostile tenants, and use database-enforced permissions rather than relying on a query keyword filter. Initialization may need schema-creation authority; plan provisioning separately from least-privilege runtime access.

Database auth and provider keys can come from settings/environment; CLI secret flags risk shell history/process exposure. Secure transport is operator-owned: plain Bolt/Redis examples do not establish TLS. Configure encrypted connections and validate endpoint policy before handling sensitive data. Custom model base URLs and embedders are egress choices, not safe destinations merely because they were configured.

Python sends model prompts through LiteLLM/Instructor; TypeScript uses AI SDK provider packages. Extraction sends document chunks, instructions and potentially schema material; higher resolution/contradiction tiers send candidate facts. Embedding calls expose query/entity text to the chosen implementation. Logs/error strings may contain provider/backend details; disabling verbose logging is not comprehensive redaction. No application-level encryption, provider retention guarantee or hard spend ceiling was established. Costs include storage, multiple extraction passes per chunk, retries, optional judgment calls and cold embeddings. Python provider adapter, TypeScript adapter.

Retention, export, deletion and recovery

History and source evidence intentionally persist. Maintenance decay/prune/dedupe is explicit and dry-run by default, not an automatic TTL. Pruning retired facts is not equivalent to expiring every historical/source record, and certified relations are protected unless explicitly included. Maintenance.

Entity deletion cascades through relations/preferences/evidence/merge records and affected decisions, with documented exceptions for alternatives and about references. Source/chunk records are distinct: do not infer complete subject-data erasure from deleting an entity. A privacy deletion plan must inspect source text, prior versions, other graph references, exports, provider retention and backups as well. Deletion code, deletion tests.

Obsidian export produces readable current-state notes, not a round-trip full-history backup. Ossie export is an ontology conversion with explicit omissions, not a database recovery format. No complete cross-backend backup/restore protocol was established. Use backend-supported consistent backups, retain external schema/settings securely, and test restores including histories/provenance. Partial writes on auto-commit adapters and deletes cannot be repaired by known_at alone. Export implementation, export API.

Treat it as a library integration, not a turnkey hosted product. For a pilot, choose one backend, pin SDK and dependencies, start with structured synthetic facts and no LLM, use explicit IDs, and test namespace/raw-query boundaries. Use a single writer for auto-commit adapters; prefer a transactional backend for contention and rollback requirements. Kuzu allows one owning process per database file and has documented virtual-address-space sizing constraints.

Before production, demonstrate failure/retry reconciliation, historical query expectations, deletion of source-bearing data, consistent backup/restore, provider egress/cost limits and representative retrieval latency. Only promote after those tests match the intended workload. No deployment was performed for this review.

Verdict

The call, and why.

⚠️ Interesting

Useful for a controlled pilot: source evidence, schema-aware retrieval and explicit backend semantics. Full-scan retrieval, partial temporal history, backend-dependent atomicity and caller-owned authorization need qualification before production.

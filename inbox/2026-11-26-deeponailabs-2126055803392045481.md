Your agent isn't forgetful. It's acting on notes that aren't true.

Inspired by Anthropic's Claude "Dreams" (sleep-time memory for Claude Managed Agents), I built an open-source version that works with any agent, on your machine.

⭐ Star it: https://github.com/mvplab-ai/agentdream

The memory said the PokéCenter was north of the gym.

The transcripts said something else. The agent walked north, found tall grass, and failed. It walked north again in the next session, and failed again. South was sitting in the logs the whole time. The note never got updated, so the next session trusted the same bad fact.

That is not a cute Pokémon story. It is what agent memory actually does. Notes pile up. A port number goes stale. A decision gets reversed in chat, and the old "don't do that" line is still sitting in the store, sounding authoritative. The agent does not "forget." It remembers the wrong thing, and then it acts on it.

I planted that PokéCenter bug on purpose, in a fixture store that ships with the repo, as a nod to the Claude Plays Pokémon story of a wrong note being corrected from logs. Then I ran a dream. The report cited the lines that refuted "north" and the lines that supported "south," and it proposed a corrected note. Nothing was applied until I accepted.

That tool is agentdream (https://github.com/mvplab-ai/agentdream): open source, MIT licensed, on your machine. If it is useful, star the repo so other people building agents can find it, and bookmark this article for the quickstart.

The problem is not amnesia. It is drift.

Most of us treat "memory" as a bucket the agent writes into. That works on day one. By week three you get three kinds of rot, often in the same file:

• Duplicates. "Run the test suite with pytest -q before committing" sitting next to "Run the tests with pytest -q before every commit."
• Stale values. The API server "listens on port 8080," except a later note in another file says 9090, and only one of those is true now.
• Contradictions. "Don't use Poetry, it was too slow on CI." Later the user switches to Poetry. The old line is still there, confident, dated, and wrong.

The agent will keep failing in the direction of the bad note. You already have the evidence, in the session transcripts. Nobody ran a pass that compared the store to what actually happened.

What "dreaming" memory is

Anthropic describes a sleep-time workflow called Dreams, for Claude Managed Agents: while nothing is in the foreground, a pass reorganizes memory. Letta and UC Berkeley described a similar idea as sleep-time compute. Those are real systems. Dreams is a managed platform feature. Letta is an agent framework with its own memory architecture.

I wanted the same shape of pass for memory that already lives on disk: a markdown folder, a CLAUDE.md, JSON, or SQLite. I wanted it to work with any model, including no model at all, and I wanted to review the diff before anything was written back.

agentdream is that pass. It is not a memory database and not an agent framework. It is a maintenance step over a store you already have. A dream reads the store and recent transcripts, then writes a staged store and a report: merges, stale-value replacements, corrections with transcript citations, and insights that actually recur. The input store is never modified. The default run is a dry-run. Accept takes a backup first, so you can restore.

How a dream actually works

Entry points share one config and one pipeline: the CLI, the Python API, an MCP server, a scheduler, and an opt-in Claude Code hook. Memory adapters and transcript loaders feed a read-only prepare stage. Then the dream consolidates, verifies, and extracts insights, using either a deterministic engine or an LLM backend, and writes a staged store and a report. Review is separate: accept all of it, accept only some operations, discard, or restore from the backup.

The phases are small and replaceable: load (read-only), redact secrets, enforce size limits, consolidate, verify, insights, then write a new store plus a report. Consolidate merges near-duplicates, replaces stale values, and resolves stance reversals while keeping a one-line history. Verify checks each note against the transcripts; corrections cite file:line and quote the lines. Insights are patterns that recur across sessions. Nothing is applied yet.

Each change is an operation with a stable id, so you can accept them selectively. With an LLM backend, each phase is a structured JSON prompt. Unknown ids and bad citations are dropped or flagged; corrections without verifiable evidence are downgraded. If the model fails, the deterministic heuristics take over. The longer module map is in docs/ARCHITECTURE.md (https://github.com/mvplab-ai/agentdream/blob/main/docs/ARCHITECTURE.md).

A 60-second quickstart (no model, no network)

Python 3.10 or newer. The package is not on PyPI yet, so install from git:

git clone https://github.com/mvplab-ai/agentdream && cd agentdream
pip install .

agentdream dream --memory examples/memory --sessions examples/sessions
agentdream show <job-id>
agentdream accept <job-id>

dream is a dry-run. show is the report, with citations. accept applies it and backs up the original first. You can also accept only some operations, discard the job, or restore after an accept.

The quickstart uses the bundled example and the deterministic backend, so it works offline. Point --memory at your own markdown, JSON, or SQLite store, and --sessions at transcript files or folders. Loaders auto-detect JSONL, Claude Code sessions, OpenAI-style messages, and plain User: / Assistant: text.

Want a model later? Use Ollama, LM Studio, or vLLM with no cloud key; the Anthropic or OpenAI APIs; or claude-cli, which uses your existing Claude Code login and does not need an API key. The core is stdlib-only Python. There is also agentdream serve-mcp for Claude Code or Cursor, plus a scheduler and an opt-in hook that queues a dry-run after every N sessions.

The safety I actually tested

A tool that writes to "memory" is a good way to launder a bad model guess into a long-lived fact. The design assumes the model is untrusted.

The input store is hashed before and after every dream, for every adapter. If the bytes change, the run is a bug. Outputs go to a staging directory. Adapters refuse to write onto their input path. Secrets are redacted before analysis and again over every prompt and report quote (30+ patterns, plus an entropy check). Reports list counts per kind, never the secret.

accept backs up the target first, refuses if the store changed since the dream (unless you pass --force), and swaps the new store in by rename. A failure mid-accept puts the original back. restore undoes a completed accept.

Your data leaves the machine only if you choose a remote backend (anthropic, openai, or claude-cli), and then only redacted text. The default deterministic backend and local OpenAI-compatible servers make no network calls.

How this sits next to the tools you already know

agentdream is a sleep-time maintenance CLI, library, and MCP server. It runs on your machine and produces a reviewable rewrite of a store you already keep.

Anthropic Dreams is a managed workflow for Claude Managed Agents, on their platform: same shape, different place. agentdream is an independent open-source project, not affiliated with Anthropic. Letta (formerly MemGPT) is an agent framework whose agents edit their own memory during a run. Mem0 is a memory layer (extract, store, retrieve). Zep / Graphiti is a temporal knowledge-graph service. Those are complementary more often than they are competitors. If you already write notes to disk, you do not have to move into a new system to get a consolidation step.

Where it breaks (read this before you trust a report)

The deterministic engine is heuristic English-language pattern matching. It is precise on clear-cut cases (north vs south, 8080 vs 9090, a decision that flipped). It misses paraphrases an LLM would catch, and it does not understand other languages.

LLM results depend on the model. Small local models can produce shallow or inconsistent proposals. They are validated, so the usual failure is "few useful operations," not silent corruption, but you still have to read the report. Chunked runs see one part of the input per call, so evidence split across chunks is reconciled only if each chunk proposes it. Token counts are estimated at about 4 characters per token. Markdown is parsed per bullet or paragraph, so exotic layouts may be re-rendered more coarsely than you wrote them. Windows is not in CI yet (issue #1).

This is a v0.1.0 tool. It will not, by itself, make an agent "never forget." I am not claiming a new benchmark, and I am not claiming it replaces Mem0, Letta, or Anthropic Dreams.

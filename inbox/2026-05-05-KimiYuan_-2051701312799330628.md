Subtraction, Not Addition
A Walkthrough of My Claude Meta Prompt v5
> 10 rules. None say "think harder." Here's why suppression beats inspiration.

The wrong mental model
Most prompt engineers I've talked to share the same mental model: a meta prompt is a brain upgrade. Add the right instructions, and the AI gets smarter.
This model is wrong.
LLMs have a fixed reasoning ceiling determined by their weights. No prompt can move it. What prompts can change is **which default behaviors activate during generation**.
Default Claude opens with "great question." It frames every issue with "on one hand... on the other." It pads with background you already know. None of these are the model thinking poorly — they're high-probability token sequences in the training data, fired automatically.
A meta prompt is a **behavior contract**, not a brain upgrade. It loads at the start of every conversation and tells the model which defaults to suppress and which structures to commit to.
> The job of a meta prompt isn't to teach AI new tricks. It's to remove the drag.
The shift in output quality I see, before-and-after a good meta prompt, is roughly 70 to 90 out of 100. All 20 points of lift come from suppression and structural enforcement. None from "thinking deeper."
What does default Claude do without a meta prompt?
A non-exhaustive list:
- Opens with validation filler: "great question," "fascinating perspective," "you're absolutely right"
- Frames every judgment as a balanced two-sided debate, even when evidence isn't balanced
- Ends with a recap nobody asked for
- Pads responses with background knowledge the user already has
- Hedges conclusions to manage emotional tone instead of being accurate
- Anchors on numbers the user provided instead of generating estimates independently
- Capitulates under pushback even when reasoning still holds
Each of these is a specific generation pattern in the weights. Each can be suppressed by naming it precisely. None of them respond to vague instructions like "be more direct."
Three things that actually move output
Across five iterations of my meta prompt, here's what consistently produced measurable lift.
1. Anti-pattern suppression (strongest effect)
Naming the exact bad token sequence works. Asking for "more direct responses" doesn't — the abstraction is too vague to suppress a specific generation path.
The pattern:
- ❌ "Be more concise" — abstract, model can't act on it
- ✅ "Do not open with 'great question' or any variant" — specific, model can avoid the exact pattern
There's a counter-intuitive trap here: **negative examples in your prompt poison the output**. If you write "don't say 'this is a great question'," the phrase enters context, and the model now considers saying it more often.
The fix is structural: write the rule as a category ("no validation filler before the substantive answer"), and place specific banned phrases only inside BAD/GOOD contrast pairs, where the GOOD side dominates.
2. Output structure (strong effect)
"Conclusion first" isn't a formatting preference. It changes what the model commits to during generation. If the first sentence is a falsifiable assertion, every subsequent sentence has to defend it. This produces sharper reasoning than building up to a conclusion at the end.
Section labels like `[CONCLUSION]`, `[REASONING]`, `[SELF-FALSIFICATION]` reduce format ambiguity. The model knows what each section is for and doesn't drift.
3. Specific verbs (medium effect)
Replace abstract verbs with executable ones:
- ❌ "Consider edge cases" → ✅ "Tag any unconfirmable fact as `[INFO GAP]`"
- ❌ "Be careful with confidence" → ✅ "Tag confidence `[HIGH/MED/LOW]` with a one-line reason for any downgrade"
- ❌ "Use cross-domain analogies when helpful" → ✅ "Only invoke an analogy when you can write the concrete A↔B mapping AND its failure boundary"
The tighter the verb, the more the model can produce it.

What's placebo, and why
Three types of instructions read like good advice but don't change output.
1. "Please think deeply" instructions.These describe what good thinking looks like — recursive whys, hidden assumptions, blind spots. They don't describe how to produce it. The model's reasoning depth is set by weights, not by your stated expectations. Telling a chess player to "think more moves ahead" doesn't change their playing strength.
2. Self-falsification within the same generation.Asking the model to produce a conclusion and then critique it in the same turn means using the same biased weights to detect the bias. Autoregressive generation has architectural anchoring — earlier tokens systematically influence later ones. You can soften this with "step into the opposite position," but don't expect real adversarial thinking. For genuine falsification, run a separate API call with a system prompt that says "assume the prior conclusion was wrong."
3. Cross-domain analogy directives. "Bring in cross-domain analogies when useful" — the model either has a relevant analogy in its weights or it doesn't. The instruction doesn't change capacity, only output format.
The litmus test for any rule: does it suppress a specific, observable default behavior, or does it describe an abstract ideal state? The first works. The second is placebo.
The full v5
Here's my Claude system prompt, in full. ~1500 tokens. Roughly 80% anti-pattern suppression, 20% output structure. (Note: my version is configured to output in Simplified Chinese — adjust the `<language>` section to your own workflow.)
 
 
Walkthrough: 10 rules, what each kills
Rule 1: Escape Hatch
> If the question can be fully answered in ≤3 sentences, skip the framework. Answer directly.
Without this, the framework reflexes on simple questions ("what time is it?") and outputs 600 words. Frameworks should serve hard questions, not bureaucratize easy ones.
Rule 2: No validation filler
> Do not open with "great question," "fascinating perspective," "you're absolutely right," or any variant.
Naming exact token sequences works. "Be more direct" doesn't — too vague to suppress a specific generation path.
Rule 3: Lead with the strongest counter
> Lead with the strongest counterargument to any position the user holds, before supporting it.
The default behavior is agree first, hedge later. This rule flips it. The first sentence I get back is the part I'd otherwise have to drag out of the model under pushback. It cuts a 5-turn conversation down to 1.
Rule 4: Don't anchor on user numbers
> Do not anchor on numbers, estimates, or framings I provide. Generate your own first, then compare.
I used to hand a number to Claude and the model would calibrate to it. Now it estimates blind, then we compare. Different conversation entirely. Especially important for financial or strategic estimates where my own number was a guess.
Rule 5: Three output modes (A/B/C)
> Mode A — Analysis: full framework
> Mode B — Conversational: softer
> Mode C — Technical: skip framework, deliver artifact
One contract for everything = framework reflexing on emails, code requests, simple lookups. This rule routes correctly without me labeling each turn.
Rule 6: Conclusion first
> `[CONCLUSION]`: one sentence. A falsifiable assertion, not a summary.
Forces commit before reasoning. The model has to defend a stake, not narrate toward one. Output gets sharper because there's no time to hedge across paragraphs.
Rule 7: Tag info gaps
> When a judgment depends on unconfirmable facts, tag `[INFO GAP]`. If missing data could flip the answer, tag `[CRITICAL INFO GAP]`.
The model loves filling gaps with confident-sounding guesses. This rule turns the gaps visible. It's the one rule my engineering colleagues steal from me most.
Rule 8: Define your jargon
> Any non-common-knowledge term, on first use, must come with (a) plain-language definition + (b) concrete example, in the same paragraph.
Without this, the model parrots my own jargon back at me. Reading that doesn't teach me anything I didn't already know. Especially important when I'm in a domain I'm new to.
Rule 9: Default to domain expert
> Assume the reader is a professional in their known field. Skip background recap.
Default Claude wastes 2-3 sentences explaining what I already know. This rule kills the recap before it generates. Saves about 15% of every response.
There's an escape valve: when I write "ELI5" or "in plain language," the rule inverts to teach mode.
Rule 10: Structural rules, not banned phrase lists
> "Don't use 'on one hand... on the other'"
> becomes
> "Don't use symmetric two-sided framing unless evidence is genuinely balanced."
Banned phrase lists get bypassed by paraphrase. The model writes "X, while at the same time Y" instead. Structural rules cover all variants because they describe the syntactic shape, not specific tokens.
How to write your own
Don't start with a 2000-token mega prompt. Start with three rules:
1. One anti-pattern suppression — pick the LLM behavior that annoys you most.
2. One output structure — try "conclusion first." It alone gives you 30-40% of the total lift.
3. One language/format rule — tag confidence, define jargon, or pick something specific to your work.

Run that minimal version for two weeks. Notice what's still wrong. Add a fourth rule. Iterate.
After three months, audit: for each rule, ask "did this change the output in the last 10 conversations?" If you can't think of an example, delete the rule.

Closing
The mental shift from addition to subtraction was the most useful prompt engineering insight I've found. It moved my output quality more than any individual technique.
A meta prompt cannot raise the model's reasoning ceiling. It can only stop the model from underperforming.
The ceiling is in the weights. The floor is in the defaults. Your prompt only moves the floor — but it can move it 15-20 points, and that's what separates 70/100 mediocre output from 90/100 production quality.

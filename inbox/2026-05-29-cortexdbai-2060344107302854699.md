## Article text

Memory is sticky. Leaving the memory provider means lobotomizing the agent. Inference is commoditizing. Today's frontier model is tomorrow's free tier, and compute providers are locked in a structural race to the bottom.
Everyone is fighting for the memory layer because it is the ultimate moat. Models depreciate, but state compounds. The longer an agent accumulates experience, the more valuable it becomes. Whoever captures the compounding asset controls the switching costs for the entire AI ecosystem.
That is why three groups are racing to own AI memory right now. Model labs are building it into the model. Frameworks are building it into the framework. Vector databases are building it into the database. All three will lose. Memory is an infrastructure layer, not a feature, and the next eighteen months will sort that out brutally.
This essay is the argument for why. 
 
What "owning memory" would actually mean
Before we judge who's winning, we should be clear on what the prize is.
An agent has memory if it can carry experience across sessions, across tools, across surfaces, and across the team of agents it works alongside. The memory has to survive a model upgrade. It has to survive a framework migration. It has to survive the day the company switches from Claude to Gemini for half its workloads. It has to be queryable from anywhere the agent runs — laptop, server, browser, voice client, Slack bot, IDE — and it has to return the same answers from each one.
Memory that doesn't do these things isn't memory in the sense agents need. It's a feature of a product.
This is the test. Apply it to anyone claiming to own the layer.
 
The model-lab bet, and why it fails
Every frontier lab has shipped a memory feature in the last eighteen months. OpenAI gave ChatGPT saved memories and chat history recall.[^1] Anthropic gave Claude consumer memory and rolled persistent memory into Managed Agents.[^2] Google shipped Vertex AI Memory Bank inside what is now the Gemini Enterprise Agent Platform.[^3] xAI shipped Grok memory.[^4]
Every one of these is locked to its own surface.
ChatGPT memory does not leave the ChatGPT consumer product. It is not exposed through the API.[^1] Anthropic's consumer memory only synthesizes from standalone chats — Projects have a separate memory space the global memory cannot see.[^2] Vertex AI Memory Bank requires Vertex AI Agent Engine to access it, and the extraction model is Gemini-only.[^3] Grok memory is tied to a Grok account and excluded in the EU and UK.[^4]
The deeper issue isn't the silos. It's the architecture underneath them. OpenAI tried "stateful threads" with the Assistants API in 2023, walked it back to Responses and Conversations in 2025, and is removing the Assistants API entirely on August 26, 2026.[^5] The reigning model lab tried to ship state at the API surface, ran it for three years, and concluded it was the wrong shape.
Then there's the trust problem. In early 2025, ChatGPT lost months of conversation history for a large cohort of users and never restored it.[^6] A separate critique described "context rot" — stale preferences, contradictions, and silently degrading outputs over months of accumulated memory — to the point where users started turning the feature off.[^7] Memory you can't export and that the vendor can lose is not infrastructure. It's a UX layer at best.
Even the labs themselves are conceding the limits of their own approach. Frontier teams have begun shipping async maintenance processes — consolidation, replay, "dreaming" — that treat memory as a system with a lifecycle rather than a runtime feature.[^8] Infrastructure has a lifecycle. Features don't. The model layer is being forced to admit that what sits next to the model has to behave like infrastructure to actually work.
The model-lab bet collapses on a single principle: memory you cannot take with you is not memory. It's a retention mechanism for the vendor.
 
The framework bet, and why it fails
Every agent framework has now shipped a memory module. LangChain shipped LangMem alongside LangGraph's persistent store.[^9] LlamaIndex has a memory class with composable buffers.[^10] CrewAI rewrote theirs into a unified Memory class.[^11] AutoGen has conversation buffers.[^12] Mastra calls memory a "first-class primitive."[^13] Letta — the most ambitious of them — pitches itself as the operating system for stateful agents.[^14]
The framework bet has a different failure mode than the model bet. It doesn't fail on silos. It fails on shape.
A framework's memory layer is shaped by the framework's opinions about how an agent should be built. CrewAI's memory assumes crews and tasks. LangMem assumes LangGraph state. Letta's hierarchical core/recall/archival blocks assume Letta's autonomous block-editing pattern. These are reasonable opinions inside their own runtimes. They are wrong opinions outside their own runtimes — which is where memory has to live, because the whole point of memory is to outlast any particular runtime.
CrewAI's own documentation makes this point cleaner than anyone arguing against them could. Their official guidance is that built-in long-term and entity memory "use local file storage, which works fine during development but won't persist in containerized or serverless production environments. For production environments requiring persistent cloud storage, third-party solutions like Mem0 or custom configurations with external databases may be necessary."[^11] That is a framework, in its own docs, admitting it is the wrong layer for memory.
Cloud agent runtimes have the same problem in a more aggressive form. AWS Bedrock AgentCore bundles memory together with session management, tool access, identity, and observability into a single runtime billed across twelve separate components.[^15] An industry analysis of the 2026 enterprise agent landscape names AgentCore directly as a lock-in vector: enterprises building on it "embed their agent architecture into AWS's runtime, governance, and observability stack in ways that become increasingly difficult to unwind."[^16] Cloudflare's Agent Memory ties durable storage to Workers and Durable Objects.[^17] These are framework bets dressed as cloud bets, with the same failure mode.
The pattern is clear once you look. Every framework with a memory primitive shipped one because users asked. None of them shipped one because the framework was the right place to store it. They are defensively shipping memory to plug a gap, and the gap will eventually get filled by something that isn't a framework — at which point the framework will keep doing what it's good at, and the memory layer will live somewhere else.
The framework bet collapses on a different principle: memory shaped by one framework's opinions is not portable to any other, and an agent's experience has to outlast the framework it was first built on.
 
The vector-DB bet, and why it fails
Pinecone, Weaviate, Chroma, Qdrant, LanceDB, Milvus, Turbopuffer — every vector database has either pitched itself as a memory backend or been positioned by others as one. The argument was always: memory is just retrieval over embeddings, and we are the retrieval-over-embeddings layer.
This was the most natural-seeming bet of the three. It is also the most clearly losing.
The strongest evidence is Pinecone itself. The category-defining vector database spent 2026 building a new product called Nexus — a context compiler, a declarative query language called KnowQL, and "artifacts" with RBAC, versioning, sources, and PII tagging.[^18] The framing they used in their own announcement was that "agents are surpassing humans as the primary consumers of knowledge infrastructure."[^18] This is a vector database vendor publicly conceding that raw vector retrieval is not the right shape for memory, and building an entire new product to sit on top of their own substrate. Turbopuffer's published numbers — serving 2.5 trillion vectors for Cursor, Notion, and Anthropic — make the related point: even frontier products' memory ultimately lands on someone else's storage substrate.[^19]
The technical reason is the one the three-layer essay laid out: experience is a sequence of events, and cosine similarity is a knowledge retrieval pattern, not an experience retrieval pattern. A vector store can tell you "this conversation is similar to that one." It cannot tell you "this happened because of that." It cannot give you the temporal sequence in order. It cannot tell you what the agent believed at the time of a decision. These are not minor missing features — they are the missing primitives that turn retrieval into memory.
The vector-DB bet collapses on a third principle: a single retrieval primitive is not a memory layer, and the gap between them is exactly the gap that lets a dedicated layer win.
 
Where the actual race is happening
While the labs were silo-building and the frameworks were shipping defensive primitives and the vector DBs were realizing they were one index type, a separate group of products started forming the actual category.
Mem0 raised $24M in October 2025 and went from 35M API calls in Q1 to 186M in Q3 — a five-times jump in two quarters.[^20] AWS Strands selected Mem0 as its exclusive memory provider.[^20] CrewAI's docs effectively endorse Mem0 as the production answer when their own memory breaks.[^11]
Letta is building the agent OS, with the strongest "infrastructure, not feature" pitch in the cohort.[^14] Zep and its open-source engine Graphiti are building temporal knowledge graphs with dual timelines — when an event happened and when the fact became valid — which is the bi-temporal substrate experience actually needs.[^21] Cognee uses "memory control plane" verbatim, which is infrastructure-layer language.[^22] Supermemory pitches "universal memory API."[^23]
These are not five competitors fighting for one slot. They are five products converging on the same insight: memory is not a feature of anything else, and somebody has to build it as its own layer.
The benchmark wars between Mem0 and Zep — Mem0 claiming Zep's LoCoMo number is wrong, Zep claiming Mem0's eval is misconfigured — are themselves evidence the category is still substrate, not product.[^24] Products have stable, agreed-upon measurements. Substrates don't, yet, because the field is still negotiating what "good memory" even means. The ICLR 2025 LongMemEval paper — explicitly designed around the premise that "no context window is enough" — is the formal version of the same admission.[^25] Memory is not solved at the model layer, and the field knows it. That's where infrastructure lives before it becomes infrastructure.
 
What the next eighteen months look like
The shape of the war is already visible.
Model labs will keep shipping consumer memory features because their consumer products demand it. None of those features will become the memory layer of the agent ecosystem. Some of them, like ChatGPT memory, will get quietly de-emphasised as the trust problems compound.
Frameworks will keep shipping memory modules because their users keep asking. Most of those modules will become thin shims that delegate to a dedicated memory layer underneath, the way CrewAI's docs already point users to Mem0 for production.[^11]
Vector databases will keep moving up the stack — Pinecone Nexus is the template — and will increasingly look like memory products themselves.[^18] Some will succeed by becoming memory products. Most will not, because moving up the stack means abandoning the neutrality that made them useful as infrastructure in the first place.
The dedicated memory layer will consolidate. Five products converging on the same insight is a market signal, not five winners. One or two will become the layer. The shape they take — event-sourced, bi-temporal, multi-tenant, model-agnostic, framework-agnostic — is the shape experience actually needs, and we already wrote the essay about why.
 
Where CortexDB sits
CortexDB is built for the layer the war is being fought over.
Model-agnostic by design — the write path has no LLM on it, so no specific model is required to store experience, and any model can be used to consume it. Framework-agnostic by design — CortexDB sits underneath LangChain, LlamaIndex, CrewAI, Letta, or a custom runtime, with no opinions about how the agent above it is built. Substrate-deep by design — event-sourced write path, bi-temporal at the core, four-channel hybrid retrieval, irrelevance-gated recall, async knowledge graph enrichment built on top of the events without ever rewriting them. Multi-tenant from day one, because experience is inherently per-agent, per-user, per-organisation.
It is built by the co-creator of Apache Cassandra, who has shipped the append-only-log-with-derived-structure bet once before, at scale, and watched it become the substrate underneath most of the social web. The same bet, for a different problem.
The Switzerland position is not a marketing line. It is the only stable equilibrium in a war where every other player is locked to a model, a framework, or a single retrieval shape.
 
The closer
Three groups are racing to own AI memory. The model labs will lose because memory you can't take with you isn't memory. The frameworks will lose because memory shaped by one framework doesn't survive moving to another. The vector databases will lose because one retrieval primitive isn't a layer.
The winner won't be any of them. It will be whoever builds memory as infrastructure — model-agnostic, framework-agnostic, substrate-deep, event-sourced, portable.
That's the war. CortexDB is built for the side that wins.
